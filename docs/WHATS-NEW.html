Free, with no hidden cost

AI Voice Studio is completely free. There is no price, no subscription, no “Pro” edition, no trial, no feature behind a payment, no advertising and no in-app purchase. There is no account to create and no telemetry: the program does not phone home, and every voice, every engine and every transcription runs on your own computer, offline. The one optional download it offers (the ONNX GPU runtime, about 1.8 GB) is free as well.

The application is free software under the GPL-3.0 — use it, study it, share it, modify it. That licence covers the program, not the voices: the voice engines and the speech models you download are separate works with their own licences. Most are MIT or Apache-2.0 and are free to use, including commercially; a few — the MMS voices and the F5-TTS weights, which are CC-BY-NC-4.0 — are for personal, non-commercial use only, and the SAPI5 and Windows Core voices follow your Windows licence. So the software has no hidden cost, and most voices are free, but if you plan to use a recording commercially, check that voice’s licence first. Help → Third-Party Licences lists every one of them.

The headline: speech to text

2027 adds a whole second direction: text from audio. A project can now be a Speech to text project. You choose a transcription model, its variant, the spoken language, the accuracy and the output format, and AI Voice Studio writes the transcript as plain text, timestamped text, SRT, VTT, HTML, JSON or CSV — one document per source file, or split by time.

Transcription runs in the same offline, no-account way as everything else: no Hugging Face login, no API key, no upload. Every model runs in its own Python environment, exactly like the speech engines, so a NeMo model and a transformers model can never break one another.

A source can be audio or video: WAV, MP3, FLAC, M4A, AAC, OGG/Opus, WMA and AIFF, plus MP4, MKV, MOV, WebM, AVI, MPG, WMV and TS, which the FFmpeg the application already downloads decodes for you. That is what turns a recorded lecture or class into searchable text, a voice memo or meeting into notes, and a video into an SRT or VTT subtitle file. A folder is walked recursively, and time by time separation can split a two-hour lecture into several short documents.

A device that tells the truth

The Compute combo now labels what each model can really do. Only a model that cannot run without a GPU — Canary-Qwen 2.5B and Granite Speech 8B — is offered the GPU alone; every other model offers both the CPU and the GPU whenever an NVIDIA card is present, with the recommended device first, and the CPU alone on a machine with no card. Because the device can differ between variants, the combo is rebuilt when the variant changes: Canary-Qwen’s 2.5B shows GPU only, its 1B CPU or GPU. On a machine with no card, a GPU-only model says so and disables Start transcribe rather than starting a run that cannot work. You are never offered Auto. A GPU run no longer waits for the optional sherpa-onnx GPU runtime, because the models bring their own PyTorch.

A GPU run also needs its CUDA runtime inside that model’s own environment. Whisper’s CTranslate2 back-end needs cuBLAS, which faster-whisper does not ship: the catalog names it as a CUDA-only package and the installer adds it on a GPU machine. An environment installed before that wheel was known (Whisper Large V3 here) quietly fell back to the CPU; Manage the STT now names the missing wheel and turns Install selected model into a repair.

Audio description: describing video

New in 2027: AI Voice Studio describes video. An audio description project runs a vision-language model over a video and writes the narration a blind or low-vision viewer needs — who is there, what they do, what text or code has appeared, where the picture goes. Like everything else in the application it runs on your own machine, in an environment of its own, with no account and no upload.

One run writes three files per video, and the project folder says which is which:

  • the description document — script, HTML, SRT, WebVTT or JSON, in the format the project chose (the reviewable script is always written beside any other format);
  • the spoken narration — the descriptions read aloud by one of your offline voices, laid at the times they belong to; and
  • the described video — a new file that plays the film with the description: the original picture stream copied untouched and the original soundtrack mixed with the narration, or, in extended audio description, the film stopped for each description. The source video is never modified.

Extended audio description is the second way to place a description: instead of speaking into a pause of the soundtrack, the picture holds on the frame it had reached while the description is spoken and then goes on. Nothing is ever talked over, at the price of a longer film — and it is the only option for a video whose dialogue never leaves a pause.

A description you can hear over the film. Standard audio description speaks the description over the film's own soundtrack, and the two were always mixed at their own levels — which buries the description in a film whose music and dialogue never stop. The Audio description window now has a Track priority combo, beside Placement and above Start audio description: Same volume (the default, both tracks exactly as they were produced), Duck, don't lower, Description 25% higher or Description 50% higher. The description keeps the level your narration settings gave it and the film's own soundtrack is mixed at 75% or 50% of it — only the film's track moves, because turning the description up would clip and would change a level you chose by ear. The last two choices are listened to the other way round if you want a louder description instead: a Narration voice volume slider now sits under the narration voice and sets the description's own level here, without opening Settings. Duck, don't lower never lowers the film: it dips the film's own soundtrack to a quarter of its own level — about −12 dB, measured on a real mix — while a description is actually being spoken, over a fade of about a tenth of a second at either end, and lets it back up between descriptions, so a film whose music never stops keeps its own sound everywhere the description is not talking. The moments are not estimated: the narration track records where each description is really heard as it is written, so the dip follows the voice rather than a setting, and two descriptions less than half a second apart are one dip instead of the film flapping between them. A dip that cannot be applied — a film so long that the list of moments would not fit on one command line — falls back to mixing both tracks as they are, never to losing the film's own sound. Extended placement has nothing to balance — the film is silent while the description is spoken — so it switches the combo off and says why. The combo now runs from the gentlest answer to the film to the most forceful: Same volume, Duck, don't lower, then the two percentage choices, and it opens on the first, which is exactly what every run before these choices existed produced.

One description per twenty seconds, not one per chunk. A chunk still bounds memory, the progress bar and resuming, but the length of a description is a window of its own, because one summary per two-minute chunk was measured to reduce a whole lecture to “a man sits in a chair beside a whiteboard” — and to never mention the line of code that had appeared on it. Each window is also told what the previous description said, so the model reports what has changed, and a window whose picture has not changed at all is skipped (and reported as skipped) rather than spoken again.

Models too large for the card now run instead of crashing. A checkpoint bigger than the graphics card is loaded in 4 bits with bitsandbytes (Gemma 3 12B is about 24 GB of weights and fits a 12 GB card that way); nothing is offloaded to the disk any more, which is what ended a real run with a Windows access violation, and a model that cannot run at all is refused with its reason instead of a crash. Pressing Repair model environment adds the quantiser to an environment built before it was part of the GPU install.

Installing a model and downloading a variant are separate steps. The packages of a model are shared by all of its variants; a checkpoint belongs to one. Settings → Manage the video describer therefore shows one Install/Repair button per model and one Download/Remove button per variant, with a status column, so downloading one checkpoint no longer takes the others' Download buttons away.

FFmpeg is asked for, not complained about. If FFmpeg is not installed, Start audio description offers to download it (it decodes the frames, reads the video's length and writes the described video) instead of refusing to run. A Windows account without Developer Mode gets its Hugging Face cache stored as copies rather than symlinks, automatically — and the run says so rather than reporting it as an error.

A gated model now explains itself

New: Google's Gemma 3 works, and its licence is explained instead of being hit as a wall. Every Gemma 3 checkpoint lives in a gated Hugging Face repository: it downloads only for an account that has accepted Google's licence. Until now the run failed part-way through with the library's 401 — Cannot access gated repo … Please log in, which names neither the page that grants access nor any way to give the application a token. Settings → Hugging Face account is that way: paste a read token from huggingface.co/settings/tokens, press Check token, and it says whose token it is before anything is downloaded.

A gated model now says what it needs before it starts. Its variant is marked in Manage the video describer's status column, and a run asked for without a token stops with two sentences naming the page on which to accept the licence and the panel to paste the token into — no gigabyte is fetched, and no model is loaded, until that access is in place. The token is carried into the model's own worker process, so the download itself is authenticated, and it is kept in your own %APPDATA%\AIVoiceStudio\settings.json, sent only to huggingface.co. Users who already have one can keep using HF_TOKEN or a previous huggingface-cli login instead.

One token, and the panel does both halves of the job. A gated model needs two things, and neither is a per-model token: the licence accepted on that model's own page, with the account the token belongs to, and that token given to the application. So the panel now names the models it can set up (Model), opens the page whose own Agree and access repository button grants the access (Open the model page…), and asks Hugging Face the question the failure itself leaves open with Check access: can this token's account download this model? A mistyped token and a licence that was never accepted produce the same error message and are fixed in two different places, and Check access is what says which one it is — it answers with the account name and with the page to accept, rather than with the library's bare 401. Asking a repository it can reach is a few hundred bytes, not a checkpoint: the check fetches the smallest file the repository lists.

The same gate explains itself in the Voice Lab. Pocket TTS clones a voice from a 5–10 second sample, and those weights live in Kyutai's gated repository kyutai/pocket-tts — the 26 pre-made voices live outside it. Without access the library does not fail: it loads its cloning-free weights, so the pre-made voices work the moment the engine is installed and only cloning stops, with advice to run an hf auth login command this installation does not have. It now stops with the two steps that do work — accept the licence on that page, add a read token in Settings → Hugging Face account — and the run's notes say that the engine is running without voice cloning, so the cause is visible before a clone is attempted.

Nothing else changed hands. Every other describing model — and every speech-to-text model, which was checked one by one against Hugging Face — still downloads with no account, no token and no click-through, and tools/check_hf_access.py re-checks the whole list (now including Kyutai's repository) against the live API.

Settings: one Voice Clone page

The OmniVoice engines category is merged into Voice Clone. Every cloning engine now lives on one page: the Voice Lab engines first, then the OmniVoice engines with their Install OmniVoice dependency / Remove OmniVoice dependency (omnivoice-triton) and Install OmniVoice Server / Remove OmniVoice Server (omnivoice-server) buttons, their install status, the three engine cards (Server, Triton, Hybrid) and the OmniVoice voice library.

One engine list. The two halves each had their own TTS combo box; they are one TTS engine list at the top of the page now, holding every Voice Lab engine plus OmniVoice Server and OmniVoice (direct, Triton), and the controls of the engine you pick follow below it. Picking an engine speaks its name and whether it is installed before the rest of its details.

Those two install button pairs moved out of Compute, so an engine is installed on the page where it is configured, exactly like the Voice Lab engines. Compute keeps the optional ONNX GPU (CUDA) runtime, and the OmniVoice Server category is unchanged — it still holds the HTTP server's host, port, device, API key, CORS and start/stop controls.

Install with winget. The package is published in the Windows Package Manager repository, so winget install AnujSharma.AIVoiceStudio installs the same installer, winget upgrade AnujSharma.AIVoiceStudio updates it and winget search AIVoiceStudio finds it. Run winget source update first if a fresh machine does not list it yet. The User Guide and the readme now open with these commands.

Voice Lab engines, 2027

The Voice Clone engines are now Pocket TTS, F5-TTS, KokoClone, Chatterbox, Qwen3-TTS, VibeVoice, MOSS-TTS and GPT-SoVITS. Each engine has its own tuning controls, remembered per engine in Settings and overridable per project.

MOSS-TTS (OpenMOSS) adds two checkpoints that fit a 12 GB card — the 48 kHz Local Transformer 4B and 1.7B models.

The 100M Nano checkpoint was offered at first, but it had no speaker of its own: upstream always drives it in voice-clone mode with a prompt recording, and without one it came back as a fraction of a second of near-silence about as often as it spoke. That variant has been removed.

The GPT-SoVITS install no longer asks for jieba_fast — a C extension with no build for the Python this app runs on, which made pip fail the whole install with just “pip install failed (exit 1)”. The worker stands in plain jieba under that name, and a failed pip step now reports the line that explains it.

A new engine joins them: Indic Parler-TTS, which speaks the Indian languages — Hindi, Bengali, Tamil, Telugu and the rest of the AI4Bharat set — and takes its text directly, so it needs no pynini text front-end, which has no Windows build. It is not a cloning engine — it speaks with one of its 65 named speakers, chosen by a description you can rewrite in Engine tuning — and needs an NVIDIA GPU, like the other large transformers.

Two engines surveyed alongside it were removed before this release: IndicF5 and OmniVoice ONNX. Neither spoke the text it was handed. IndicF5 was an F5-TTS fine-tune whose checkpoint only half loaded under the transformers it pinned, so its take came back as speech-shaped nonsense (a word error rate of 0.52–0.89 against the text it was given), and the OmniVoice ONNX export's backbone barely conditioned on its input at all — the same Hindi sentence came back as unrelated Hindi at 0.95–1.00, in its own voice and when cloning. The application's own OmniVoice engines, which run the PyTorch checkpoint, are the ones to use for speech.

Two models that were surveyed at the same time are deliberately not offered, because no installable Windows runtime exists for them: Svara-TTS (vLLM/FlashInfer are Linux-only and it has no CPython 3.13 Windows wheel) and AI4Bharat's Indic-TTS (its front-end needs pynini, which has no Windows wheel, and its pinned numba release has no build for the Python this app runs on).

Both MOSS-TTS and GPT-SoVITS also read audio through the soundfile shim now: without FFmpeg, a reference recording could not be loaded at all.

GPT-SoVITS (RVC-Boss) adds its six releases (v2ProPlus, v2Pro, v4, v3, v2 and v1) for few-shot cloning from as little as five seconds of audio. GPT-SoVITS has no voices of its own: it is clone-only, so its voices appear once you create or clone one on the Voice Clone page. It speaks English, Chinese, Korean and Cantonese; Japanese is not offered, because its Japanese front-end needs pyopenjtalk, which has no installable build for the Python this app runs on. Both engines run in their own Python environment, like every other Voice Lab engine.

One Python environment per engine

Every pip-installed engine — and, in 2027, every transcription model — gets its own environment under %APPDATA%\AIVoiceStudio\ (tts_envs\<engine> and stt_envs\<model>). Two engines that need conflicting dependencies can never break each other, and removing an engine removes its environment with it.

Those environments are built on a per-user copy of the Python the application ships (%APPDATA%\AIVoiceStudio\python_runtime), so they keep working when the application is reinstalled, upgraded or moved into another folder: a model you downloaded once does not have to be downloaded again just because setup ran a second time. An environment that still names a Python from an earlier installation is repaired in place - its packages are kept - the next time it is used, instead of failing with “did not find executable at ...” and exit code 103.

Compute choice and GPU use

A Compute choice sits next to the actions that need it, remembered per category. On a GPU machine the speech engine now keeps several segments in flight instead of one, so the card is no longer idle between sentences.

Projects, menus and progress

  • Speech-to-text projects. The New Project wizard opens on the Project base choice, so the first decision is which kind of project you are making.
  • Menus that match the project. The Edit menu's wording follows the selected project: a transcription project has files, a recording project has recordings.
  • A real progress window. A transcription now shows a modal progress dialog that can be cancelled, and finishing offers Open project folder — the same courtesy the recording flow has always shown.
  • Start Selected Files. For a transcription project the Edit menu's picker states the project base and offers Select a transcribe file or Select by file break, then Only transcribe selected file or Transcribe all files from here — the same out-of-order convenience recording projects have.
  • Clearer confirmations. Restart Project and Restart All Files now spell out that recordings or transcribe files and the audio creation or transcribe options are reset.

Keyboard gestures and accessibility

One shared access-key handler activates the labelled button in every window whatever has the focus, and explains a key whose target is disabled instead of doing nothing. The frame's shortcuts are checked against the physical keyboard so a Shift+letter gesture is never missed. A What's New item joined the Help menu, and the accessibility and gesture audits run in the test suite.

The window title now reaches a screen reader. wxPython names every window after its own class, and that leftover name was being announced: NVDA+T on the main window said “frame” instead of the title. A window's accessible name is now its title — read live, so the describe window's “Audio description – <film>” is what you hear — and a control nobody named is left unnamed rather than announced as “listBox” or “panel”.

The executable itself now carries the application's name and version, so the screen reader's report the application version command answers “AI Voice Studio, version 2027.1.0” instead of “Application unknown, version not detected”.

Settings → General no longer offers two identical Browse... buttons. The first folder is named for what it holds — the Project save location, where your projects and their recordings live — and each row carries its own button, Browse project location... and Browse model location..., so a screen reader announces which folder a button changes.

Twenty dark themes and wallpapers

2027 gives the interface a wardrobe. The original Light and Dark themes are untouched, and twenty predefined dark themes join them. The first ten are the original set — Midnight Graphite, Obsidian Gold, Deep Navy, Forest Pine, Plum Royale, Crimson Slate, Ocean Teal, Amber Dusk, Carbon Lime and Blue Steel — each with a distinct palette and a painted style of its own, so no two look alike.

Ten more were added on request, and these ones are vibrant: Neon Magenta, Inferno Red, Solar Flare, Voltage Yellow, Laser Lime, Emerald Surge, Cyber Cyan, Azure Rush, Electric Indigo and Ultraviolet. They keep the same dark, WCAG AA-legible text as every other theme, but their accents are saturated and their backgrounds are tinted with the accent's own hue, so they read as colourful rather than neutral. The original ten are exactly as they were: same names, same colours, and still the first ten in the Theme list.

The theme controls now live in their own category. Settings → Appearance holds the theme list, the custom theme studio and the wallpaper, while Settings → General keeps the developer switch, the project and model folders and the update settings. Nothing was removed in the move.

A custom theme studio (Settings → Appearance → Create custom theme…) lets you choose every colour — background, text, control, control text, accent and heading — pick a painted style and name the theme. There is no limit: create, edit and delete as many themes as you like. A live preview shows each change before you save.

Any theme — built-in, predefined or custom — can carry a wallpaper: choose your own picture, or let the theme draw its pattern. The welcome screen is now a full-width action bar of the four main buttons — Remove selected project (Alt+J), Create New Project, Record (open a project) and Settings (download voices) — above a left projects sidebar holding the Recent projects list, and the wallpaper fills only the large empty area that remains beside them. It never paints behind a button or the project list.

Updates and installation

  • Help → Check for updates asks GitHub for the newest release and can download the installer for your Windows version. A quiet check runs once a day; nothing is downloaded or installed unless you ask.
  • The installer still lets you choose install for all users or install for me only.
  • A winget package (AnujSharma.AIVoiceStudio) lets winget install and winget upgrade use exactly this installer.

What was removed, and why

  • Bark (Suno AI) was removed from the Voice Clone engines: its 130 speaker presets and .npz-only "cloning" were the one engine the rest of the Voice Clone page could not express.
  • NeuTTS was removed: it needed a gated Hugging Face login the application cannot provide.
  • Cohere Transcribe was never offered: it only downloads after signing in to Hugging Face and accepting a licence, and this application deliberately works without an account.
  • Voxtral 24B was removed from the catalog: its ~48 GB of bfloat16 weights cannot load on the 12 GB cards the catalog targets. The 3B model is the one that fits.

Thank you for using AI Voice Studio. Everything on this page is free and offline; the whole application is built so a screen reader user can do all of it from the keyboard.
