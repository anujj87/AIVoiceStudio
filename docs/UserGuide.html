What you can use it for

Everything AI Voice Studio does happens on your own computer: nothing is uploaded and no account is needed. That makes it useful both for convenience and for work that has to stay private.

  • Podcasts and audio essays — open a script (PDF, DOCX, Markdown, HTML or clipboard text), record it, and play the finished episode with the .m3u8 / .pls / .wpl playlist the project generates.
  • Game voice-over and character voices — clone a voice from a five-second sample and give every line of a character the same voice (see Voice cloning).
  • Study notes and revision audio — record your notes once and listen to them while you walk, drive, or take a break from reading.
  • Audiobooks, lessons and accessible reading — DAISY 2.02 and DAISY 3 books (audio, text and images) with playlists.
  • Audio and video into text — transcribe recordings, voice memos, interviews and video or audio lectures into TXT, Markdown, SRT, VTT, HTML, JSON or CSV (see Transcription).
  • Subtitles and captions — write SRT or VTT with real timings for a video, a lecture recording or an accessibility pass.

Free, with no hidden cost

The application is completely free: no price, no subscription, no “Pro” edition, no trial, no feature behind a payment, no advertising, no in-app purchase, no account and no telemetry. The one optional download it offers (the ONNX GPU runtime, about 1.8 GB) is free too. The program is free software under the GPL-3.0.

That licence covers the program. The voices, engines and speech-recognition models you download are separate works with their own licences: most are MIT or Apache-2.0 and are free to use, while a few (such as the MMS voices and the F5-TTS weights, which are CC-BY-NC-4.0) are for personal, non-commercial use only, and the SAPI5 / Windows voices follow your Windows licence. If you intend to use a recording commercially, check that voice’s licence first — Help → Third-Party Licences lists all of them.

Installation

There are two ways to install AI Voice Studio on Windows, and both use the same installer:

  • With winget — the package is in the Windows Package Manager repository: winget install AnujSharma.AIVoiceStudio. Update it later with winget upgrade AnujSharma.AIVoiceStudio and remove it with winget uninstall AnujSharma.AIVoiceStudio. If winget says the package was not found, run winget source update first (or add --source winget). winget search AIVoiceStudio lists it.
  • With the setup file — download AI-Voice-Studio-v-2027-1-0-Setup-x64.exe (or -x86 for 32-bit Windows) from github.com/anujj87/AIVoiceStudio/releases and run it.
  1. Run AI-Voice-Studio-v-2027-1-0-Setup-x64.exe and follow the installer.
  2. The installer asks whether to install for all users (administrator rights required) or for you only. Choosing for me only needs no administrator rights and installs the application under %LOCALAPPDATA%\Programs; an earlier installation of the same version family is updated in place.
  3. When asked, choose whether to create a desktop icon and whether to launch the application after setup.
  4. Read the licence page — it lists the third-party components the application bundles. The same information is available after installation from Help → Third-Party Licences.

Nothing else needs to be installed: the CPU runtime, the ONNX text-to-speech engines and the TTS download manager are part of the application. GPU support, FFmpeg and the pip-installed voice-cloning engines are downloaded on demand into your own user folder.

First launch — terms of use

The first time the application starts it shows a Terms of Use dialog. It has six check boxes, each stating a condition of use (voice-cloning rights, no illegal use, commercial-use licence checks, SAPI5/Windows voice rights, no warranty from the author, and careful and legal use of voice cloning), plus a bold final check box, “I agree with all above terms”.

  • Ticking the bold final check box ticks all six conditions; un-ticking it un-ticks them.
  • I Agree and Disagree (Close Program) only become available once the final check box is ticked.
  • If you press Disagree, press Escape, or close the window, the application does not start at all — no project, no network, no settings are touched.
  • After you press I Agree, your acceptance is remembered and the dialog is not shown again until you install a newer version (a newer version asks again when the terms text has changed).
The acceptance is stored in your settings file, %APPDATA%\AIVoiceStudio\settings.json as terms_version. Removing the application folder from Program Files does not remove that file, so reinstalling without deleting your user folder keeps your answer; a new version that ships newer terms asks again.

Making your first recording

  1. Open Settings (Ctrl+,). In the Download and remove ONNX TTS category choose a TTS engine (Piper is a good start), a language and a variant, then press Download selected variant. Wait for the download to finish.
  2. Close Settings. Press Ctrl+Shift+N to create a new project.
  3. Type a project name, press Open document and choose a PDF, TXT, DOC/DOCX, HTML or Markdown file. Choose the punctuation mode.
  4. Press Next, choose how the document is split into audio files, then press Finish. The Recording window opens.
  5. Choose a voice (TTS → language → variant → voice), set rate, pitch and volume if needed, then press Start recording.
Every finished segment is saved to the project folder immediately. You can close the Recording window at any time and continue later — reopening the project resumes from the first unsaved segment.

The main window

The main window shows a welcome message, three action buttons (Create New Project, Record, Settings) and a Recent projects list. Select a project with the arrow keys and press Enter to open it, or press the Remove selected project button below the list. Right-click the list for the same actions as the Edit menu.

The Recording window

When the window opens, the first control is a read-only Text to record box that announces what will be spoken. Tab to the Compute combo box, then the TTS, language, variant and voice combo boxes, the rate/pitch/volume sliders, and the output format (WAV, MP3 or FLAC).

  • Start recording begins (or resumes) synthesis. If the window was opened from Start Selected Recording, a status line above the button reports the chosen position (“Ready: segment 12 of 40 — chapter 12…”) and the chosen scope before you start.
  • Pause stops after the current segment; Resume continues.
  • Stop stops after the current segment; finished files stay saved.
  • Engine tuning… (Voice Lab engines) sets this project's generation options — diffusion steps, guidance scale, temperatures, seed and so on.
  • MP3 and FLAC need FFmpeg; the app offers to download it into your user folder the first time you choose those formats.

Downloading voices

Voices are downloaded from the official open-source releases (k2-fsa/sherpa-onnx and rhasspy/piper). You only download the voices you actually use. The catalog has nine families: Piper/VITS (many languages), Kokoro-82M, Kitten TTS, VITS zh-AISHELL3, Matcha-TTS, OmniVoice, OmniVoice Server, SAPI5 (the voices installed in Windows) and the Windows Core voices (OneCore, including the Hindi and other system voices). Each engine has several language packs and quality variants; the voice list comes from the variant you install.

Kokoro tip: the “Version 0.19 (English only)” variant contains exactly 11 English voices. For Hindi, French, Chinese, Japanese, Italian and Portuguese voices choose the Multilingual (53 voices — all languages) variant instead — it contains every language voice in one download. Selecting a voice that is not in the installed variant plays the first English voice, so always match the voice to the variant you downloaded.

Voice cloning — the Voice Lab engines

The text-to-speech engines are installed as Python packages instead of downloaded ONNX models, because they are generative models that can copy a voice from a short sample: Pocket TTS (Kyutai), F5-TTS, KokoClone (Kokoro-ONNX speech plus Kanade voice conversion), Chatterbox (Resemble AI), Qwen3-TTS, VibeVoice (Microsoft, community fork), MOSS-TTS (OpenMOSS), GPT-SoVITS (RVC-Boss) and, for the Indian languages, Indic Parler-TTS (AI4Bharat). Together they are called the Voice Lab, and they are configured in Settings → Voice clone. OmniVoice (categories 5 and 6) can also clone a voice. Pocket TTS, F5-TTS and KokoClone run on the CPU or the GPU; the large transformers (Chatterbox, Qwen3-TTS, VibeVoice, MOSS-TTS, GPT-SoVITS) and Indic Parler-TTS are GPU-only, because their CPU run is many times slower than real time. Indic Parler-TTS is not a cloning engine at all — it speaks with one of its 65 named speakers, picked by rewriting the prose description of the voice and its delivery. Every variant offered fits inside 12 GB of video memory. GPT-SoVITS has no voices of its own: it always speaks from a recording you clone, and it speaks English, Chinese, Korean and Cantonese — Japanese is not offered, because its Japanese front-end needs pyopenjtalk, which has no installable build for the Python this app runs on.

  1. In the Engine combo choose the engine, then press Install engine…. The dialog names the packages that will be installed and their size, and — when an NVIDIA GPU is detected — says that the CUDA build of PyTorch is installed so the engine can run on the GPU or on the CPU. The packages go into that engine's own Python environment (%APPDATA%\AIVoiceStudio\tts_envs\<engine>), so two engines can never break each other's dependencies. When pip finishes, the app imports the engine to check the install actually works and reports the result.
  2. Choose the Device: CPU is always listed; GPU (CUDA) and Auto appear when an NVIDIA GPU is detected. See Compute for how much of the machine each choice uses.
  3. Choose what to speak: Use a built-in voice (the pre-made voices the engine ships with — Pocket TTS, KokoClone, Qwen3-TTS, VibeVoice and MOSS-TTS provide many; GPT-SoVITS provides none, so clone a voice for it) or Clone a voice from a sample: type a voice name, pick a clean 4–15 second recording of one speaker, optionally type its transcript, and press Create cloned voice.
  4. Engine tuning… edits the generation defaults of the selected engine. Every control starts at the engine's own documented default, and each project can override them from the Recording window without changing the defaults.

Cloned and built-in voices then appear in Available TTS, in the Preview cascades and in the Recording window, so they can be used everywhere without further configuration.

Licences differ per engine. Pocket TTS is Apache-2.0 (with per-voice terms), Chatterbox and VibeVoice are MIT and Indic Parler-TTS is Apache-2.0; F5-TTS code is MIT but its model weights are CC-BY-NC-4.0, which forbids commercial use. Check Help → Third-Party Licences before commercial work — the same obligation you accepted in the Terms of Use dialog.
The first synthesis with a freshly installed engine downloads its model from Hugging Face and is therefore slow; later sentences are much faster.
Pocket TTS: the pre-made voices need nothing, cloning needs one thing. Kyutai's voice-cloning weights live in the gated repository kyutai/pocket-tts; the 26 pre-made voices do not, which is why Pocket TTS speaks the moment it is installed and only Clone a voice from a sample asks for an account. The engine does not fail without it — it quietly loads its cloning-free weights — so a clone attempt is what stops, and it names the two steps: accept the licence at https://huggingface.co/kyutai/pocket-tts and add a read token in Settings → Hugging Face account. Choose Pocket TTS voice cloning in that panel and press Check access to see whether it is in place before you clone.

Transcription — speech to text

A transcription project turns recorded audio (and video files) into text documents instead of the other way round. Create one with Project → New project → Transcription, choose the recordings or the folder to transcribe, then open the Transcribe dialog — the last step of the wizard, and what Open reopens on a recent transcription project. The dialog offers five choices:

  • Compute — the device to run the chosen model on. Only a model that cannot run without a GPU (Canary-Qwen 2.5B, Granite Speech 8B) is offered the GPU alone; every other model offers both the CPU and the GPU when an NVIDIA card is present (the recommended device first) and the CPU alone on a machine with no card. The list is rebuilt when you change the variant, because one model can hold a GPU-only checkpoint and a CPU-friendly one. “Auto” is deliberately not offered: it would quietly pick the device instead of you.
  • Speech to text model and Variant — any model from Settings → Manage the STT. Models that are not installed yet say so in the list.
  • Language — the spoken language, or Detect automatically where the model supports it.
  • Accuracy — fast (greedy decoding), balanced (beam search, recommended) or most accurate (wide beam search, slowest).
  • Translation — only for the models that can translate speech into English; on the others the box says so and is disabled.

Start transcribe runs the job in the background and writes one document per source (or one per time slice) into the project folder: TXT, SRT, VTT, HTML, JSON or CSV, with or without timestamps, following the choices made when the project was created. A modal progress window shows how far the run has got and can cancel it; when it finishes, Open project folder opens the folder the documents were written to. The status line shows what is happening, and a failure names its cause instead of a traceback tail.

What you can transcribe

A source can be a single file or a whole folder (the folder is walked recursively). Audio: WAV, MP3, FLAC, M4A, AAC, OGG/Opus, WMA and AIFF. Video: MP4, MKV, MOV, WebM, AVI, M4V, MPG, MPEG, WMV, TS and M2TS — FFmpeg, which the application already downloads for MP3/FLAC output, decodes them, so a lecture recorded as video needs no separate step. The output document is named after the source file and written next to the project.

  • TXT / Markdown — plain study notes, with an optional timestamp at the start of each line.
  • SRT / VTT — ready-made subtitles or captions with real timings, for a video, a lecture recording or an accessibility pass.
  • HTML — a titled document you can open in a browser or a screen reader.
  • JSON / CSV — one record per segment, with its start and end, for feeding the text into something else.

With time by time separation a long recording is split into parts of the number of minutes you choose, so a two-hour lecture becomes several short documents instead of one enormous file. Because everything runs on the machine, a confidential interview or a private note can be transcribed with no internet connection at all.

Every model is installed into a Python environment of its own under %APPDATA%\AIVoiceStudio\stt_envs\<model id>, so their dependencies (NeMo, transformers, two different PyTorch pins, protobuf) can never break each other. Remove model deletes that environment. No model needs a Hugging Face account, a token or a licence click-through.

Not every model can report timings. Whisper and the NeMo text models say when each phrase was spoken; the audio language models (Qwen3-ASR, Voxtral, Granite Speech, Moonshine) do not, and are never asked to — they produce one untimed segment. Voxtral is offered at 3B only: the 24B model is too large for an ordinary 12 GB card.

Audio description — describing a video

Audio description narrates what is happening on screen for a blind or low-vision viewer: who is there, what they do, what text or code has appeared, where the picture goes. AI Voice Studio watches the video with a vision-language model, writes the descriptions, speaks them with one of your offline voices, and muxes them into a new copy of the film. Nothing is uploaded: the model runs on your own machine, in a Python environment of its own.

Three files per video, and the source is never touched. One run writes (1) the description document in the format the project chose, (2) the spoken narration — an audio file of the descriptions read aloud — and (3) the described video: a new file next to the project containing the original picture and sound with the description heard over the pauses. Your source video is read only; it is never edited, moved or overwritten.

Creating an audio description project

Project → New project, then choose the project base Audio description and give the project a name. The wizard page then asks for the video(s) and the describing model:

  • Video files — one or more video files (MP4, MKV, MOV, AVI, WebM, WMV, M4V, MPG, TS, 3GP, OGV and more). A whole folder can be added; files that are not video are refused with their names listed.
  • Video description model — every model in Settings → Manage the video describer (Qwen3-VL, Qwen2.5-VL, Qwen2.5-Omni, Qwen3-Omni, Gemma 3, Gemma 4, MiniCPM-o, MiniCPM-V 4, SmolVLM2, Moondream). Every entry says whether it is ready to use or not installed.
  • Model variant — the checkpoint of that model, each labelled with its download size and the video memory it needs: downloaded, not downloaded yet or download stopped part-way.
  • Compute — the CPU or the GPU for the model.
  • Frame rate — how many frames of every second of video the model is shown (1 per second to 1 per five seconds). More frames is more detail and more time.
  • Chunk — how much video is described in one pass before the run stops to save progress (1–10 minutes per chunk). This is about memory, progress and resuming; what one description covers is decided by the window below.
  • Output document — description script (plain text or a web page), SRT or WebVTT subtitles, or JSON.

The page also shows the estimated run time and how many descriptions that video will produce — about one for every twenty seconds of video — and warns before anything starts on a long film, because describing video is far slower than transcribing it.

Audio description in the Settings window

Settings → Manage the video describer is where the models are installed. Each model lists its licence, its download size and the video memory it wants, and each variant is a row of its own:

  • Install model environment / Repair model environment — builds (or repairs) that model's private Python environment under %APPDATA%\AIVoiceStudio\describe_envs\<model id>. It turns into Repair when something is missing from it, such as the CUDA runtime on a GPU machine.
  • Download selected variant / Remove variant download — fetches or deletes the checkpoint of the variant selected in the row. Downloading one variant never takes the others away: every variant of a model keeps its own Download button, so a second checkpoint can be fetched at any time.
  • Status — the state of that variant: Downloaded, Not downloaded (about N GB), Partly downloaded (a fetch that was cancelled or failed; downloading it again continues where it stopped) or Install the model first.
  • Remove model environment — deletes that environment and everything in it.
Two layers, not one. The packages of a model are shared by all its variants; a checkpoint belongs to one variant. That is why installing a model and downloading a variant are separate buttons, and why removing one variant leaves the model (and its other variants) installed.
A checkpoint larger than your card is loaded in 4 bits. On a machine with an NVIDIA card, the model environment also installs bitsandbytes, the quantiser. A variant whose weights are larger than the card — Gemma 3 12B is about 24 GB — is then loaded in 4-bit form (about a quarter of the size) instead of being spilled to the disk, which used to end the run with a Windows access violation. A model that fits is still loaded at full precision.
Gemma 3 needs a Hugging Face token; nothing else here does. Every Gemma 3 checkpoint lives in Google's gated repository, so its download only works for an account that has accepted its licence. Three steps, once: choose the model in Settings → Hugging Face account and press Open the model page…, then press the page's own accept button (Agree and access repository); create a read token at https://huggingface.co/settings/tokens; paste it into the same panel and press Check token (it reports whose token it is) and then Check access (it says whether the licence is in place for that model). There is no per-model token — one read token serves every gated model — and Check access is what tells a mistyped token from a licence that was never accepted, which look identical in the library's error. A gated model says so before it starts — in the Status column of the table and again when a run is asked for without a token — rather than failing part-way through a download with the library's 401 — Cannot access gated repo ... Please log in. The token stays in your own %APPDATA%\AIVoiceStudio\settings.json and is sent only to huggingface.co; an HF_TOKEN environment variable or a previous huggingface-cli login works just as well for users who already have one.

The Audio description window

The last step of the wizard — and what Open reopens on a recent audio description project — is the Audio description window. It does not ask again what the project already decided: the model, its variant, the device, the frame rate, the chunk length and the output format are reported at the top, with the state of the model and of the variant next to them.

What it asks is how the descriptions are placed and who speaks them:

  • Placement — how the description reaches the viewer:
    • Speak into the pauses (standard) — the film is not changed at all. Each description is placed in a silence of the soundtrack, so the picture and the film's length stay as they are.
    • Pause the video for each description (extended) — the picture stops on the frame it had reached, the description is spoken into the quiet, and the film goes on. Nothing is ever talked over, at the price of a longer film (about eleven seconds per description). This is the only option for a video whose dialogue never leaves a pause, and the one to use when the text on screen matters: the pause is the moment the viewer reads it.
  • Track priority — which of the two tracks gives way, which is the one place the description and the film's own soundtrack are heard together (standard placement). The list runs from the gentlest answer to the film to the most forceful, and it opens on the first, which is what every run before these choices existed produced. Same volume — the default — mixes both tracks exactly as they were produced. Duck, don't lower does not lower the film at all: it dips the film's own soundtrack to a quarter of its own level (about −12 dB) while a description is actually being spoken, over a fast fade at either end, and lets it back up between descriptions — the choice for a film whose music never stops, because its own sound is left alone everywhere the description is not talking. The moments are not estimated: the narration track records where each description is really heard while it is written, and two descriptions less than half a second apart are one dip, so the film does not flap back up in the middle of a spoken passage. If a dip cannot be applied at all, the film is mixed with both its tracks as they are rather than losing its own sound. Description 25% higher and Description 50% higher keep the description at the level your narration settings gave it and mix the film's own soundtrack at 75% or 50% of it, so a description stands out from a film whose music and dialogue never stop. Only the film's track moves: raising the description instead would clip (speech at full scale already peaks at full scale) and would change a level you had already chosen by ear — unless you ask for it with the narration volume slider below. With extended placement the combo is switched off, because the film's soundtrack is silent while the description is spoken and there is nothing to balance.
  • Fit descriptions into the pauses — uses the speech-to-text model chosen in Settings to find the silent gaps and put each description into the pause that follows the moment it describes, instead of at a fixed boundary. Only available with standard placement, because pausing the film replaces the idea. A description that no pause can hold is left out of the timed track rather than spoken over dialogue, and the run says how many that was.
  • Also speak the descriptions into a narration audio file — turns the descriptions into speech with an offline voice, and is on by default on a machine that has a voice, because it is what produces the narration audio and the described video. With standard placement it can be switched off, and then only the document is written; with extended placement it is always on, because a description the viewer cannot hear is not an audio description.
  • Narration TTS model → Narration model variant → Narration voice — the same cascade the Recording window uses, listing only the voices you have already downloaded. The audio is written in the format chosen in Settings → Recording settings.
  • Narration voice volume — how loud the description is spoken, directly under the voice that speaks it. 1.00 is the voice as it was downloaded, 0.50 is half of it and 2.00 is twice it; the value is remembered for the next project and written into the run's own record. Only the description moves here — the film's own soundtrack is what Track priority sets.

Start audio description runs the job in the background. A progress window shows the percentage and can cancel the run; the window's own chunk report lists every piece as it is described, with its text, and says when a piece was skipped because the picture had not changed. Closing the window does not lose work: the description script is rewritten after every finished piece, so a run that is stopped after an hour keeps the descriptions it had already produced, and starting again continues from what is missing.

When the run finishes, a summary names the three outputs and any warnings (for example a voice that could not be loaded, or a described video that could not be written), and offers Open project folder.

What appears in the project folder

For a source video called Lecture.mp4, a run writes:

Edit → Restart All Descriptions deletes all three files for the project's videos and marks the sources pending again; Edit → Start Selected Descriptions describes only the videos you pick.

How the descriptions are produced

  • Chunks — the video is cut into the chunks chosen in the wizard. A chunk is what bounds memory, what the progress bar counts and what can be resumed; it is not one description.
  • Windows — each chunk is described window by window, one description for about twenty seconds of video. This is the setting that decides how much a listener is told: one summary per two-minute chunk says “a man sits in a chair beside a whiteboard” and never mentions the line of code that appeared on it, which is exactly what twenty-second descriptions fix.
  • Frames — the frames sampled from a window (at the chosen frame rate) go to the model in one prompt. If they do not fit your graphics card, the ones kept are spread evenly over the window, so it is still described from end to end, and the run says so.
  • What came before — each description is told what the previous one said, so the model reports what has changed — text, code, a gesture, a new person — instead of describing the same scene again.
  • The guideline prompt — every request carries the professional audio-description rules: present tense, one or two short sentences, say what matters first, be objective, never invent, name a person only when the video itself does.
  • The picture-change gate — a window whose picture is the same as the last one described is skipped: it would repeat what the listener has already heard and, in extended mode, stop the film for nothing. The report says which pieces were skipped and why.
FFmpeg is required. It decodes the video to sample frames, reads the video's length and writes the described video. If it is not installed, Start audio description offers to download it (about 1 GB into %APPDATA%\AIVoiceStudio\ffmpeg) and asks you to press Start again when it has arrived. The same FFmpeg serves MP3/FLAC output and transcription.

Getting the best descriptions

  • Start with a small model and a short clip: Qwen3-VL 2B or SmolVLM2 on the CPU, Qwen3-VL 4B on a 12 GB card. Qwen3-VL 8B is the best quality that fits a 12 GB card.
  • Raise the frame rate — and prefer extended placement — when the video is mostly on-screen text, slides, code or numbers.
  • Keep chunk length at its default: shorter chunks bound memory and make a long film easier to stop and continue, and they no longer change how much is said.
  • A long run can be closed and resumed; descriptions already written are kept.
  • Everything is a draft. The script is written for exactly this reason: read it, correct the names and the wording, and keep it with the film.

If something goes wrong

  • “This model is not installed yet” — install it in Settings → Manage the video describer.
  • “Could not load the model on this graphics card” — the checkpoint is larger than the card and the 4-bit load could not be built. Press Repair model environment (it adds the quantiser), or choose a smaller variant.
  • “Storing the downloaded model files as copies” — a normal note on a Windows account without Developer Mode: the Hugging Face cache cannot use symbolic links, so files are copied into the cache instead. Nothing to fix.
  • “401 — Cannot access gated repo … Please log in” — the chosen checkpoint (Gemma 3 is the only one) downloads only for an account that has accepted its licence. Open the model's page on huggingface.co, accept the licence, then paste a read token into Settings → Hugging Face account and press Check token. A run says this before it starts whenever no token is configured, so the message should not appear mid-download.
  • “Pocket TTS could not download the weights that can clone a voice” — the 26 pre-made voices still work; cloning needs the gated kyutai/pocket-tts weights. Accept their licence on that page and add a read token in Settings → Hugging Face account, then record again. Check access in that panel (with Pocket TTS voice cloning chosen) says whether it is in place.
  • “Could not write the described video” — FFmpeg is missing or could not read the source. The script and the narration are still written; install FFmpeg and run the project again.
  • Fewer descriptions than expected, or pieces reported as skipped — the picture genuinely had not changed, or no pause was long enough. Choose extended placement if the dialogue never stops.

Punctuation modes

Not every TTS voice can pronounce punctuation. The punctuation mode chosen when the project is created decides how the text is prepared before it is sent to the voice:

  • Default — text passes through unchanged.
  • None — sentence punctuation is removed.
  • Math — sentence punctuation is removed; math symbols such as +, =, <, > are kept and spoken.
  • All — every mark is spoken as a word: my name is "anujsharma". becomes my name is quote anujsharma quote dot; print('hello') becomes print left paren tic hello tic right paren.

The exact spoken text of every recorded segment is saved as processed_text.json in the project folder, next to the audio file it produced.

Expression tags are not punctuation, and no mode touches them. A voice that reads them — Kitten TTS 2.0, with a leading [emotion] tag, inline <event> tags and (((emphasis))) spans — is given them exactly as written, so [joyful] is never read out as “left bracket joyful right bracket” and (((hardly))) keeps its emphasis. The Settings → Punctuation example shows this as soon as such a voice is selected.

Compute — choosing CPU or GPU

The application uses two kinds of engine, and they need different things:

  • The built-in ONNX engines (Piper, Kokoro, Kitten, Matcha, VITS, the Windows voices, OmniVoice and OmniVoice Server) run on sherpa-onnx. Their GPU (CUDA) option needs the optional GPU runtime downloaded from Settings → Compute (about 1.8 GB, CUDA 12 + cuDNN 9) and a restart. Only an NVIDIA driver is required — no CUDA toolkit.
  • The pip-installed Voice Lab engines bring their own PyTorch, so they need only an NVIDIA driver for GPU use; their device is chosen in Settings → Voice clone (CPU, GPU (CUDA) or Auto).

Every Voice Lab engine supports the GPU when your machine has one: the CUDA build of PyTorch is installed from the official PyTorch wheel index for whatever NVIDIA card the driver exposes — there is no model or VRAM requirement.

A Compute combo in every category

Each category that has a Preview button — Available TTS, Recording settings, Punctuation and Voice Clone (the OmniVoice library) — has a small Compute combo next to it. Pick CPU or GPU (and Auto when both exist) and the next preview runs there. The choice is remembered per category, so a long preview session keeps using it until you change it. The Recording window has the same combo for the recording itself, and a project remembers the compute option it was recorded with.

How much of the machine is used

  • GPU — the whole available NVIDIA card is used, whatever the model: the first CUDA device, cuDNN's autotuner, the TensorFloat-32 fast paths, high float32 matmul precision and the autograd engine switched off.
  • CPU — between 80% and 95% of the machine's logical CPUs are used, so a long recording is fast while the desktop, the Recording window and the audio writer stay responsive. Machines with fewer than four logical CPUs keep one core free instead; a single-core machine uses its one core.

A GPU recording keeps two segments in flight at once (up to four on a larger machine). The built-in ONNX engines prepare and speak one sentence per call, so a single engine spends most of its time waiting for the CPU to turn the next sentence into sounds and the card is idle in between. A second segment overlaps that CPU work with the card, which raises its usage and shortens the recording; each segment is still produced by the same model with the same settings, so the audio does not change. A small model such as Kokoro-82M cannot keep a modern card at 100% for long — one sentence is too little work — so the meter shows bursts; a CPU recording stays one segment at a time, because it already uses its whole thread band.

The Voice Lab engines fill a card the same way, but each of them says how much of it one segment costs: they speak one text per call, so a second segment at the same time needs a second loaded model — a second worker process of its own. The plan is read from the card when the recording starts: the memory free then, less a 1.5 GB reserve the desktop keeps, divided by that copy's measured peak. Kitten TTS 2.0 is the heaviest of them at 5 GB a copy (a 1.7B model held at bf16, plus its codec), so a 12 GB card keeps one copy, a 16 GB card two and a 24 GB card three. The lighter the copy, the more of them a card holds: GPT-SoVITS's 1.4–3.2 GB copies give three even on a 12 GB card, while the 3.6–9.5 GB copies of Chatterbox, VibeVoice and MOSS-TTS leave room for one or two. Qwen3-TTS is the exception in the other direction: its own call takes a list of texts, so several segments are generated from one loaded model in a single batched call. The application log records which plan a recording settled on, and every segment is still the same model with the same settings, so the audio does not change.

Updating to a newer version

AI Voice Studio is published on GitHub. The application can tell you when a newer version exists and download the installer for you — it never installs anything without asking.

Check now

Choose Help → Check for updates (access key Alt+D), or press Check for updates now in Settings → General → Updates. The application asks GitHub for the latest release and answers either way:

  • If a newer version exists, a dialog shows the installed version, the new version, and the release notes, with three buttons: Download and install, Open release page and Remind me later.
  • If the version you have is the newest, it says so.
  • If GitHub cannot be reached, it says why instead of failing silently.

Downloading and installing

Download and install fetches the installer for this Windows version into a temporary folder, with the same resumable download and progress window the voice downloads use, and a Cancel button. When it has finished, you are asked whether to install now; if you agree, the installer starts and the application closes so its files can be replaced. If you choose Install later, the downloaded file stays where the message tells you.

The download always comes from this project's own release page (github.com/anujj87/AIVoiceStudio/releases), and the release notes are shown before anything is downloaded, so you can read what is changing first.

Automatic checks

By default the application looks for a newer release once a day when it starts. When one is found, the same dialog appears; when there is nothing new, the check is silent. Turn it off in Settings → General → Updates → Check for updates automatically when the application starts.

The dialog's Do not remind me about this version again check box mutes one specific version — you will be told again when a later one is released.

Installing with winget

AI Voice Studio follows the Windows Package Manager standard, and its package (AnujSharma.AIVoiceStudio) is published there. These work from any terminal:

  • winget search AnujSharma.AIVoiceStudio — show the package winget has.
  • winget install AnujSharma.AIVoiceStudio — install it.
  • winget upgrade AnujSharma.AIVoiceStudio — update it in place.
  • winget uninstall AnujSharma.AIVoiceStudio — remove it.

The same installer serves winget, the built-in update check and a manual download, and it installs per user by default, so no administrator password is needed. The manifests winget uses are generated from this release and live in the repository's winget folder.

Keyboard gestures

Settings → Keyboard gestures is modelled on NVDA's Input Gestures dialog. Troubleshooting

“No matching distribution found for torch” while installing an engine

The installer takes PyTorch from the official CUDA wheel index. That happens when the index has no build for the Python version the application runs on, or the download mirror is unreachable. The installer then falls back to the plain CPU packages, so the engine is still installed and usable on the CPU; the dialog reports that GPU support is unavailable. If the fallback also fails, check your internet connection and press Install again.

“ModuleNotFoundError: No module named 'torch'” when previewing or recording

This happens when an engine's package is installed in one environment but the worker was started in another. The application now resolves the interpreter from the engine's own environment and says so in the engine's own words when nothing is installed. If you still see it: open Settings → Voice clone, remove the engine and install it again; then close and reopen the Recording window.

“did not find executable at …” after reinstalling AI Voice Studio

Every model you install runs in its own Python environment under %APPDATA%\AIVoiceStudio, and an environment remembers the exact Python it was built from. Installations before this one built them from a Python inside the program folder, so reinstalling the application somewhere else - “only me” after an all-users install, or into a different folder - left every one of them naming a folder that had gone. Starting such a model failed with exit code 103 and did not find executable at '...': The system cannot find the path specified., which looks like a model crash.

Environments are now built from a per-user copy of the Python the application ships (%APPDATA%\AIVoiceStudio\python_runtime), which cannot move, so a reinstall no longer affects the models you already have. An environment that still names a Python that has gone is repaired in place the next time the model is used - its downloaded packages are kept. If a run still fails this way, install that model again from its category in Settings: that builds its environment from scratch.

Recording fails with a TorchCodec / FFmpeg error

Newer TorchAudio decodes through TorchCodec, which on Windows looks for FFmpeg's shared libraries. The Voice Lab worker now detects that and falls back to its own audio reader with no FFmpeg needed; FFmpeg remains optional. If you do have FFmpeg installed, install the “full-shared” build so its DLLs are present.

The recording produced an empty (silent) WAV file

This used to happen when the raw float samples were cast straight to int16. The engine now converts samples correctly. If you still hear silence, make sure the selected voice was downloaded completely (re-download it from Settings) and try the CPU compute option.

Recording fails with “Could not load the TTS model… graph.h:1997”

This error came from two different ONNX Runtime copies fighting inside one process. The app now ships exactly one ONNX Runtime, and the pip-installed engines run in their own processes. If you still see it, close the application, open Settings → Compute, remove and re-download the GPU runtime if you use it, and restart the app.

The GPU (CUDA) option does not appear

For the built-in engines: download the GPU runtime in Settings → Compute and restart the application. The option only appears when the runtime is installed and an NVIDIA GPU is detected. For the Voice Lab engines only the NVIDIA driver is needed — device options are in Settings → Voice clone.

My cloned voice cannot be used

The engine must be installed first (Settings → Voice clone, section 1), and the Voice Lab engines download their model on first use. On a slow connection this can take a while — the status text reports progress, and the model is cached afterwards.

The Terms of Use dialog appeared again

It is shown again after a version update whose terms text changed (the application compares the accepted terms version with the current one). It is not a sign that your settings were lost.

MP3 / FLAC output asks for FFmpeg every time

Accept the download prompt once; FFmpeg is saved to your user folder (%APPDATA%\AIVoiceStudio\ffmpeg) and reused afterwards.

Keyboard shortcuts do nothing while a dialog is open

Menu shortcuts (Ctrl+Shift+N and similar) work from the main window. While a modal dialog such as Settings or the Recording window is open, they are intentionally inactive; close the dialog first.

“Check for updates” cannot reach GitHub

The check needs an internet connection to api.github.com. It reports the reason instead of failing silently: a proxy, a firewall, or no connection at all. Nothing else in the application depends on it — you can also download the installer from the release page directly. If the check found an update but the download stopped, the part that was already fetched is reused when you try again, because the download is resumable.

A new version is available but the update dialog did not appear

The automatic check runs once a day and only speaks when it finds something newer. Open Help → Check for updates at any time to look again. If a release was published while you had the application open, the next start picks it up; the collected check date is stored in %APPDATA%\AIVoiceStudio\settings.json.

  • Recorded audio and processed_text.json: the project folder.
  • Downloaded voices and cloned voices: the model folder (Settings → General).
  • Per-engine Python environments and the Voice Lab engines' models: %APPDATA%\AIVoiceStudio\tts_envs.
  • Optional runtimes, the addon environment and FFmpeg: %APPDATA%\AIVoiceStudio.
