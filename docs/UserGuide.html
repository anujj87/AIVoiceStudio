AI Voice Studio — User Guide

Developed by Anuj Sharma. Application version 2026.3.7. This guide explains installation, the first-launch terms of use, the first recording, every Settings category, voice cloning with the Voice Lab engines, punctuation, the compute back-ends, licences and how to solve common problems. The application is designed to be fully usable with a screen reader (NVDA, JAWS, Narrator).

Installation

  1. Run AI-Voice-Studio-v-2026-3-7-Setup-x64.exe and follow the installer. (With winget, winget install AnujSharma.AIVoiceStudio does the same thing.)
  2. Choose whether to install for all users or only for you.
  3. When asked, choose whether to create a desktop icon and whether to launch the application after setup.
  4. Read the licence page — it lists the third-party components the application bundles. The same information is available after installation from Help → Third-Party Licences.

Nothing else needs to be installed: the CPU runtime, the ONNX text-to-speech engines and the TTS download manager are part of the application. GPU support, FFmpeg and the pip-installed voice-cloning engines are downloaded on demand into your own user folder.

First launch — terms of use

The first time the application starts it shows a Terms of Use dialog. It has six check boxes, each stating a condition of use (voice-cloning rights, no illegal use, commercial-use licence checks, SAPI5/Windows voice rights, no warranty from the author, and careful and legal use of voice cloning), plus a bold final check box, “I agree with all above terms”.

  • Ticking the bold final check box ticks all six conditions; un-ticking it un-ticks them.
  • I Agree and Disagree (Close Program) only become available once the final check box is ticked.
  • If you press Disagree, press Escape, or close the window, the application does not start at all — no project, no network, no settings are touched.
  • After you press I Agree, your acceptance is remembered and the dialog is not shown again until you install a newer version (a newer version asks again when the terms text has changed).
The acceptance is stored in your settings file, %APPDATA%\AIVoiceStudio\settings.json as terms_version. Removing the application folder from Program Files does not remove that file, so reinstalling without deleting your user folder keeps your answer; a new version that ships newer terms asks again.

Making your first recording

  1. Open Settings (Ctrl+,). In the Download and remove category choose a TTS engine (Piper is a good start), a language and a variant, then press Download selected variant. Wait for the download to finish.
  2. Close Settings. Press Ctrl+Shift+N to create a new project.
  3. Type a project name, press Open document and choose a PDF, TXT, DOC/DOCX, HTML or Markdown file. Choose the punctuation mode.
  4. Press Next, choose how the document is split into audio files, then press Finish. The Recording window opens.
  5. Choose a voice (TTS → language → variant → voice), set rate, pitch and volume if needed, then press Start recording.
Every finished segment is saved to the project folder immediately. You can close the Recording window at any time and continue later — reopening the project resumes from the first unsaved segment.

The main window

The main window shows a welcome message, three action buttons (Create New Project, Record, Settings) and a Recent projects list. Select a project with the arrow keys and press Enter to open it, or press the Remove selected project button below the list. Right-click the list for the same actions as the Edit menu.

  • Select an audio file (default) — the files already recorded in the project folder, so one of them is recorded again.
  • Select by file break — every file break of the project, recorded or not, so recording can start at any break.
A second pair of options decides how far recording goes: Only record selected file records just that file and stops, while Record all files from here records the chosen file and then every file after it to the end of the project. The dialog never refuses to open for lack of recordings: a 100-chapter book can have chapter 75 recorded today and the rest later. The only requirement is a project whose document has been split into file breaks.
Remove Project…Removes the project from the menu and deletes its folder from your hard disk. This cannot be undone.

The Recording window

When the window opens, the first control is a read-only Text to record box that announces what will be spoken. Tab to the Compute combo box, then the TTS, language, variant and voice combo boxes, the rate/pitch/volume sliders, and the output format (WAV, MP3 or FLAC).

  • Start recording begins (or resumes) synthesis. If the window was opened from Start Selected Recording, a status line above the button reports the chosen position (“Ready: segment 12 of 40 — chapter 12…”) and the chosen scope before you start.
  • Pause stops after the current segment; Resume continues.
  • Stop stops after the current segment; finished files stay saved.
  • Engine tuning… (Voice Lab engines) sets this project's generation options — diffusion steps, guidance scale, temperatures, seed and so on.
  • MP3 and FLAC need FFmpeg; the app offers to download it into your user folder the first time you choose those formats.

Downloading voices

Voices are downloaded from the official open-source releases (k2-fsa/sherpa-onnx and rhasspy/piper). You only download the voices you actually use. The catalog has nine families: Piper/VITS (many languages), Kokoro-82M, Kitten TTS, VITS zh-AISHELL3, Matcha-TTS, OmniVoice, OmniVoice Server, SAPI5 (the voices installed in Windows) and the Windows Core voices (OneCore, including the Hindi and other system voices). Each engine has several language packs and quality variants; the voice list comes from the variant you install.

Kokoro tip: the “Version 0.19 (English only)” variant contains exactly 11 English voices. For Hindi, French, Chinese, Japanese, Italian and Portuguese voices choose the Multilingual (53 voices — all languages) variant instead — it contains every language voice in one download. Selecting a voice that is not in the installed variant plays the first English voice, so always match the voice to the variant you downloaded.

Voice cloning — the Voice Lab engines

Three text-to-speech engines are installed as Python packages instead of downloaded ONNX models, because they are generative models that can copy a voice from a short sample: Pocket TTS (Kyutai), Bark (Suno AI) and F5-TTS. Together they are called the Voice Lab, and they are configured in Settings → Voice clone. OmniVoice (categories 5 and 6) can also clone a voice.

  1. In the Engine combo choose the engine, then press Install engine…. The dialog names the packages that will be installed and their size, and — when an NVIDIA GPU is detected — says that the CUDA build of PyTorch is installed so the engine can run on the GPU or on the CPU. The packages go into that engine's own Python environment (%APPDATA%\AIVoiceStudio\tts_envs\<engine>), so two engines can never break each other's dependencies. When pip finishes, the app imports the engine to check the install actually works and reports the result.
  2. Choose the Device: CPU is always listed; GPU (CUDA) and Auto appear when an NVIDIA GPU is detected. See Compute for how much of the machine each choice uses.
  3. Choose what to speak: Use a built-in voice (the pre-made voices the engine ships with — Pocket TTS and Bark provide many) or Clone a voice from a sample: type a voice name, pick a clean 4–15 second recording of one speaker, optionally type its transcript, and press Create cloned voice.
  4. Engine tuning… edits the generation defaults of the selected engine. Every control starts at the engine's own documented default, and each project can override them from the Recording window without changing the defaults.

Cloned and built-in voices then appear in Available TTS, in the Preview cascades and in the Recording window, so they can be used everywhere without further configuration.

Licences differ per engine. Pocket TTS and Bark are Apache-2.0/MIT; F5-TTS code is MIT but its model weights are CC-BY-NC-4.0, which forbids commercial use. Check Help → Third-Party Licences before commercial work — the same obligation you accepted in the Terms of Use dialog.
The first synthesis with a freshly installed engine downloads its model from Hugging Face and is therefore slow; later sentences are much faster.

One Python environment per engine

Every pip-installed engine gets its own virtual environment under %APPDATA%\AIVoiceStudio\tts_envs\:

EnvironmentUsed by
tts_envs\pocket_ttsPocket TTS (Kyutai)
tts_envs\barkBark (Suno AI)

Each engine's worker process runs on its own environment's interpreter, so PyTorch and CUDA never enter the application process. Removing an engine uninstalls its packages from its environment only.

Punctuation modes

Not every TTS voice can pronounce punctuation. The punctuation mode chosen when the project is created decides how the text is prepared before it is sent to the voice:

  • Default — text passes through unchanged.
  • None — sentence punctuation is removed.
  • Math — sentence punctuation is removed; math symbols such as +, =, <, > are kept and spoken.
  • All — every mark is spoken as a word: my name is "anujsharma". becomes my name is quote anujsharma quote dot; print('hello') becomes print left paren tic hello tic right paren.

The exact spoken text of every recorded segment is saved as processed_text.json in the project folder, next to the audio file it produced.

Compute — choosing CPU or GPU

The application uses two kinds of engine, and they need different things:

  • The built-in ONNX engines (Piper, Kokoro, Kitten, Matcha, VITS, the Windows voices, OmniVoice and OmniVoice Server) run on sherpa-onnx. Their GPU (CUDA) option needs the optional GPU runtime downloaded from Settings → Compute (about 1.8 GB, CUDA 12 + cuDNN 9) and a restart. Only an NVIDIA driver is required — no CUDA toolkit.
  • The pip-installed Voice Lab engines bring their own PyTorch, so they need only an NVIDIA driver for GPU use; their device is chosen in Settings → Voice clone (CPU, GPU (CUDA) or Auto).

Every Voice Lab engine supports the GPU when your machine has one: the CUDA build of PyTorch is installed from the official PyTorch wheel index for whatever NVIDIA card the driver exposes — there is no model or VRAM requirement.

A Compute combo in every category

Each category that has a Preview button — Available TTS, Recording settings, Punctuation and OmniVoice engines — has a small Compute combo next to it. Pick CPU or GPU (and Auto when both exist) and the next preview runs there. The choice is remembered per category, so a long preview session keeps using it until you change it. The Recording window has the same combo for the recording itself, and a project remembers the compute option it was recorded with.

How much of the machine is used

  • GPU — the whole available NVIDIA card is used, whatever the model: the first CUDA device, cuDNN's autotuner, the TensorFloat-32 fast paths, high float32 matmul precision and the autograd engine switched off.
  • CPU — between 80% and 95% of the machine's logical CPUs are used, so a long recording is fast while the desktop, the Recording window and the audio writer stay responsive. Machines with fewer than four logical CPUs keep one core free instead; a single-core machine uses its one core.

Updating to a newer version

AI Voice Studio is published on GitHub. The application can tell you when a newer version exists and download the installer for you — it never installs anything without asking.

Check now

Choose Help → Check for updates (access key Alt+D), or press Check for updates now in Settings → General → Updates. The application asks GitHub for the latest release and answers either way:

  • If a newer version exists, a dialog shows the installed version, the new version, and the release notes, with three buttons: Download and install, Open release page and Remind me later.
  • If the version you have is the newest, it says so.
  • If GitHub cannot be reached, it says why instead of failing silently.

Downloading and installing

Download and install fetches the installer for this Windows version into a temporary folder, with the same resumable download and progress window the voice downloads use, and a Cancel button. When it has finished, you are asked whether to install now; if you agree, the installer starts and the application closes so its files can be replaced. If you choose Install later, the downloaded file stays where the message tells you.

The download always comes from this project's own release page (github.com/anujj87/AIVoiceStudio/releases), and the release notes are shown before anything is downloaded, so you can read what is changing first.

Automatic checks

By default the application looks for a newer release once a day when it starts. When one is found, the same dialog appears; when there is nothing new, the check is silent. Turn it off in Settings → General → Updates → Check for updates automatically when the application starts.

The dialog's Do not remind me about this version again check box mutes one specific version — you will be told again when a later one is released.

Installing with winget

AI Voice Studio follows the Windows Package Manager standard. Once the package is in the winget repository these work from any terminal:

  • winget install AnujSharma.AIVoiceStudio — install it.
  • winget upgrade AnujSharma.AIVoiceStudio — update it in place.
  • winget uninstall AnujSharma.AIVoiceStudio — remove it.

The same installer serves winget, the built-in update check and a manual download, and it installs per user by default, so no administrator password is needed. The manifests winget uses are generated from this release and live in the repository's winget folder.

Developer Mode

Enable Developer Mode in Settings → General → Enable Developer Mode to unlock advanced features:

  • Heavy logging — detailed diagnostic logs are written to %APPDATA%\AIVoiceStudio\logs\ with multiple subsystem files (gui.log, tts.log, engine.log, recording.log, addons.log, download.log) plus a crash log for unhandled exceptions.
  • Addon management — install, enable, disable and remove third-party addons from the Developer settings panel.
  • Python environment — manage the addon virtualenv, install pip packages, list installed packages.
  • Diagnostics — open the log folder, view system information, and access diagnostic tools.
Developer Mode requires restarting the application for heavy logging to take full effect. Addons are discovered on startup or when toggling Developer Mode. The Developer category is hidden while Developer Mode is off.

Addon System

AI Voice Studio supports a plugin architecture inspired by the NVDA screen reader. Addons let you add new TTS engines, voices, and capabilities. They run in the shared addon environment (addon_env), separate from the per-engine environments described above.

Installing an Addon

  1. Enable Developer Mode in Settings → General.
  2. Open Settings → Developer.
  3. Press Install addon from ZIP... and choose your addon archive.
  4. Restart the application to load the addon.

Managing Addons

In the Developer settings panel you can Enable, Disable or Remove installed addons. The addon list shows each addon's name, version, and status.

See the Addon Development Guide (Help menu) for full details on creating your own addons, adding TTS engines, and managing pip dependencies.

Troubleshooting

“No matching distribution found for torch” while installing an engine

The installer takes PyTorch from the official CUDA wheel index. That happens when the index has no build for the Python version the application runs on, or the download mirror is unreachable. The installer then falls back to the plain CPU packages, so the engine is still installed and usable on the CPU; the dialog reports that GPU support is unavailable. If the fallback also fails, check your internet connection and press Install again.

“ModuleNotFoundError: No module named 'torch'” when previewing or recording

This happens when an engine's package is installed in one environment but the worker was started in another. The application now resolves the interpreter from the engine's own environment and says so in the engine's own words when nothing is installed. If you still see it: open Settings → Voice clone, remove the engine and install it again; then close and reopen the Recording window.

Recording fails with a TorchCodec / FFmpeg error

Newer TorchAudio decodes through TorchCodec, which on Windows looks for FFmpeg's shared libraries. The Voice Lab worker now detects that and falls back to its own audio reader with no FFmpeg needed; FFmpeg remains optional. If you do have FFmpeg installed, install the “full-shared” build so its DLLs are present.

The recording produced an empty (silent) WAV file

This used to happen when the raw float samples were cast straight to int16. The engine now converts samples correctly. If you still hear silence, make sure the selected voice was downloaded completely (re-download it from Settings) and try the CPU compute option.

Recording fails with “Could not load the TTS model… graph.h:1997”

This error came from two different ONNX Runtime copies fighting inside one process. The app now ships exactly one ONNX Runtime, and the pip-installed engines run in their own processes. If you still see it, close the application, open Settings → Compute, remove and re-download the GPU runtime if you use it, and restart the app.

The GPU (CUDA) option does not appear

For the built-in engines: download the GPU runtime in Settings → Compute and restart the application. The option only appears when the runtime is installed and an NVIDIA GPU is detected. For the Voice Lab engines only the NVIDIA driver is needed — device options are in Settings → Voice clone.

My cloned voice cannot be used

The engine must be installed first (Settings → Voice clone, section 1), and the Voice Lab engines download their model on first use. On a slow connection this can take a while — the status text reports progress, and the model is cached afterwards.

The Terms of Use dialog appeared again

It is shown again after a version update whose terms text changed (the application compares the accepted terms version with the current one). It is not a sign that your settings were lost.

MP3 / FLAC output asks for FFmpeg every time

Accept the download prompt once; FFmpeg is saved to your user folder (%APPDATA%\AIVoiceStudio\ffmpeg) and reused afterwards.

Keyboard shortcuts do nothing while a dialog is open

Menu shortcuts (Ctrl+Shift+N and similar) work from the main window. While a modal dialog such as Settings or the Recording window is open, they are intentionally inactive; close the dialog first.

“Check for updates” cannot reach GitHub

The check needs an internet connection to api.github.com. It reports the reason instead of failing silently: a proxy, a firewall, or no connection at all. Nothing else in the application depends on it — you can also download the installer from the release page directly. If the check found an update but the download stopped, the part that was already fetched is reused when you try again, because the download is resumable.

A new version is available but the update dialog did not appear

The automatic check runs once a day and only speaks when it finds something newer. Open Help → Check for updates at any time to look again. If a release was published while you had the application open, the next start picks it up; the collected check date is stored in %APPDATA%\AIVoiceStudio\settings.json.

Where are my files?

  • Recorded audio and processed_text.json: the project folder.
  • Downloaded voices and cloned voices: the model folder (Settings → General).
  • Per-engine Python environments and the Voice Lab engines' models: %APPDATA%\AIVoiceStudio\tts_envs.
  • Optional runtimes, the addon environment and FFmpeg: %APPDATA%\AIVoiceStudio.
  • Acceptance of the terms of use: %APPDATA%\AIVoiceStudio\settings.json.

See also the Read Me, the Third-Party Licences page and, for programmers, the bundled book (F1).
