AI Voice Studio — Addon Development Guide

This guide explains how to create addons for AI Voice Studio. Addons let you extend the application with new TTS engines, custom voices, additional languages, and other capabilities. The addon system is inspired by the NVDA screen reader's addon architecture.

Requirements: AI Voice Studio 2026.3.1 or later with Developer Mode enabled in Settings. You also need Python 3.11+ installed on your system (the addon system manages its own pip environment).
License note: AI Voice Studio is licensed GPL-3.0. All examples in this guide use engines that are also freely licensed (MIT or Apache-2.0). When creating your own addon, ensure any third-party dependencies you use have compatible licenses for your intended use — and remember that an engine's code and its model weights can carry different licences (F5-TTS is MIT code but CC-BY-NC-4.0 weights, for example). The complete list of what the application already bundles is in Help → Third-Party Licences (docs/THIRD-PARTY-LICENSES.html).

Overview

AI Voice Studio supports a plugin architecture that lets third-party developers add new text-to-speech engines and voices. Each addon is a self-contained directory with a manifest file and optional Python code.

What an Addon Can Do

  • Register a new TTS engine — any engine that produces audio samples can be integrated (local models, cloud APIs, etc.).
  • Add new voices — register voices that appear in the Recording window alongside built-in voices.
  • Install pip dependencies — the addon system manages its own Python virtual environment (addon_env); you can install any compatible PyPI package via the dependencies field in your manifest.
  • Support voice cloning — addons can register voice cloning engines that create custom voices from short audio samples.

How Addons Are Loaded

  1. On startup (or when Developer Mode is toggled), the addon manager scans %APPDATA%/AIVoiceStudio/addons/.
  2. Each subdirectory with a valid manifest.json is registered.
  3. Enabled addons have their Python modules imported and engines registered.
  4. Addon-provided voices appear in the Recording window's voice selector.

Quick Start: Your First Addon

Let's create a simple addon that adds a "Hello TTS" engine synthesizing basic sine-wave speech.

Step 1: Create the directory

%APPDATA%\AIVoiceStudio\addons\hello_tts\
  manifest.json
  __init__.py
  engine.py

Step 2: Write manifest.json

{
    "name": "Hello TTS",
    "version": "1.0.0",
    "description": "A simple demo TTS engine for AI Voice Studio.",
    "author": "Your Name",
    "url": "https://example.com/hello-tts",
    "min_app_version": "0.1.0",
    "engine_id": "hello_tts",
    "engine_name": "Hello TTS Engine",
    "engine_entry_point": "engine:HelloTtsEngine",
    "dependencies": [],
    "voices": [
        {
            "id": "hello_english",
            "name": "Hello English",
            "language": "en",
            "data_dir": ""
        }
    ],
    "provides": ["tts_engine", "voice"],
    "enabled": true
}

Step 3: Write engine.py

import numpy as np

class HelloTtsEngine:
    """A minimal TTS engine that produces a test tone."""

    sample_rate = 22050

    def __init__(self, voice_entry: dict):
        self.voice_entry = voice_entry

    def synthesize(self, text: str, sid: int = 0,
                   speed: float = 1.0, pitch: float = 1.0,
                   volume: float = 1.0) -> np.ndarray:
        """Produce a 1-second 440 Hz test tone."""
        duration = 1.0
        t = np.linspace(0, duration, int(self.sample_rate * duration),
                        endpoint=False)
        freq = 440.0 * pitch
        samples = np.sin(2 * np.pi * freq * t) * volume * 0.5
        return (samples * 32767).astype(np.int16)

Step 4: Write __init__.py

"""Hello TTS addon for AI Voice Studio."""

Step 5: Restart AI Voice Studio

The addon should appear in the voice selector with "Hello English" as an available voice.

Tip: Enable Developer Mode in Settings first (General → Developer Mode checkbox). Heavy logging will show detailed information about addon loading in %APPDATA%/AIVoiceStudio/logs/addons.log.

Adding a New TTS Engine

To register a custom TTS engine, implement a class with the standard synthesize() interface:

class MyTtsEngine:
    """Your custom TTS engine."""

    # Required: output sample rate in Hz
    sample_rate = 22050

    def __init__(self, voice_entry: dict):
        self.voice_entry = voice_entry
        # Load your model / connect to API here

    def synthesize(
        self,
        text: str,
        sid: int = 0,
        speed: float = 1.0,
        pitch: float = 1.0,
        volume: float = 1.0,
    ) -> "np.ndarray":
        """Synthesize text into audio.
        Returns int16 PCM samples at self.sample_rate."""
        # Your synthesis logic here
        pass

Engine Registration

  1. Set engine_id in your manifest (e.g. "my_tts").
  2. Set engine_entry_point to "module_name:ClassName".
  3. When a voice with "engine_id": "my_tts" is selected for recording, AI Voice Studio instantiates your engine class with the voice entry dict and calls synthesize().

Using the Built-in Python Environment

If your engine needs extra Python packages (e.g. pyttsx3, requests, openai), add them to the dependencies field in your manifest:

{
    "dependencies": ["pyttsx3", "requests>=2.31"]
}

AI Voice Studio installs these into its managed Python virtual environment when the addon is enabled. No system-wide pip install is needed.

Python Environments: Addons vs. TTS Engines

Since version 2026.3.1 the application does not have one Python environment: it creates one virtual environment per pip-installed TTS engine. This matters when you write an addon, because your code may be imported into the application while the engine it uses runs somewhere else.

EnvironmentUsed forContains
addon_envYour addon, the Developer category, the ONNX GPU runtimeYour dependencies list; the bundled sherpa-onnx runtime
tts_envs\pocket_ttsPocket TTS (Kyutai)pocket-tts, soundfile, scipy
tts_envs\barkBark (Suno AI)transformers, torch, soundfile, scipy
tts_envs\f5ttsF5-TTSf5-tts, torch, torchaudio, soundfile
tts_envs\omnivoiceOmniVoice and OmniVoice Server (shared deliberately)omnivoice-triton / omnivoice-server, torch, CUDA PyTorch

What this means for an addon

  • Your addon's modules are imported into the application process. If your engine needs a package that conflicts with the bundled runtime (a second onnxruntime, a full PyTorch, CUDA libraries), do not import it in the application process: run the work in a subprocess started with the interpreter of the environment that has the package, exactly as the Voice Lab engines do (voicelab.worker).
  • Keep dependencies to packages that live happily next to the addon environment's runtime. A heavy ML stack belongs in an engine environment, not in the addon manifest.
  • Register and inspect an engine's built-in voices the same way for every engine: an addon-provided voice appears in Available TTS, in the Preview cascades and in the Recording window, and respects the category's Compute choice (CPU, or GPU when an NVIDIA GPU is detected).
  • Removing an addon removes its files; packages installed into an engine's own environment stay there until that engine is removed from Settings.
To see a complete, working example of the worker pattern, read ai_voice_studio/voicelab/worker.py (a standalone script started with the engine's own interpreter) and Chapter 77 of the bundled book.

Example 1: Custom Piper Voice Pack

This example registers a custom Piper voice as an addon. Piper voices use the VITS architecture and are licensed under MIT. The app already includes Piper support — this example shows how to add a new Piper voice that isn't in the built-in catalog (e.g. a community-made or custom-trained voice).

manifest.json

{
    "name": "Custom Piper Hindi Voice",
    "version": "1.0.0",
    "description": "A custom Piper VITS voice for Hindi.",
    "author": "Your Name",
    "min_app_version": "0.1.0",
    "engine_id": "piper_hindi_custom",
    "engine_name": "Piper Hindi (Custom)",
    "engine_entry_point": "engine:PiperCustomEngine",
    "dependencies": [],
    "voices": [
        {
            "id": "hi_hi_IN_female",
            "name": "Hindi Female (Custom)",
            "language": "hi",
            "data_dir": "voices/hi_female"
        }
    ],
    "provides": ["tts_engine", "voice"]
}

engine.py

"""Custom Piper voice addon for AI Voice Studio.

Piper voices are VITS-based ONNX models licensed under MIT.
This engine wraps sherpa-onnx (bundled with the app) to run them.
"""
import os
import numpy as np


class PiperCustomEngine:
    """Runs a custom Piper voice via the bundled sherpa-onnx."""

    sample_rate = 22050

    def __init__(self, voice_entry: dict):
        self.voice_entry = voice_entry
        self._dir = voice_entry.get("dir", "")
        self._model = None

    def _ensure_model(self):
        if self._model is not None:
            return
        import sherpa_onnx

        model_path = self._find_file(".onnx")
        tokens_path = os.path.join(self._dir, "tokens.txt")
        lexicon_path = os.path.join(self._dir, "lexicon.txt")
        data_dir = os.path.join(self._dir, "espeak-ng-data")
        if not os.path.isdir(data_dir):
            data_dir = ""

        vits = sherpa_onnx.OfflineTtsVitsModelConfig(
            model=model_path,
            lexicon=lexicon_path if os.path.isfile(lexicon_path) else "",
            tokens=tokens_path,
            data_dir=data_dir,
            dict_dir="",
            noise_scale=0.667,
            noise_scale_w=0.8,
            length_scale=1.0,
        )
        cfg = sherpa_onnx.OfflineTtsConfig(
            model=sherpa_onnx.OfflineTtsModelConfig(
                vits=vits, num_threads=2, provider="cpu"
            ),
            rule_fsts="",
            max_num_sentences=1,
        )
        self._model = sherpa_onnx.OfflineTts(cfg)
        self.sample_rate = self._model.sample_rate

    def _find_file(self, ext: str) -> str:
        for f in os.listdir(self._dir):
            if f.endswith(ext):
                return os.path.join(self._dir, f)
        raise FileNotFoundError(
            f"No {ext} file found in {self._dir}. "
            "Download the Piper voice model first."
        )

    def synthesize(self, text, sid=0, speed=1.0, pitch=1.0, volume=1.0):
        """Synthesize text using the bundled sherpa-onnx + Piper model."""
        self._ensure_model()
        audio = self._model.generate(
            text=text, sid=int(sid), speed=float(speed)
        )
        # sherpa-onnx returns float samples in [-1, 1]
        samples = np.asarray(audio.samples)
        if np.issubdtype(samples.dtype, np.floating):
            return (np.clip(samples, -1.0, 1.0) * 32767).astype(np.int16)
        return samples.astype(np.int16)

"""Custom Kokoro voice addon for AI Voice Studio.

Kokoro-82M is Apache-2.0 licensed and runs via the bundled sherpa-onnx.
This engine wraps the Kokoro-specific ONNX config.
"""
import os
import numpy as np


class KokoroCustomEngine:
    """Runs a custom Kokoro voice via the bundled sherpa-onnx."""

    sample_rate = 24000

    def __init__(self, voice_entry: dict):
        self.voice_entry = voice_entry
        self._dir = voice_entry.get("dir", "")
        self._model = None

    def _ensure_model(self):
        if self._model is not None:
            return
        import sherpa_onnx

        model = self._find_file("model.onnx")
        tokens = os.path.join(self._dir, "tokens.txt")
        voices = os.path.join(self._dir, "voices.bin")
        data_dir = os.path.join(self._dir, "espeak-ng-data")
        if not os.path.isdir(data_dir):
            data_dir = ""

        kokoro = sherpa_onnx.OfflineTtsKokoroModelConfig(
            model=model,
            voices=voices if os.path.isfile(voices) else "",
            tokens=tokens,
            lexicon="",
            data_dir=data_dir,
            dict_dir="",
            length_scale=1.0,
            lang="",
        )
        cfg = sherpa_onnx.OfflineTtsConfig(
            model=sherpa_onnx.OfflineTtsModelConfig(
                kokoro=kokoro, num_threads=2, provider="cpu"
            ),
            rule_fsts="",
            max_num_sentences=1,
        )
        self._model = sherpa_onnx.OfflineTts(cfg)
        self.sample_rate = self._model.sample_rate

    def _find_file(self, name: str) -> str:
        path = os.path.join(self._dir, name)
        if not os.path.isfile(path):
            raise FileNotFoundError(
                f"{name} not found in {self._dir}. "
                "Download the Kokoro model first."
            )
        return path

    def synthesize(self, text, sid=0, speed=1.0, pitch=1.0, volume=1.0):
        self._ensure_model()
        audio = self._model.generate(
            text=text, sid=int(sid), speed=float(speed)
        )
        samples = np.asarray(audio.samples)
        if np.issubdtype(samples.dtype, np.floating):
            return (np.clip(samples, -1.0, 1.0) * 32767).astype(np.int16)
        return samples.astype(np.int16)

Packaging Addons as Distributable ZIPs

Once your addon is tested and ready to share, package it as a ZIP file.

Directory Layout

The ZIP root must contain manifest.json and your Python files:

MyAddon-v1.0.0.zip
  manifest.json        # Required
  __init__.py          # Entry point
  engine.py            # TTS engine
  voices/              # Optional voice data

Creating the ZIP

# From the addon directory:

# PowerShell (Windows):
Compress-Archive -Path * -DestinationPath ..\MyAddon-v1.0.0.zip

# Python:
import zipfile
with zipfile.ZipFile("MyAddon-v1.0.0.zip", "w", zipfile.ZIP_DEFLATED) as zf:
    zf.write("manifest.json")
    zf.write("__init__.py")
    zf.write("engine.py")

# Command line (Linux/Mac):
zip -r MyAddon-v1.0.0.zip manifest.json __init__.py engine.py

Installing a Packaged Addon

  1. Open Settings → Developer (Developer Mode must be enabled).
  2. Press Install addon from ZIP....
  3. Select your MyAddon-v1.0.0.zip file.
  4. The addon is extracted to %APPDATA%/AIVoiceStudio/addons/my_addon/.
  5. Restart the application. The addon's voices appear in the Recording window.
Tip: The addon directory name is derived from the addon's name field in manifest.json (spaces become underscores, lowercased). The ZIP can contain a flat structure (all files at the root) or a subdirectory — the installer finds manifest.json either way.

Version Updates

To distribute an update, simply bump the version field in manifest.json and create a new ZIP. Users install the update by removing the old addon and installing the new ZIP, or by overwriting the addon directory.

Managing pip Dependencies

AI Voice Studio manages its own Python virtual environment at %APPDATA%/AIVoiceStudio/addon_env/. All addon dependencies are installed here, keeping them isolated from the system Python and from each other.

How It Works

  1. Your addon's dependencies field lists required packages.
  2. When the addon is enabled, the addon manager creates the virtualenv (if it doesn't exist) and runs pip install.
  3. Packages are available to your addon's Python code at import time.
  4. To uninstall, disable the addon and reinstall it, or manually manage the virtualenv.

Programmatic pip Access

from ai_voice_studio.python_runtime import get_runtime

rt = get_runtime()
result = rt.pip_install(["pyttsx3", "requests"])
if result["ok"]:
    print("Dependencies installed!")
else:
    print("Error:", result["error"])

# List installed packages
packages = rt.pip_list()
for pkg in packages:
    print(f"{pkg['name']} {pkg['version']}")

Addon Voice Cloning Support

Addons can register voice cloning engines that create custom voices from short reference recordings. The cloned voice then appears in the Recording window alongside downloaded voices.

The application's own cloning engines are the Voice Lab engines (Pocket TTS, Bark, F5-TTS, configured in Settings → Voice clone) plus OmniVoice; a cloner you register through an addon is offered in the same places, and the cloned voices it creates are stored in the model store just like the built-in ones.

Implementing a Cloner

class MyCloner:
    """Voice cloning engine."""

    def clone_voice(
        self,
        name: str,
        sample_path: str,
        language: str,
        model_dir: str = "",
    ) -> dict:
        """Create a cloned voice from a reference recording.
        Returns a voice entry dict."""
        # Your cloning logic
        pass

Registration

Set "provides": ["voice_cloner"] in your manifest and implement the cloner class. The Voice Clone tab in Settings will show your cloner alongside the built-in Voice Lab cloners (Pocket TTS, Bark, F5-TTS) and the OmniVoice clone / voice-design modes.

Installing and Managing Addons

Manual Installation

  1. Place your addon folder in %APPDATA%/AIVoiceStudio/addons/my_addon/.
  2. Restart AI Voice Studio or toggle Developer Mode.

Via Developer Mode (in-app)

  1. Enable Developer Mode in Settings → General.
  2. Open Settings → Developer.
  3. Press "Install Addon from ZIP..." and choose your addon archive.
  4. The addon is extracted and registered automatically.

In Developer Mode, the Developer settings panel shows all installed addons with Enable/Disable buttons. Disabled addons are not loaded at startup but remain on disk.

Removing

In Developer Mode, select an addon and press "Remove" to delete it completely.

Testing Your Addon

Check the Logs

With Developer Mode enabled, use the Log Viewer in the Developer settings panel, or check these log files:

  • logs/addons.log — addon discovery, loading, errors
  • logs/app.log — main application log with full tracebacks
  • logs/crash.log — unhandled exception details

Common Test Steps

  1. Place your addon in the addons directory.
  2. Restart the app (or toggle Developer Mode).
  3. Check addons.log for "Discovered addon: ..." messages.
  4. Create a project and verify your voice appears in the Recording window.
  5. Test Preview and recording with your voice.
  6. Test with different rate/pitch/volume settings.

Debug Tips

  • Use ai_voice_studio.heavy_logging.get_logger("my_addon") in your code for subsystem-specific logging.
  • Check logs/engine.log for engine-specific issues.
  • All caught exceptions in your addon are logged automatically when Developer Mode is on.

Troubleshooting

Addon does not appear in the voice list

  • Verify Developer Mode is enabled.
  • Check addons.log for errors during discovery or loading.
  • Ensure manifest.json is valid JSON.
  • Ensure engine_id matches between manifest and voices.

Dependencies fail to install

  • Check that Python 3.11+ is installed and accessible.
  • Check addons.log for pip error output.
  • Try manually: %APPDATA%/AIVoiceStudio/addon_env/Scripts/pip install your-package

Engine crashes during synthesis

  • Check logs/engine.log and logs/crash.log.
  • Ensure your engine's synthesize() returns np.ndarray of int16 samples at the declared sample_rate.
  • Use ai_voice_studio.heavy_logging.log_exception_with_context() in your except blocks for better diagnostics.

Pip environment is corrupted

Delete the virtualenv and let it be recreated:

Remove-Item -Recurse -Force "%APPDATA%\AIVoiceStudio\addon_env"

Restart AI Voice Studio. The environment will be recreated on the next addon installation.

The addon works but its engine cannot find a package I installed

  • Check which environment the package went into. Addon dependencies go to addon_env; each pip-installed TTS engine gets its own folder under %APPDATA%\AIVoiceStudio\tts_envs\<engine>. Installing torch for Bark does not make it visible to your addon, and vice versa.
  • If your engine needs a heavy dependency, run it in a worker subprocess started with that environment's interpreter instead of importing it in the application process.
  • See Python Environments: Addons vs. TTS Engines.

GPU is offered for my engine but the synthesis runs on the CPU

  • The Compute combo chooses a provider; it cannot give a package GPU support it was not installed with. A plain pip install torch on Windows is CPU-only — the CUDA build has to come from the official PyTorch wheel index (see the PYTORCH_CUDA_INDEX constant in voicelab/engines.py).
  • The CUDA index only carries wheels for some Python versions; when none matches the application's interpreter the install falls back to CPU and says so.
