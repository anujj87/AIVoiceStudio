AI Voice Studio

Developed by Anuj Sharma — version 2026.3.6 — licence: GPL-3.0.

AI Voice Studio converts documents (PDF, TXT, DOC/DOCX, HTML, Markdown and clipboard text) into spoken audio files using free, offline neural voices. It is built with wxPython and sherpa-onnx, and it is designed to work well with screen readers such as NVDA, JAWS and Narrator.

Features at a glance

  • Offline text to speech — Piper, VITS, Kokoro, Matcha, Kitten, OmniVoice, OmniVoice Server, SAPI5 and the Windows Core voices, downloaded or installed once from Settings and reused by all projects.
  • Voice cloning — the Voice Lab — clone a voice from a short sample with Pocket TTS (Kyutai), Bark (Suno AI), F5-TTS or OmniVoice. Each engine is installed into its own Python environment, so their dependencies never conflict.
  • Punctuation control — four modes, including “All”, which speaks every punctuation mark as a word (quote, dot, left paren, tic…) for voices that cannot pronounce punctuation.
  • Project-based recording — each document becomes a project; every segment is saved to disk immediately as WAV, MP3 or FLAC, and recording resumes where it stopped after a crash or close.
  • Record a single file or the rest of the book — Start Selected Recording can re-record one chosen file only, or every file from the chosen break to the end of the project, whether the later files were recorded already or not.
  • Standard playlists — “Audio files with playlist” projects automatically get .m3u8, .pls and .wpl files next to the audio, so the whole recording plays in order in VLC, PotPlayer, GOM, Windows Media Player, Winamp and other modern players.
  • DAISY books — DAISY 2.02 audio books and DAISY 3 (Z39.86-2005) audio + text books with images, built automatically when recording completes and exportable as one ZIP file.
  • GPU acceleration for every engine that supports it — a per-category Compute combo chooses CPU or GPU, the whole NVIDIA card is used on GPU, and an optional ONNX GPU runtime (about 1.8 GB) covers the built-in engines; only an NVIDIA driver is required.
  • Terms of use on first launch — a dialog states the conditions of use (voice-cloning rights, illegal use, commercial licences, system voices, no warranty) and the application starts only after you accept; acceptance is remembered per version.
  • Screen-reader friendly — real MSAA accessible names on every control, NVDA-style settings dialog, keyboard shortcuts throughout.

Quick start

  1. On first launch, read the Terms of Use, tick the agreement check box and press I Agree.
  2. Open Settings (Ctrl+,) and use the Download and remove category to install at least one voice (for example Piper, English US, medium).
  3. Create a New Project (Ctrl+Shift+N), choose a document and how it is split into audio files, and pick the punctuation mode.
  4. Press Start recording in the Recording window. Each finished segment is saved immediately.

Computing back-ends

The app offers Auto, GPU (CUDA) and CPU back-ends in the Recording window, and a Compute combo next to every Preview button in Settings (Available TTS, Recording settings, Punctuation, OmniVoice engines). The choice is remembered per category.

  • CPU is always available: the CPU ONNX Runtime ships with the application. A CPU run uses between 80% and 95% of the machine's logical CPUs, so the desktop and the Recording window stay responsive.
  • GPU (CUDA) for the built-in ONNX engines needs the optional GPU runtime, downloaded from Settings → Compute (about 1.8 GB, includes CUDA 12 and cuDNN 9). It activates after the application restarts. Only an NVIDIA driver is needed — no CUDA toolkit installation.
  • The pip-installed Voice Lab engines (Pocket TTS, Bark, F5-TTS) need only the NVIDIA driver: the CUDA build of PyTorch is installed into the engine's own environment. A GPU run uses the whole available card, whatever the model.

Voice cloning — the Voice Lab

Three TTS engines are installed as Python packages rather than ONNX models, because they generate speech from a reference sample: Pocket TTS (Kyutai), Bark (Suno AI) and F5-TTS. They live in Settings → Voice clone, where you can install or remove an engine, choose the device (CPU, GPU, Auto), pick a built-in voice or create a cloned one from a short recording, and tune the engine's generation defaults. OmniVoice (direct and HTTP-server versions) also supports voice cloning and design. The first synthesis after installing an engine downloads its model from Hugging Face and is therefore slower.

One Python environment per engine

Every pip-installed engine runs in its own virtual environment under %APPDATA%\AIVoiceStudio\tts_envs\<engine>, so the torch, torchaudio, transformers and triton versions one engine needs can never break another. The two OmniVoice engines deliberately share one environment (tts_envs\omnivoice) because they are the same model behind two front-ends; addons use the shared addon_env. Each engine's worker process runs on that environment's interpreter, so PyTorch and CUDA never load into the application process.

Punctuation modes

  • Default — the text is passed to the voice unchanged.
  • None — sentence punctuation is removed before recording.
  • Math — sentence punctuation is removed, math symbols are kept and spoken.
  • All — every punctuation mark is replaced by its spoken word, e.g. my name is "anujsharma". becomes my name is quote anujsharma quote dot, and print('hello') becomes print left paren tic hello tic right paren.

The mode is chosen per project in the New Project window; the default for new projects is set in Settings → Punctuation, where you can also preview any mode through a selected voice.

Project types

  • Audio files with playlist (default) — the document is split into segments; each segment becomes an audio file, and three playlist files (.m3u8, .pls, .wpl) are generated when recording completes. Playlists reference the audio by file name only, so they keep working when the project folder is copied or zipped.
  • Clipboard — paste text and record it directly, no document file needed.
  • DAISY audio and text with images book (3) — a DAISY 3 (Z39.86-2005) book: full DTBook text, NCX navigation, paragraph-level audio synchronization, and images from the source document embedded. Book information (title, author, narrator…) is entered in the wizard.
  • DAISY audio book (2.02) — a DAISY 2.02 audio-only book with SMIL navigation and NCC metadata. MP3 segments are automatically re-encoded to 44.1 kHz MPEG-1 when needed so every DAISY player decodes them fully.

All DAISY project types get an Export DAISY as ZIP button in the Recording window once recording is complete.

Playlists for your recordings

When an Audio files with playlist project finishes recording, three playlist files appear in the project folder next to the audio:

FilePlays in
<project>.m3u8VLC, PotPlayer, GOM, mpv
<project>.plsWinamp, VLC, GOM, PotPlayer
<project>.wplWindows Media Player, PotPlayer, GOM

Open any of them in your player to hear the whole recording from the first segment to the last, in reading order. To add playlists to a project you already recorded: open it and press Start recording — nothing pending means the playlists are written immediately.

Project lifecycle

  • Resume recording — continue where the last recording stopped.
  • Restart project — delete all recordings and settings, keep only the project name, and recreate the project.
  • Restart all recording — delete all audio files and record every segment again from the beginning.
  • Start selected recording — pick the file to record: Select an audio file lists the files already recorded in the project, Select by file break lists every file break of the project whether it is recorded or not. A second choice decides whether only the selected file is recorded or all files from there to the end of the project. The dialog opens even when nothing has been recorded yet, so a long book can be recorded out of order.
  • Remove project — delete the project from the menu and from your hard disk.

First launch — terms of use

On the first start, and again after a version whose terms changed, the application shows a Terms of Use dialog with six conditions of use and an “I agree with all above terms” check box. The bold check box ticks all six; the I Agree and Disagree (Close Program) buttons only become available once it is ticked. Disagreeing, pressing Escape or closing the window exits without starting the application. Acceptance is stored in %APPDATA%\AIVoiceStudio\settings.json.

Storage

  • Projects, recorded audio and processed_text.json (the exact spoken text of every segment) live in the project folder.
  • Downloaded voices and cloned voices live in the model folder (changeable in Settings → General).
  • One Python environment per pip-installed engine, and those engines' models: %APPDATA%\AIVoiceStudio\tts_envs.
  • Optional runtimes (ONNX GPU runtime, addon environment) and FFmpeg live under %APPDATA%\AIVoiceStudio.
