AI Voice Studio

Developed by Anuj Sharma — version 2027.1.0 — licence: GPL-3.0.

AI Voice Studio converts documents (PDF, TXT, DOC/DOCX, HTML, Markdown and clipboard text) into spoken audio files using free, offline neural voices. It is built with wxPython and sherpa-onnx, and it is designed to work well with screen readers such as NVDA, JAWS and Narrator.

Install

Windows, with winget — the package is in the Windows Package Manager repository, so one command installs it and one keeps it current:

winget install AnujSharma.AIVoiceStudio      # install (per user, no admin)
winget upgrade AnujSharma.AIVoiceStudio      # update to the newest release
winget uninstall AnujSharma.AIVoiceStudio    # remove it again

If winget cannot find the package, refresh its source first with winget source update (or pass --source winget); the same identifier is listed by winget search AIVoiceStudio.

Windows, with the installer — download AI-Voice-Studio-v-2027-1-0-Setup-x64.exe (or the -x86 build for 32-bit Windows) from github.com/anujj87/AIVoiceStudio/releases and follow the wizard. The install is per user by default, so no administrator rights are needed; the wizard also offers an all-users install. A scripted install is AI-Voice-Studio-v-2027-1-0-Setup-x64.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART.

Updating — the built-in Help → Check for updates downloads the same installer, and winget upgrade does the same thing from a terminal.

Free, with no hidden cost

AI Voice Studio is completely free. There is no price, no subscription, no “Pro” edition, no trial, no feature locked behind a payment, no advertising and no in-app purchase. There is no account to create and no telemetry — the program does not phone home, and every voice, every engine and every transcription runs on your own computer, offline. The only optional download it offers (the ONNX GPU runtime, about 1.8 GB) is free as well.

The application is free software under the GPL-3.0: you may use it, study it, share it and modify it at no cost. That licence covers the program itself. It does not cover the voice engines and the speech models you download — those are separate works with their own licences, and many of them are free to use while a few are not free for commercial work.

What you can use it for

Because everything runs offline and nothing is uploaded, AI Voice Studio is used for work that must stay private as much as for convenience:

  • Podcasts and audio essays — turn a script (PDF, DOCX, Markdown, HTML or the clipboard) straight into spoken audio, one file per section, with an .m3u8 / .pls / .wpl playlist for the episode.
  • Game voice-over and character voices — clone a voice from a five-second sample, speak the lines yourself, and generate every dialogue file with the same character voice. Eight open-source clone engines are built in, on CPU and on NVIDIA GPU.
  • Study notes and revision audio — record your own notes and hear them while you walk, drive or rest your eyes, instead of re-reading them.
  • Audiobooks, lessons and accessible reading — DAISY 2.02 and DAISY 3 books (audio + text + images) with playlists, built for screen-reader users first.
  • Turning audio or video into text — transcribe recordings, voice memos, interviews, meetings, and video or audio lectures (.mp4, .mkv, .m4a, .mp3…) into TXT, Markdown, SRT, VTT, HTML, JSON or CSV. SRT/VTT are ready-made subtitles; a two-hour lecture can be split into chunks of n minutes per document.
  • Subtitles and captions — the same transcription writes SRT and VTT with real timings, for a video, a lecture recording or an accessibility pass.
  • Readers and volunteers — produce an audio version of a document people cannot read, on a machine with no internet connection.

Features at a glance

  • Offline text to speech — Piper, VITS, Kokoro, Matcha, Kitten, OmniVoice, OmniVoice Server, SAPI5 and the Windows Core voices, downloaded or installed once from Settings and reused by all projects.
  • Voice cloning — the Voice Lab — clone a voice from a short sample with Pocket TTS (Kyutai), F5-TTS, KokoClone, Chatterbox (Resemble AI), Qwen3-TTS, VibeVoice, MOSS-TTS (OpenMOSS), GPT-SoVITS or OmniVoice. Indic Parler-TTS is installed the same way and appears in the same list, but it does not clone — it speaks with one of its named speakers, selected by a prose description of the voice and delivery you can rewrite. Each engine is installed into its own Python environment, so their dependencies never conflict (KokoClone, Chatterbox, Qwen3-TTS, VibeVoice, MOSS-TTS and GPT-SoVITS run only in their own). Chatterbox, Qwen3-TTS, VibeVoice, MOSS-TTS, GPT-SoVITS and Indic Parler-TTS are large transformers and run on the NVIDIA GPU only (Indic Parler-TTS is not a cloning engine at all: it speaks with one of its named speakers, chosen by a description you can rewrite). Every variant offered fits inside 12 GB of video memory, and GPT-SoVITS is clone-only, so its voices appear once you create one. One of these needs a Hugging Face account, and only for cloning: Kyutai's voice-cloning Pocket TTS weights live in the gated repository kyutai/pocket-tts, so Pocket TTS speaks its 26 pre-made voices the moment it is installed while Clone a voice from a sample asks for that licence to be accepted and a read token added in Settings → Hugging Face account.
  • Speech to text — transcribe recordings and videos into TXT, SRT, VTT, HTML, JSON or CSV with a speech-recognition model of your choice (Whisper, Qwen3-ASR, Canary-Qwen, Parakeet TDT, Moonshine, SpeechBrain, Voxtral, Granite Speech). Each model runs in a Python environment of its own, and the Compute combo tells the truth about it: only a model that cannot run without a GPU (Canary-Qwen 2.5B, Granite Speech 8B) is offered the GPU alone, while every other model offers both the CPU and the GPU when a card is present — and the CPU alone on a machine that has none. No model needs an account, a token or a licence click-through.
  • Audio description — a vision-language model watches a video and narrates what is happening for a blind or low-vision viewer, and one run writes three files per video: the description document (script, HTML, SRT, VTT or JSON), the spoken narration read by one of your offline voices, and a described video — the original picture and sound with the description heard over the pauses, or the film stopped for every description (extended audio description). The source video is never modified. Each model runs in a Python environment of its own (describe_envs\<model id>).
  • Punctuation control — four modes, including “All”, which speaks every punctuation mark as a word (quote, dot, left paren, tic…) for voices that cannot pronounce punctuation.
  • Project-based recording — each document becomes a project; every segment is saved to disk immediately as WAV, MP3 or FLAC, and recording resumes where it stopped after a crash or close.
  • Record a single file or the rest of the book — Start Selected Recording (Start Selected Files for a transcription project) can re-record one chosen file only, or every file from the chosen break to the end of the project, whether the later files were recorded already or not.
  • Standard playlists — “Audio files with playlist” projects automatically get .m3u8, .pls and .wpl files next to the audio, so the whole recording plays in order in VLC, PotPlayer, GOM, Windows Media Player, Winamp and other modern players.
  • DAISY books — DAISY 2.02 audio books and DAISY 3 (Z39.86-2005) audio + text books with images, built automatically when recording completes and exportable as one ZIP file.
  • GPU acceleration for every engine that supports it — a per-category Compute combo chooses CPU or GPU, the whole NVIDIA card is used on GPU, and an optional ONNX GPU runtime (about 1.8 GB) covers the built-in engines; only an NVIDIA driver is required.
  • Terms of use on first launch — a dialog states the conditions of use (voice-cloning rights, illegal use, commercial licences, system voices, no warranty) and the application starts only after you accept; acceptance is remembered per version.
  • Screen-reader friendly — real MSAA accessible names on every control, a window title the screen reader's window-title command announces (NVDA+T says AI Voice Studio), the application's own name and version in the executable (so report the application version answers instead of saying “Application unknown”), NVDA-style settings dialog, keyboard shortcuts throughout.
  • Themes — twenty predefined dark looks, plus your own — System default, the original Light and Dark, and twenty predefined dark themes, each with a distinct palette and painted style. The original ten are Midnight Graphite, Obsidian Gold, Deep Navy, Forest Pine, Plum Royale, Crimson Slate, Ocean Teal, Amber Dusk, Carbon Lime and Blue Steel; ten vibrant themes join them without changing any of those — Neon Magenta, Inferno Red, Solar Flare, Voltage Yellow, Laser Lime, Emerald Surge, Cyber Cyan, Azure Rush, Electric Indigo and Ultraviolet. Create as many custom themes as you want in Settings → Appearance → Create custom theme…, choosing every colour, the style and a name.
  • Wallpapers — any theme, predefined or custom, can show a wallpaper on the welcome screen: your own image, or the theme's painted pattern. The welcome screen is a full-width action bar of the four main buttons, a left projects sidebar holding the recent-projects list, and the large empty area that remains — the wallpaper fills only that empty area, so it never paints behind a button or the project list.
  • Updates itself on request — Help → Check for updates asks GitHub for the newest release and, if there is one, shows what changed and downloads the installer for this Windows version; an automatic check runs once a day and can be switched off in Settings → General.
  • winget-compatible — the release ships the manifests the Windows Package Manager needs, so winget install AnujSharma.AIVoiceStudio and winget upgrade AnujSharma.AIVoiceStudio use exactly the same installer.

Quick start

  1. On first launch, read the Terms of Use, tick the agreement check box and press I Agree.
  2. Open Settings (Ctrl+,) and use the Download and remove ONNX TTS category to install at least one voice (for example Piper, English US, medium).
  3. Create a New Project (Ctrl+Shift+N), choose a document and how it is split into audio files, and pick the punctuation mode.
  4. Press Start recording in the Recording window. Each finished segment is saved immediately.

Computing back-ends

The app offers Auto, GPU (CUDA) and CPU back-ends in the Recording window, and a Compute combo next to every Preview button in Settings (Available TTS, Recording settings, Punctuation, Voice Clone, next to the OmniVoice library). The choice is remembered per category.

  • CPU is always available: the CPU ONNX Runtime ships with the application. A CPU run uses between 80% and 95% of the machine's logical CPUs, so the desktop and the Recording window stay responsive.
  • GPU (CUDA) for the built-in ONNX engines needs the optional GPU runtime, downloaded from Settings → Compute (about 1.8 GB, includes CUDA 12 and cuDNN 9). It activates after the application restarts. Only an NVIDIA driver is needed — no CUDA toolkit installation.
  • The pip-installed Voice Lab engines (Pocket TTS, F5-TTS, KokoClone, Chatterbox, Qwen3-TTS, VibeVoice, MOSS-TTS, GPT-SoVITS, Indic Parler-TTS) need only the NVIDIA driver: the CUDA build of PyTorch is installed into the engine's own environment. A GPU run uses the whole available card, whatever the model. KokoClone additionally gets the CUDA build of the ONNX runtime (onnxruntime-gpu), so its Kokoro synthesis runs on the card as well as its Kanade voice conversion. Chatterbox pins PyTorch to 2.6.0, so its environment installs that release's CUDA build from the CUDA 12.6 index — the only index that still carries it.

Voice cloning — the Voice Lab

The Voice Lab engines are installed as Python packages rather than downloaded ONNX models, because they generate speech from a reference sample: Pocket TTS (Kyutai), F5-TTS, KokoClone (Kokoro-ONNX speech with Kanade zero-shot voice conversion: seven languages from a 3–10 second sample, with a Kokoro voice per language available before you clone anything), Chatterbox (Resemble AI), Qwen3-TTS and VibeVoice (Microsoft, community fork), plus Indic Parler-TTS for the Indian languages. They live in Settings → Voice clone, where you can install or remove an engine, choose the device (CPU, GPU, Auto), pick a built-in voice or create a cloned one from a short recording, and tune the engine's generation defaults. OmniVoice (direct and HTTP-server versions) also supports voice cloning and design. The first synthesis after installing an engine downloads its model from Hugging Face and is therefore slower.

Configurable keyboard gestures

Settings → Keyboard gestures works like NVDA's Input Gestures dialog: the application's commands are grouped by category in a tree, each command lists the keyboard keys that trigger it, and you can add a key combination, remove one, or restore the defaults. A key already assigned to another command is named before it is reassigned, and a genuine clash is reported rather than silently resolved. A gesture needs Ctrl, Alt or Windows (or a function key), so a bare letter can never take over ordinary typing. The Help menu's What's New page summarises what changed from the 2026 series to 2027.

One Python environment per engine

Every pip-installed engine runs in its own virtual environment under %APPDATA%\AIVoiceStudio\tts_envs\<engine>, so the torch, torchaudio, transformers and triton versions one engine needs can never break another. The two OmniVoice engines deliberately share one environment (tts_envs\omnivoice) because they are the same model behind two front-ends; addons use the shared addon_env. Each engine's worker process runs on that environment's interpreter, so PyTorch and CUDA never load into the application process.

Voxtral 4B TTS is deliberately not offered

Mistral AI's Voxtral 4B TTS (the 4B text-to-speech model — not the Voxtral speech-to-text models Settings → Manage the STT installs) is not in the TTS catalog, and this was a decision rather than an omission. It is loadable only by vLLM-Omni: transformers refuses the checkpoint ("model type voxtral_tts but Transformers does not recognize this architecture") and there is no ONNX, GGUF or pip distribution, while vLLM publishes no Windows wheels at all — every vllm/vllm-omni wheel is Linux, and upstream points Windows users at WSL2 — so it cannot be installed into an engine's environment on this application's platform. It also needs a single NVIDIA GPU of 16 GB or more (published runs used 20.5 GiB of a 24 GB card and 27.3 GiB of a 32 GB one), above the 12 GB ceiling every Voice Lab engine here is held to, and the open-weights checkpoint omits the codec's encoder, so cloning a voice from a recording cannot work. The model also takes no emotion tags or text instructions: emotion is chosen only by picking one of its preset voices, of which just three carry one (neutral, casual, cheerful). Offering it would have promised an install, a card and a clone that cannot be made. The Voxtral speech-to-text model stays offered, because it does run locally.

Speech to text

Settings → Manage the STT installs speech-recognition models, and the Transcribe dialog of a project runs one of them over its recordings and videos, writing TXT, SRT, VTT, HTML, JSON or CSV documents. A modal progress window shows how far the run has got and can cancel it; finishing offers Open project folder. Every model is installed into a Python environment of its own (stt_envs\<model id>), because their stacks conflict constantly — NeMo against transformers, two different PyTorch pins, protobuf at two versions — so installing one model can never break another.

Only a model that cannot run without a GPU is offered the GPU alone. Almost every model runs on both devices, so the Compute combo offers both the CPU and the GPU whenever an NVIDIA card is present (the recommended device first), and the CPU alone on a machine with no card — many users have none, and must still be able to transcribe. The two GPU-only checkpoints say so: Canary-Qwen 2.5B is a speech-language model and Granite Speech 8B is ~17 GB of weights. Because the device can differ between variants, the combo is rebuilt when the variant changes. “Auto” is not offered, because it would quietly pick the device instead of the user.

A GPU run needs its CUDA runtime inside that model’s own environment. Whisper’s CTranslate2 back-end needs cuBLAS, which faster-whisper does not ship, so the catalog lists it as a CUDA-only package. If an environment predates that wheel a GPU run would quietly fall back to the CPU, so Manage the STT names the missing wheel and turns Install selected model into a repair.

No speech-to-text model needs a Hugging Face account, a token or a licence click-through: a model whose repository is gated (Cohere Transcribe was one) is deliberately not in the catalog. (The describing models have one exception that asks for a token; see Audio description below.) Timings are requested only from the models that produce them — Whisper and the NeMo text models do, the audio language models (Qwen3-ASR, Voxtral, Granite Speech, Moonshine) do not. Voxtral is offered at 3B only: the 24B checkpoint is roughly 48 GB of weights and cannot load on an ordinary 12 GB card.

What you can transcribe

A transcription project accepts audio and video alike: WAV, MP3, FLAC, M4A, AAC, OGG/Opus, WMA and AIFF recordings, and the video containers MP4, MKV, MOV, WebM, AVI, M4V, MPG, MPEG, WMV, TS and M2TS. FFmpeg — which the application already downloads for MP3/FLAC output — decodes the video formats too, so a lecture recorded as .mp4 needs no separate step; point the project at a folder and it walks it recursively. This is what makes the usual jobs possible: a recorded lecture or class becomes searchable text, a voice memo or meeting becomes notes, and a video gets an SRT or VTT subtitle file that any player understands. TXT and Markdown with an optional timestamp, HTML, JSON and CSV are there for study and for feeding the text to something else. Because nothing is uploaded, a confidential interview or a private medical note can be transcribed on a machine with no internet connection at all.

Audio description

Settings → Manage the video describer installs the vision-language models that describe video (Qwen3-VL, Qwen2.5-VL, Qwen2.5-Omni, Qwen3-Omni, Gemma 3, Gemma 4, MiniCPM-o, MiniCPM-V 4, SmolVLM2, Moondream), each into a Python environment of its own under describe_envs\<model id>, so a describing model can never break a TTS engine or a speech-to-text model. Installing the model and downloading a variant are two separate steps: the packages are shared by every variant, a checkpoint is not, so each variant keeps its own Download (or Remove variant) button and its own status.

A model that runs its own modelling code needs more than a describing stack, and its catalogue entry says so instead of asking you to run pip install: MiniCPM-o 2.6 needs torchaudio and librosa for its own files, and the transformers 4.52 series - its code imports whisper internals that 4.53 removed. Pins like that are safe here because each model's environment is its own: Install (or Repair model environment) installs exactly what that one model needs, and nothing else can be affected.

An audio description project (Project → New project → Audio description) collects the video files, the describing model, its variant, the device, the frame rate, the chunk length and the output format. The Audio description window then asks only how the description reaches the viewer — standard (spoken into the pauses of the soundtrack, with optional gap fitting from the speech-to-text model) or extended (the film stops on the current frame for every description and goes on) — and which installed voice speaks it, chosen as the same TTS model → variant → voice cascade the Recording window uses. A Narration voice volume slider sits directly under the voice, so how loud the description is spoken is chosen here as well as in Settings > Recording settings; 1.00 is the voice as downloaded.

The Audio description window also asks which of the two tracks gives way: Track priority, beside Placement and above Start audio description, offers Same volume (the default), Duck, don't lower, Description 25% higher and Description 50% higher. Duck, don't lower does not lower the film at all: it dips the film's own soundtrack to a quarter of its own level (about −12 dB) while a description is actually being spoken, over a fast fade at either end, and lets it back up between descriptions, so a film whose music never stops keeps its own sound everywhere the description is not talking. Where the descriptions really are is not guessed at either: the narration track records the moments the voice is heard while it is written, and two descriptions less than half a second apart are one dip rather than the film flapping between them. Same volume is the default — both tracks exactly as they were produced, which is what a project written before any of these choices existed was mixed as — and the other two keep the description at the level your narration settings gave it while mixing the film's own soundtrack at 75% or 50% of it, so a description is not buried by a film whose music and dialogue never stop. Only the film's track moves — turning the description up would clip and would change a level you chose by ear — and extended placement switches the choice off, because there the film's soundtrack is silent while the description is spoken.

Two things need a Hugging Face account: Gemma 3, and the voice cloning Pocket TTS does. Their weights live in gated repositories, so a download refuses itself until the repository's licence has been accepted on its own page (with an account of your own) and the application has been given a token for that account. There is no per-model token — one read token serves every gated model — so Settings → Hugging Face account does both halves of the job: a picker of the gated models the application ships, Open the model page… for the page whose own accept button grants the access, Get a token… for the page a read token is created on, and Check token / Check access for the two questions the failure itself leaves open — whose token this is, and whether that account may download this model. A gated model says so up front, both in the Status column of Settings → Manage the video describer and — if a run is asked for without a token — in two sentences naming the page to accept and the panel to paste into, instead of the bare 401 — Cannot access gated repo ... Please log in the library reports. The token is kept in your own %APPDATA%\AIVoiceStudio\settings.json, is sent only to huggingface.co, and can also be supplied the way Hugging Face's own tools expect it (an HF_TOKEN environment variable, or a previous huggingface-cli login). Every other model downloads with no account, no token and no click-through. Pocket TTS's 26 pre-made voices do not need it either: only cloning a voice does.

A finished run leaves three files per video in the project folder: Lecture.txt (or .html, .srt, .vtt, .json) with the reviewable script always written beside it; Lecture - narration.wav with the descriptions read aloud at the moments they belong to; and Lecture - described.mp4, the film to watch — the original picture stream copied untouched with the original sound and the description heard together (standard), or the described film with its pauses (extended). The source video is read only.

Descriptions are made one window at a time: about one for every twenty seconds of video, which is the cadence broadcast audio description uses and what makes a change in the picture — text, code, a gesture — get reported instead of summarised away. Each description is told what the previous one said, so the model reports what has changed, and a window whose picture has not changed is skipped rather than repeated. Edit → Restart All Descriptions deletes the three outputs and starts again; Edit → Start Selected Descriptions describes only the videos you pick.

FFmpeg is required — it decodes the frames, reads the video's length and writes the described video — and when it is missing, Start audio description offers to download it into %APPDATA%\AIVoiceStudio\ffmpeg. A checkpoint larger than the graphics card is loaded in 4 bits instead of being spilled to the disk (which used to end a run with a Windows access violation), and a model that cannot run at all is refused with its reason rather than crashing.

Punctuation modes

  • Default — the text is passed to the voice unchanged.
  • None — sentence punctuation is removed before recording.
  • Math — sentence punctuation is removed, math symbols are kept and spoken.
  • All — every punctuation mark is replaced by its spoken word, e.g. my name is "anujsharma". becomes my name is quote anujsharma quote dot, and print('hello') becomes print left paren tic hello tic right paren.

The mode is chosen per project in the New Project window; the default for new projects is set in Settings → Punctuation, where you can also preview any mode through a selected voice. Expression tags are not punctuation: an engine that reads them — Kitten TTS 2.0's leading [emotion] tag, inline <event> tags and (((emphasis))) spans — is given them exactly as written, whichever mode is chosen.

Project types

  • Audio files with playlist (default) — the document is split into segments; each segment becomes an audio file, and three playlist files (.m3u8, .pls, .wpl) are generated when recording completes. Playlists reference the audio by file name only, so they keep working when the project folder is copied or zipped.
  • Clipboard — paste text and record it directly, no document file needed.
  • DAISY audio and text with images book (3) — a DAISY 3 (Z39.86-2005) book: full DTBook text, NCX navigation, paragraph-level audio synchronization, and images from the source document embedded. Book information (title, author, narrator…) is entered in the wizard.
  • DAISY audio book (2.02) — a DAISY 2.02 audio-only book with SMIL navigation and NCC metadata. MP3 segments are automatically re-encoded to 44.1 kHz MPEG-1 when needed so every DAISY player decodes them fully.

All DAISY project types get an Export DAISY as ZIP button in the Recording window once recording is complete.

Project lifecycle

  • Resume recording — continue where the last recording stopped.
  • Restart project — delete all recordings or transcribe files and the settings, keep only the project name, and recreate the project.
  • Restart all recording (Restart all files for a transcription project) — delete all recorded or transcribe files and record or transcribe every segment again from the beginning.
  • Start selected recording (Start selected files for a transcription project) — the dialog opens with a read-only Project base combo naming the project's base, then pick the file to record: Select an audio file (Select a transcribe file) lists the files already in the project, Select by file break lists every file break of the project whether it is recorded or not. A second choice decides whether only the selected file is recorded or all files from there to the end of the project. The dialog opens even when nothing has been recorded yet, so a long book can be recorded out of order.
  • Remove project — delete the project from the menu and from your hard disk.

First launch — terms of use

On the first start, and again after a version whose terms changed, the application shows a Terms of Use dialog with six conditions of use and an “I agree with all above terms” check box. The bold check box ticks all six; the I Agree and Disagree (Close Program) buttons only become available once it is ticked. Disagreeing, pressing Escape or closing the window exits without starting the application. Acceptance is stored in %APPDATA%\AIVoiceStudio\settings.json.

Storage

  • Projects, recorded audio and processed_text.json (the exact spoken text of every segment) live in the project folder.
  • Downloaded voices and cloned voices live in the model folder (changeable in Settings → General).
  • One Python environment per pip-installed engine, and those engines' models: %APPDATA%\AIVoiceStudio\tts_envs.
  • One Python environment per speech-to-text model: %APPDATA%\AIVoiceStudio\stt_envs\<model id>. Their models come from the shared Hugging Face cache.
  • Optional runtimes (ONNX GPU runtime, addon environment) and FFmpeg live under %APPDATA%\AIVoiceStudio.
  • The Python those environments are built on is a per-user copy of the one the application ships: %APPDATA%\AIVoiceStudio\python_runtime. It lives there rather than in the program folder so that reinstalling, updating or moving the application leaves your installed models working - an older environment that names a Python which has gone is repaired in place, with its downloaded packages kept.
