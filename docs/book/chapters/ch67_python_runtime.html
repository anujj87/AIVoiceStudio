Chapter 67

Managed Python Runtime

Learning Objectives

  • Understand why AIVS manages its own Python environment
  • See how the PythonRuntime creates and manages venvs
  • Understand the frozen app vs. development mode distinction

67.1 Why a Managed Runtime?

AIVS needs to install optional packages (OmniVoice, coqui-tts) into an isolated venv without touching the main application's packages. This is critical because:

  • The main app uses sherpa-onnx (ONNX runtime)
  • Optional engines use PyTorch/CUDA (conflicts with ONNX)
  • Addons may need their own dependencies
  • Never modify the installer's packages

67.2 PythonRuntime Architecture

# %APPDATA%/AIVoiceStudio/addon_env/
# ├── Scripts/python.exe     (Windows)
# ├── Scripts/pip.exe
# └── Lib/site-packages/      (installed packages)

class PythonRuntime:
    def ensure_env(self):
        """Create the venv if it doesn't exist."""
        if not self.is_created:
            subprocess.run([self.system_python, "-m", "venv", self._env_dir])

    def pip_install(self, packages, progress=None):
        """Install packages into the managed venv."""
        pip = self.ensure_pip()
        proc = subprocess.Popen([pip, "install"] + packages, ...)
        for line in proc.stdout:
            if progress: progress(line, 0, 0)

    def run_in_env(self, script):
        """Run a Python script inside the managed venv."""
        return subprocess.run([self.python_exe, "-c", script], ...)

    def is_package_installed(self, package_name):
        """Check if a package is installed in the venv."""
        result = self.run_in_env(
            f"import importlib.metadata; print(importlib.metadata.version('{package_name}'))"
        )
        return result.returncode == 0

67.4 Key Takeaways

  • The PythonRuntime manages an isolated venv for optional packages
  • run_in_env() executes scripts inside the managed venv
  • The runtime must work in both dev mode and frozen app mode
  • Package installation is cancellable via threading.Event
