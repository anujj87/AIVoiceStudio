Chapter 73

Playlist Builder

Learning Objectives

  • Generate standard playlist files that modern players understand (M3U8, PLS, WPL)
  • Keep playlists portable by referencing audio through sibling-relative file names only
  • Escape XML attributes correctly with xml.sax.saxutils.escape so WPL files never break
  • Wire playlist generation into the recording lifecycle without touching the audio pipeline

73.1 Why a Playlist Builder?

An Audio files with playlist project records each segment of a document into its own audio file. After a long recording session you may have fifty files named 01 page 1.wav, 02 page 2.wav and so on. Every modern player can open a folder of audio files, but none of them know the order in which the pages should be played. The documents/playlist_builder.py module solves exactly this problem: after recording completes it writes three standard playlist files next to the audio, and every player (VLC, PotPlayer, GOM, Windows Media Player, Winamp, mpv) understands at least one of them:

FileFormatPlayers
<project>.m3u8Extended M3U, UTF-8VLC, PotPlayer, GOM, mpv
<project>.plsWinamp playlist (INI style)VLC, GOM, PotPlayer, Winamp
<project>.wplWindows Media Playlist (SMIL/XML)Windows Media Player, PotPlayer, GOM
Portability rule: every entry references the audio by file name only — never an absolute path. The playlists keep working when the project folder is copied, moved or zipped, because the player resolves a bare name against the folder the playlist itself lives in.

73.3 The XML Attribute Helper

def _quoted(value: str) -> str:
    """XML attribute value, always wrapped in double quotes."""
    return '"%s"' % _xml_escape(value).replace('"', """)

Explain Line by Line Code Description (Block 3)

  1. Line 1: def _quoted(value: str) -> str:
    Defines a private helper that returns value as a safely quoted XML attribute value. The WPL writer uses it for every src and title attribute it emits.
  2. Line 2: """XML attribute value, always wrapped in double quotes."""
    The docstring records the contract: the result is always wrapped in double quotes, which is what the Windows Media Player playlist parser expects.
  3. Line 3: return '"%s"' % _xml_escape(value).replace('"', """)
    Three steps in one expression. First _xml_escape(value) replaces &, < and > with entities. Then .replace('"', """) escapes double quotes — necessary because escape() deliberately leaves quotes alone (it escapes text nodes, not attributes). Finally the % operator wraps the result in literal double quotes. Without the quote escaping, a segment titled He said "hello" would produce a WPL file that Windows Media Player refuses to open.
Common pitfall: xml.sax.saxutils.escape() only escapes the characters that are illegal in text. Attributes are delimited by quotes, so a quote inside an attribute value must also be escaped (&quot;). This one-line helper is the difference between a WPL file that opens everywhere and one that only works for titles without quotes.

73.4 Selecting and Ordering Entries

def _ready_entries(segments: List[Dict[str, Any]]) -> List[Dict[str, Any]]:
    """Recorded segments (``status == "done"`` with a saved file), in order."""
    entries = [
        s for s in segments
        if s.get("status") == "done" and s.get("saved")
    ]
    entries.sort(key=lambda s: s.get("index", 0))
    return entries

Explain Line by Line Code Description (Block 4)

  1. Line 1: def _ready_entries(segments):
    Defines the filter that decides which segments appear in the playlists. The function takes the raw segments list loaded from project.json and returns only the ones that were actually recorded.
  2. Line 2: """Recorded segments ... in order."""
    The docstring states both the filter condition and the guarantee: results come back sorted by segment index, i.e. in the same order the audio was recorded.
  3. Lines 3–5: entries = [s for s in segments if s.get("status") == "done" and s.get("saved")]
    A list comprehension that keeps a segment only when both conditions hold. status == "done" means the TTS engine finished that segment, and a truthy s.get("saved") means an audio file name was recorded for it. Segments that are still pending (or done but somehow without a saved file) are excluded, so a half-finished recording produces a playlist covering only the audio that really exists. s.get(...) is used instead of s["status"] so a malformed segment dict cannot raise KeyError — it simply fails both checks and is skipped.
  4. Line 6: entries.sort(key=lambda s: s.get("index", 0))
    Sorts the filtered list in place by the segment's index field. sort(key=...) calls the lambda once per element and orders by the returned number. The sort is stable, so segments with equal indices keep their original relative order. This matters because project.json may list segments in any order after edits and re-recording.
  5. Line 7: return entries
    Returns the ordered list to the caller.
def _titles(entries: List[Dict[str, Any]]) -> List[str]:
    return [str(s.get("title") or os.path.basename(s["saved"])) for s in entries]


def _files(entries: List[Dict[str, Any]]) -> List[str]:
    return [os.path.basename(str(s["saved"])) for s in entries]

Explain Line by Line Code Description (Block 5)

  1. Line 1: def _titles(entries):
    Defines the helper that extracts the display title for every playlist entry.
  2. Line 2: return [str(s.get("title") or os.path.basename(s["saved"])) for s in entries]
    A comprehension with a fallback chain. s.get("title") returns the segment title, or None if the project file has none. The or operator then falls back to os.path.basename(s["saved"]) — the audio file's own name such as 01 page 1.wav. str(...) guarantees the final value is a string even if the title field held a number. Players display these titles next to each track.
  3. Line 4: def _files(entries):
    Defines the helper that extracts the audio file names.
  4. Line 5: return [os.path.basename(str(s["saved"])) for s in entries]
    For every entry, takes the saved path and strips everything up to the last separator with os.path.basename. str(...) is defensive: even if a project file stored the path as something else, the playlist receives a plain string. The result is a bare file name like 02 page 2.wav, which is exactly the portable reference the module promises.

73.5 The Three Writers

M3U8 (extended M3U, UTF-8)

def _write_m3u8(path: str, title: str, names: List[str], titles: List[str]) -> None:
    lines = ["#EXTM3U", f"#PLAYLIST:{title}"]
    for name, entry_title in zip(names, titles):
        lines.append(f"#EXTINF:-1,{entry_title}")
        lines.append(name)
    with open(path, "w", encoding="utf-8", newline="\n") as fh:
        fh.write("\n".join(lines) + "\n")

Explain Line by Line Code Description (Block 6)

  1. Line 1: def _write_m3u8(path, title, names, titles):
    Defines the writer for the extended M3U format. path is the output file, title the playlist name shown by players, names the audio file names and titles the matching display titles (same order).
  2. Line 2: lines = ["#EXTM3U", f"#PLAYLIST:{title}"]
    Starts the file with the two mandatory header lines. #EXTM3U tells the player "this is the extended M3U format, not a plain one". #PLAYLIST:{title} is an f-string that names the whole playlist; VLC shows this name in its title bar, PotPlayer in its playlist header.
  3. Line 3: for name, entry_title in zip(names, titles):
    Iterates over both lists in parallel: zip(names, titles) yields (name, title) pairs, one per track, stopping at the shorter list.
  4. Line 4: lines.append(f"#EXTINF:-1,{entry_title}")
    Appends the extended-info line for one track. The format is #EXTINF:<duration in seconds>,<artist>-<title>. The value -1 means "duration unknown" — the player reads the real length from the audio file itself when it loads the track. Everything after the comma is the display title.
  5. Line 5: lines.append(name)
    Appends the track reference itself — a bare file name such as 01 page 1.wav. Non-comment lines in M3U are always the media locations, resolved relative to the playlist file's folder.
  6. Line 6: with open(path, "w", encoding="utf-8", newline="\n") as fh:
    Opens the output file for writing. encoding="utf-8" is what makes this an M3U8 file (the "8" stands for UTF-8) and lets non-ASCII segment titles survive. newline="\n" overrides the Windows default so the file ends every line with a bare LF — the line ending players expect — regardless of the host platform.
  7. Line 7: fh.write("\n".join(lines) + "\n")
    Joins all collected lines with newlines into one string and writes it, adding one final newline so the file is well-formed. A single write call is also faster than hundreds of small writes.

PLS (Winamp style)

def _write_pls(path: str, title: str, names: List[str], titles: List[str]) -> None:
    lines = ["[playlist]"]
    for i, (name, entry_title) in enumerate(zip(names, titles), start=1):
        lines.append(f"File{i}={name}")
        lines.append(f"Title{i}={entry_title}")
        lines.append(f"Length{i}=-1")
    lines.append(f"NumberOfEntries={len(names)}")
    lines.append("Version=2")
    with open(path, "w", encoding="utf-8", newline="\n") as fh:
        fh.write("\n".join(lines) + "\n")

Explain Line by Line Code Description (Block 7)

  1. Line 1: def _write_pls(path, title, names, titles):
    Defines the writer for the PLS (Winamp) playlist format, an INI-style key=value text format.
  2. Line 2: lines = ["[playlist]"]
    Starts the file with the mandatory [playlist] section header. Every PLS key must live inside this section.
  3. Line 3: for i, (name, entry_title) in enumerate(zip(names, titles), start=1):
    Loops over the parallel name/title pairs with a counter. enumerate(..., start=1) numbers the entries from 1, because the PLS format requires 1-based keys (File1, File2, …) and a missing File1 makes some parsers reject the whole file.
  4. Line 4: lines.append(f"File{i}={name}")
    Writes the track reference key. File1=01 page 1.wav means "the first track is this file". As in M3U, a bare name is resolved relative to the playlist's folder.
  5. Line 5: lines.append(f"Title{i}={entry_title}")
    Writes the display title for the same entry number. The number must match the File key exactly or players will pair the wrong title with the wrong file.
  6. Line 6: lines.append(f"Length{i}=-1")
    Writes the track length in seconds; -1 again means "unknown, read it from the file".
  7. Lines 7–8: lines.append(f"NumberOfEntries={len(names)}") and lines.append("Version=2")
    Closes the section with the two mandatory footer keys. NumberOfEntries tells parsers how many tracks to expect (so a truncated file is detected), and Version=2 identifies the PLS format revision every current player expects.
  8. Lines 9–10: with open(...) as fh: fh.write(...)
    Writes the joined lines with UTF-8 encoding and LF line endings — identical I/O pattern to the M3U8 writer, for the same reasons.

WPL (Windows Media Player, SMIL)

def _write_wpl(path: str, title: str, names: List[str]) -> None:
    body = "".join(
        f'      \n' for name in names
    )
    wpl = (
        '\n'
        '\n'
        '  \n'
        '    \n'
        f'    {_quoted(title)}\n'
        '  \n'
        '  \n'
        '    \n'
        + body +
        '    \n'
        '  \n'
        '\n'
    )
    with open(path, "w", encoding="utf-8", newline="\n") as fh:
        fh.write(wpl)

Explain Line by Line Code Description (Block 8)

  1. Line 1: def _write_wpl(path, title, names):
    Defines the writer for the Windows Media Playlist format. Note it does not take the titles list: WPL has no per-track title attribute — Windows Media Player reads the media's own metadata instead.
  2. Lines 2–3: body = "".join(f' \n' for name in names)
    Builds the XML body with a generator expression joined into one string. For every audio file it emits one <media src="..."/> element — the SMIL way of saying "play this file in sequence". The src value passes through _quoted(), so quotes and XML-special characters inside a file name can never break the document. The six leading spaces indent each element to match the surrounding structure.
  3. Lines 4–16: wpl = ('' ... )
    Assembles the full SMIL document as one concatenated string. <?wpl version="1.0"?> is the processing instruction Windows Media Player uses to recognise the file type. The <meta name="Generator"> element records which application produced the playlist. The <seq> (sequence) element means its children play one after another in document order — exactly the reading order of the recorded document.
  4. Lines 17–18: with open(...) as fh: fh.write(wpl)
    Writes the finished XML with UTF-8 encoding and LF line endings. The file is now a valid WPL playlist that Windows Media Player, PotPlayer and GOM all open.

73.6 The Public Entry Point

def build_playlists(
    project_dir: str,
    project_name: str,
    segments: List[Dict[str, Any]],
) -> List[str]:
    """Write the M3U8/PLS/WPL playlists into ``project_dir``.

    Returns the list of written file paths; empty when no segment has been
    recorded yet.  Existing playlist files are overwritten so they stay in
    sync with the project's segments (e.g. after re-recording).
    """
    entries = _ready_entries(segments)
    if not entries:
        return []
    safe = "".join(
        c if c not in '\\/:*?"<>|' else "_" for c in project_name
    ).strip() or "playlist"
    names = _files(entries)
    titles = _titles(entries)

    written: List[str] = []
    m3u8_path = os.path.join(project_dir, safe + ".m3u8")
    _write_m3u8(m3u8_path, project_name, names, titles)
    written.append(m3u8_path)

    pls_path = os.path.join(project_dir, safe + ".pls")
    _write_pls(pls_path, project_name, names, titles)
    written.append(pls_path)

    wpl_path = os.path.join(project_dir, safe + ".wpl")
    _write_wpl(wpl_path, project_name, names)
    written.append(wpl_path)
    return written

Explain Line by Line Code Description (Block 9)

  1. Lines 1–4: def build_playlists(project_dir, project_name, segments):
    The one public function of the module, called by the Recording window after recording finishes. It takes the project folder (where the audio already lives), the human project name (which becomes the playlist file base name), and the full segment list from project.json. It returns the list of files it wrote — the caller turns this into the "playlists were generated" note in the completion dialog.
  2. Lines 5–6: entries = _ready_entries(segments) / if not entries: return []
    Filters and orders the recorded segments. If nothing was recorded the function returns an empty list immediately and no playlist files are created — there is nothing to list.
  3. Lines 7–9: safe = "".join(c if c not in '\\/:*?"<>|' else "_" for c in project_name).strip() or "playlist"
    Turns the project name into a safe file-name base. The comprehension keeps every character except the nine characters Windows forbids in file names (\ / : * ? " < > |); each forbidden one becomes an underscore. .strip() removes leading/trailing spaces, and the or "playlist" fallback covers a name that was entirely punctuation — a project named ??? must not produce a file literally named playlist.m3u8's base as an empty string.
  4. Lines 10–11: names = _files(entries) / titles = _titles(entries)
    Extracts the two parallel lists the writers need: bare audio file names and their display titles, both in segment order.
  5. Lines 13–21: the three os.path.join(project_dir, safe + ".ext") blocks
    Writes each playlist into the project folder next to the audio. Each writer call is followed by written.append(...), so by the end the list holds the three absolute paths (.m3u8, .pls, .wpl) in that order. Opening a writer with "w" truncates any existing file, which is exactly the desired "regenerate on every recording" behaviour: after re-recording one segment, the playlists are rebuilt with the new content in the correct order.

73.7 How the Recording Window Uses It

The wiring lives in gui/recording_dialog.py. When the synthesis worker reports that all segments are done, the dialog runs:

def _build_playlists_if_needed(self):
    self._playlist_files = []
    ptype = self.data.get("project_type", "audio_playlist")
    if ptype != "audio_playlist":
        return
    try:
        fresh = project.load_project(self.project_dir)
        from ..documents.playlist_builder import build_playlists
        self._playlist_files = build_playlists(
            self.project_dir,
            fresh.get("name", "playlist"),
            fresh.get("segments", []),
        )
    except Exception as exc:
        log.warning("Playlist generation failed: %s", exc)

Explain Line by Line Code Description (Block 10)

  1. Line 2: self._playlist_files = []
    Resets the result list on every call, so a DAISY project (which returns early) never leaves a stale value behind.
  2. Line 3: ptype = self.data.get("project_type", "audio_playlist")
    Reads the project type with a default, then the guard on the next line makes playlist generation exclusive to Audio files with playlist projects — DAISY books get their own structure instead.
  3. Line 5: fresh = project.load_project(self.project_dir)
    Reloads project.json from disk instead of trusting the copy the dialog loaded when it opened. This is essential: the synthesis worker runs in a background thread and has been marking segments done in the file while the dialog sat idle — the in-memory copy still shows them as pending, which would produce an empty playlist.
  4. Line 6: from ..documents.playlist_builder import build_playlists
    A local (function-level) import. Importing lazily keeps the recording window's startup fast and avoids a hard module dependency at import time.
  5. Lines 7–10: self._playlist_files = build_playlists(...)
    Calls the builder with the freshly loaded name and segments and stores the three written paths for the completion summary.
  6. Lines 11–12: except Exception as exc: log.warning(...)
    Catches any failure (a read-only folder, a full disk) and logs a warning instead of crashing. Playlist generation is a convenience on top of a finished recording — the recording itself is already safely on disk, so the user must not lose the completion message because a playlist could not be written.

73.9 Key Takeaways

  • Three playlist formats cover all modern players: M3U8 (VLC/PotPlayer/GOM), PLS (Winamp family), WPL (Windows Media Player)
  • Entries are file names only — playlists survive moving, copying or zipping the project folder
  • duration = -1/#EXTINF:-1 tells players to read the real length from each audio file
  • XML attributes need &quot; escaping too — escape() alone is not enough for WPL
  • Generation runs after recording and reads fresh project state from disk, so it is a pure post-processing step that never touches the audio pipeline
