Chapter 52

Settings Dialog

Current implementation (2026.3.1). The dialog now has a Voice Clone page with one section per Voice Lab engine: install / remove the engine, its size and licence, the device selector (CPU / GPU / Auto), per-engine tuning defaults and a Compute combo next to each Preview button. Installs run in the engine’s own Python environment, and the dialog reports the result of an import check when pip finishes. See Chapter 77 and Chapter 78. Package status labels are answered from a cached, non-blocking probe (venv_packages) so opening Settings stays instant under a screen reader.

Learning Objectives

  • Understand the multi-tab Settings dialog architecture
  • See how settings panels are loaded and managed
  • Understand the NVDA SettingsPanel pattern

52.2 Panel Management Pattern

# From gui/settings_dialog.py
class SettingsDialog(wx.Dialog):
    def __init__(self, parent, settings, store):
        super().__init__(parent, title="Settings", size=(800, 600))

        # Create a notebook (tab control)
        self._notebook = wx.Notebook(self)

        # Create panels
        self._panels = []
        self._add_panel(GeneralPanel(self._notebook, settings))
        self._add_panel(DownloadPanel(self._notebook, store, downloader))
        self._add_panel(AvailablePanel(self._notebook, store))
        # ... more panels ...

    def _add_panel(self, panel):
        self._notebook.AddPage(panel, panel.title)
        self._panels.append(panel)

    def _on_ok(self, _):
        # Apply all panels
        for panel in self._panels:
            if hasattr(panel, "apply_to_settings"):
                panel.apply_to_settings()
        self.settings.save()
        self.EndModal(wx.ID_OK)

52.3 Key Takeaways

  • The Settings dialog uses a wx.Notebook with 8 tabs
  • Each tab is a panel class with its own UI and logic
  • Panels implement apply_to_settings() to save their state
  • The dialog follows the NVDA SettingsPanel pattern (title, description, apply)
  • Settings are saved immediately on OK
