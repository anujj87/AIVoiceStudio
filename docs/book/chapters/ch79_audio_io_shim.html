Chapter 79

Audio I/O That Works on a Machine With No FFmpeg

Learning Objectives

  • Understand why torchaudio.load stopped being self-contained
  • Probe a third-party decoder on a real file instead of trusting documentation
  • Replace one API with another transparently, and restore the original when it works
  • Convert reference audio once, deterministically, instead of failing on a format
  • Report a degraded-but-working path to the user instead of hiding it

79.1 The Failure That Started This

A user installed F5-TTS and pressed Preview. The engine loaded, the model downloaded, and then:

RuntimeError: Failed to create AudioDecoder for C:\Users\...\tmpvmlfm3u2.wav:
Could not load libtorchcodec. Likely causes:
  1. FFmpeg is not properly installed in your environment...
  2. The PyTorch version (2.11.0+cu128) is not compatible with this
     version of TorchCodec...
OSError: Could not load this library:
  ...\torchcodec\libtorchcodec_core9.dll

Three things were true at once, and it is worth separating them:

  • From torchaudio 2.9 onward, load/save decode through TorchCodec; torchaudio’s own backend argument is accepted and ignored. Code that looks like it selects a decoder no longer selects anything.
  • TorchCodec on Windows needs FFmpeg’s shared libraries (avcodec-*.dll and friends), which belong to an FFmpeg build the application does not ship.
  • The user’s machine had no FFmpeg at all. Every version TorchCodec tried failed, which is why the message lists six versions — that wall of text is one failure repeated, not six problems.
The application already downloads FFmpeg on request for MP3/FLAC output. Requiring it for reading audio would turn an optional feature into a hard requirement, so the audio path was fixed in code instead.

79.2 Measure, Do Not Assume

TorchCodec is not always broken — it works perfectly on a machine with FFmpeg. Replacing it unconditionally would throw away a capable decoder. So the code measures it, on a real file:

def _write_probe_wav(path, sample_rate=16000, seconds=0.05):
    frames = max(1, int(sample_rate * seconds))
    with wave.open(path, "wb") as handle:
        handle.setnchannels(1)
        handle.setsampwidth(2)
        handle.setframerate(int(sample_rate))
        handle.writeframes(struct.pack(f"<{frames}h", *([0] * frames)))


def _torchcodec_works(torchaudio):
    path = os.path.join(tempfile.gettempdir(), "aivs_voicelab_probe.wav")
    try:
        _write_probe_wav(path)
        torchaudio.load(path)
        return True
    except Exception:
        return False
    finally:
        with contextlib.suppress(OSError):
            os.remove(path)

Explain Line by Line Code Description (Block 1)

  1. Lines 1–7: _write_probe_wav
    Builds the smallest possible WAV with the standard library: one channel, 16-bit samples, 0.05 seconds of silence.wave needs no dependency, so this works even on a machine where every audio library is broken — which is precisely the situation being tested. The _write_probe_wav name says what it writes; the frames = max(1, ...) guard prevents a zero-frame file, which some decoders reject for a different reason and would produce a misleading “broken” verdict.
  2. Line 4: struct.pack(f"<{frames}h", *([0] * frames))
    Little-endian sequence of signed 16-bit zeros — raw PCM in exactly the layout a WAV header promises. Generating samples in code beats bundling a fixture file, because the probe must not depend on anything the packaging step might forget to include.
  3. Lines 10–12: the actual measurement
    A real decode, not a version check. Feature detection by attempting the operation is the only method that survives version combinations nobody documented — and this bug is proof that documented compatibility tables are not enough.
  4. Lines 13–17: cleanup on every path
    finally removes the temp file even when the decode fails, so a broken decoder cannot leave litter in %TEMP% on every launch. contextlib.suppress(OSError) keeps a failed cleanup from masking the real result.

79.3 A Drop-In Replacement Built on soundfile

soundfile wraps libsndfile, and — crucially — libsndfile ships inside the wheel. Reading WAV, FLAC, OGG and MP3 therefore works with nothing installed on the machine.

def _soundfile_load(sf, torch, uri, frame_offset=0, num_frames=-1,
                    normalize=True, channels_first=True, format=None,
                    buffer_size=4096, backend=None):
    if hasattr(uri, "read"):
        data, sample_rate = sf.read(uri, dtype="float32", always_2d=True)
    else:
        try:
            start = max(0, int(frame_offset or 0))
        except (TypeError, ValueError):
            start = 0
        try:
            frames = int(num_frames)
        except (TypeError, ValueError):
            frames = -1
        data, sample_rate = sf.read(
            str(uri), start=start, frames=(frames if frames > 0 else -1),
            dtype="float32", always_2d=True,
        )
    samples = np.ascontiguousarray(data.T if channels_first else data)
    tensor = torch.from_numpy(samples.astype(np.float32, copy=False))
    return tensor, int(sample_rate)

Explain Line by Line Code Description (Block 2)

  1. Lines 1–2: the signature
    It mirrors torchaudio.load exactly, including the arguments the engines pass but that do not apply (normalize, format, buffer_size, backend). A shim that accepts a narrower signature is a shim that breaks the first time an engine passes a new keyword — the engines here are third-party code that changes between releases.
  2. Line 3: file-like objects
    Callers may pass an open file or a buffer rather than a path; hasattr(uri, "read") routes that case to soundfile’s own handling, so the shim covers both call styles.
  3. Lines 5–14: offsets and frame counts
    Frame slicing is converted from torchaudio’s conventions to soundfile’s: a negative or unparsable num_frames becomes “the whole file”, and a negative offset clamps to zero. Defensive conversion here means a caller passing None gets audio instead of an exception about a type.
  4. Line 15: the shape flip
    soundfile returns (frames, channels); torchaudio returns (channels, frames). data.T plus np.ascontiguousarray fixes both the axis order and the memory layout — the second part matters because a non-contiguous array passed to torch.from_numpy can produce wrong strides or copies deep inside an engine.
  5. Line 16: the tensor
    astype(np.float32, copy=False) avoids a copy when the dtype already matches, and int(sample_rate) normalises NumPy integers to plain Python ints, which is what the engines and WAV writers expect.

The saving side is the mirror image, with one extra concern — integer PCM must stay integer:

def _soundfile_save(sf, torch, uri, src, sample_rate, channels_first=True,
                    format=None, encoding=None, bits_per_sample=None,
                    buffer_size=4096, backend=None, compression=None):
    data = src
    if hasattr(data, "detach"):      # torch tensor
        data = data.detach()
    if hasattr(data, "cpu"):
        data = data.cpu()
    if hasattr(data, "numpy"):
        data = data.numpy()
    array = np.asarray(data)
    if channels_first and array.ndim > 1:
        array = array.T
    if array.dtype.kind in "iu":     # integer PCM stays integer
        sf.write(str(uri), array, int(sample_rate))
    else:
        sf.write(str(uri), np.clip(array.astype(np.float32), -1.0, 1.0),
                 int(sample_rate))

Explain Line by Line Code Description (Block 3)

  1. Lines 5–10: duck-typed conversion
    The argument may be a PyTorch tensor (possibly on the GPU), a NumPy array or a plain list. Each hasattr step unwraps one layer — detach before cpu before numpy is the order that works for a tensor with gradients on a CUDA device. Duck typing is the right tool here because importing torch inside these helpers would defeat the point of keeping them dependency-light.
  2. Lines 11–13: channel order
    The same flip as on load, guarded by array.ndim > 1 so mono data is not accidentally squeezed into a 1-D array.
  3. Lines 14–15: the integer branch
    Sound is often handled as int16 PCM in this project. Writing int16 through libsndfile preserves it exactly; converting to float and back would add rounding for no reason. dtype.kind in "iu" is the compact way to say “signed or unsigned integer”.
  4. Lines 16–18: the float branch
    Float audio is clipped to −1.0…1.0 before writing, because libsndfile’s behaviour with out-of-range floats has changed between versions. An explicit clip makes the file’s contents predictable everywhere.

79.4 Installing the Shim Only When Needed

_AUDIO_SHIM_ENV = "AIVS_VOICELAB_NO_AUDIO_SHIM"


def _install_audio_io_shim(torchaudio=None, soundfile=None, torch=None):
    if str(os.environ.get(_AUDIO_SHIM_ENV, "")).strip().lower() in ("0", "false", "no"):
        return None
    if torchaudio is None:
        try:
            import torchaudio as _torchaudio
        except Exception:
            return None
        torchaudio = _torchaudio
    if getattr(torchaudio, "_aivs_soundfile_io", False):
        return None
    if _torchcodec_works(torchaudio):
        return None
    if soundfile is None:
        try:
            soundfile = _import_soundfile()
        except Exception:
            return (... a message explaining decoding is unavailable ...)
    if torch is None:
        try:
            import torch as _torch
        except Exception:
            return None
        torch = _torch

    def load(*args, **kwargs):
        return _soundfile_load(soundfile, torch, *args, **kwargs)

    def save(*args, **kwargs):
        return _soundfile_save(soundfile, torch, *args, **kwargs)

    torchaudio.load = load
    torchaudio.save = save
    torchaudio._aivs_soundfile_io = True
    return ("Audio files are read with the bundled soundfile library: this "
            "computer has no FFmpeg, which the TorchCodec decoder torchaudio "
            "normally uses needs. WAV, FLAC, OGG and MP3 work; formats only "
            "FFmpeg can decode (for example m4a/AAC) do not.")

Explain Line by Line Code Description (Block 4)

  1. Lines 1–4: the opt-out switch
    AIVS_VOICELAB_NO_AUDIO_SHIM=0 disables the swap. An escape hatch for a machine where the measurement is wrong is what keeps a clever workaround from becoming an unfixable bug: a user (or the developer) can always get the original behaviour back without editing code.
  2. Lines 5–10: getting hold of torchaudio
    The module can be passed in (tests do that) or imported. If it cannot be imported at all there is nothing to shim — an engine that needs torchaudio will fail on its own import with a clearer message than anything this function could invent.
  3. Lines 11–12: idempotence
    The marker attribute on the module itself means a second call does nothing. Without it, the shim would wrap the shim: load would call soundfile through a function that calls soundfile, and a future un-shim would be impossible.
  4. Lines 13–14: the decision
    The single most important line pair in the module: if the real decoder works, do nothing. This is what keeps the wider format support (and the platform’s own codecs) for users who have FFmpeg.
  5. Lines 15–22: the fallback library
    If soundfile is missing too, the function returns a message rather than raising: the engine will then either fail with its own error or succeed some other way, and the message explains the situation in the log either way.
  6. Lines 24–33: the swap
    Two closures bound to the already-imported libraries, assigned onto the module object. Assigning module attributes (rather than wrapping the module in a proxy) means every engine that already did import torchaudio and calls torchaudio.load(...) picks up the replacement with no cooperation at all.
  7. The returned note
    The text is not a warning to be discarded — it travels back to the application with the synthesis response, where VoicelabEngine._report_notes logs it. A user who later wonders why an .m4a reference failed has the answer in the log next to the run that failed.

79.5 Reference Clips in Other Formats

Voice cloning feeds a reference recording to the engine. F5-TTS cleans its reference with pydub, which shells out to FFmpeg for anything that is not a WAV. An MP3 reference therefore died with [WinError 2] The system cannot find the file specified — even though the Voice Clone page advertises MP3, FLAC and OGG.

_WAV_SUFFIXES = (".wav", ".wave")


def _convert_to_wav(path, soundfile=None):
    try:
        sf = soundfile if soundfile is not None else _import_soundfile()
        size = os.path.getsize(path)
        stamp = int(os.path.getmtime(path))
        key = f"{path}|{size}|{stamp}".encode("utf-8", "replace")
        digest = hashlib.md5(key).hexdigest()[:12]
        destination = os.path.join(
            tempfile.gettempdir(), f"aivs_reference_{digest}.wav")
        if os.path.isfile(destination) and os.path.getsize(destination) > 0:
            return destination
        data, sample_rate = sf.read(str(path), dtype="float32", always_2d=True)
        sf.write(destination, data, int(sample_rate))
        return destination
    except Exception:
        return path

Explain Line by Line Code Description (Block 5)

  1. Line 1: _WAV_SUFFIXES
    The formats the engines’ own pre-processing can already read. Anything else is converted before the engine sees it.
  2. Lines 3–6: the cache key
    Path + size + modification time, hashed to a short digest. Including size and mtime means the key changes when the file changes, so the converted copy can never be stale — the classic trap with a name-only cache. errors="replace" on encode keeps a path with unusual characters from raising.
  3. Lines 7–11: the destination
    A deterministic name in the temp folder, derived from the source. Deterministic means a second preview of the same voice reuses the converted file instead of converting again — which matters because converting is slower than reading.
  4. Lines 12–13: the reuse check
    os.path.isfile(...) and os.path.getsize(...) > 0 rejects a zero-byte leftover from an interrupted write. Trusting existence alone would hand the engine an empty file and produce a mystifying error much later.
  5. Lines 14–16: the conversion
    Read as float32 and write as WAV with the same sample rate: no resampling, no normalisation, no quality loss beyond the original decode. The engine receives exactly the audio the user chose.
  6. Lines 17–19: the honest fallback
    On any failure the original path is returned. Leaving the file untouched lets the engine either handle it itself or report precisely what it cannot read — which is far more useful to the user than a silent swap to a file that may not be equivalent.
Why not just install FFmpeg? Because an application that requires a system-wide binary for its core feature is an application that fails on locked-down machines, and because the reference-clip path only needs a decoder — which the bundled soundfile wheel already is.

79.6 Mini Project: Prove the Fix on Your Machine

Run this in an engine’s own environment (replace the path with your tts_envs folder) to see the difference the shim makes:

import os, tempfile, wave, struct

import torchaudio

from ai_voice_studio.voicelab.worker import _install_audio_io_shim

path = os.path.join(tempfile.gettempdir(), "probe.wav")
with wave.open(path, "wb") as handle:
    handle.setnchannels(1)
    handle.setsampwidth(2)
    handle.setframerate(16000)
    handle.writeframes(struct.pack("<1600h", *([0] * 1600)))

try:
    audio, rate = torchaudio.load(path)
    print("before shim: OK", audio.shape, rate)
except Exception as exc:
    print("before shim: FAILED", type(exc).__name__)

note = _install_audio_io_shim()
print("note:", note)

audio, rate = torchaudio.load(path)
print("after shim : OK", audio.shape, rate)

On a machine with FFmpeg the note is None and both loads succeed; on a machine without it the first load raises and the second returns a tensor.

  1. Why does the shim live in the worker rather than in the application process? Answer in terms of process boundaries and dependencies.
  2. Add (in a scratch copy) a _soundfile_load that ignores channels_first. Which engine would break first, and how would the symptom look — an exception, silence, or garbage audio?
  3. Time a preview with an MP3 reference twice. Explain what the second run saves and why the cache key must include the file’s mtime.
  4. Convert an .m4a file with the current code and explain the result from the note’s text rather than from an error message.

79.7 Key Takeaways

  • Library behaviour changes across versions: torchaudio now delegates decoding to TorchCodec
  • Detect capability by trying the operation on a real input, then fall back only if it truly fails
  • Write shims with the full signature of the API they replace, and assign them onto the module object
  • Make workarounds idempotent and switchable with an environment variable
  • Convert user media once, with a cache key derived from path, size and mtime
  • Never silently change what the user gave you — if you cannot process it, return it untouched
  • Send notes back to the application and log them: a degraded path that works should still be explainable
