Chapter 48

TTS Engine Integration

Current implementation (2026.3.1). The sherpa-onnx wrapper described here is still the engine for the ONNX and built-in voices, and it now sits behind two more layers:
  • tts/engine.py is reached through tts/models.py, which resolves a voice entry — including the pip-installed Voice Lab engines' built-in and cloned voices — and hands sherpa-onnx the right model files.
  • voicelab.VoicelabEngine implements the same synthesize() contract by talking to a worker subprocess running on that engine's own interpreter, so PyTorch and CUDA never load in the application process (see Chapter 76).
  • Reference audio for cloning is decoded without FFmpeg when TorchCodec cannot load (Chapter 79), and the engine cache key includes the provider, so a compute change rebuilds the engine.

Learning Objectives

  • Understand how multiple TTS engines are unified under one interface
  • See the engine factory pattern in action
  • Understand pitch, volume, and speed post-processing

48.3 Post-Processing Pipeline

# After synthesis, audio goes through post-processing:
def synthesize(self, text, sid=0, speed=1.0, pitch=1.0, volume=1.0):
    # 1. Core synthesis (sherpa-onnx / subprocess)
    audio = self._tts.generate(text=text, sid=sid, speed=speed)
    samples = np.array(audio.samples, dtype=np.int16)

    # 2. Pitch adjustment
    if pitch != 1.0:
        samples = _shift_pitch(samples, pitch)

    # 3. Volume adjustment
    if volume != 1.0:
        samples = _apply_volume(samples, volume)

    return samples

# Pitch shifting via resampling
def _shift_pitch(samples, pitch):
    new_length = int(len(samples) / pitch)
    indices = np.linspace(0, len(samples) - 1, new_length)
    shifted = np.interp(indices, np.arange(len(samples)),
                        samples.astype(np.float64))
    return shifted.astype(np.int16)

# Volume scaling with clipping
def _apply_volume(samples, volume):
    scaled = samples.astype(np.float64) * volume
    return np.clip(scaled, -32768, 32767).astype(np.int16)

48.4 Key Takeaways

  • All engines implement the same interface (synthesize → int16 numpy array)
  • The factory pattern selects the engine based on voice_entry["engine"]
  • Heavy engines (XTTS, OmniVoice) run in subprocesses
  • Post-processing (pitch, volume) happens after synthesis, before saving
  • Engine instances are cached to avoid reloading models
