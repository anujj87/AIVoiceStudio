Chapter 81

A First-Launch Terms Dialog That Cannot Be Bypassed

Learning Objectives

  • Gate application start-up behind a modal dialog in a way that survives every exit path
  • Remember acceptance per application version, so updates re-prompt and daily use does not
  • Gate buttons on a group of checkboxes, and let one master checkbox drive the rest
  • Handle the wx traps: Escape, the close box, Alt+F4, and modal vs non-modal code paths
  • Test a modal dialog without a user, and why “shown non-modally” matters

81.1 The Requirement, Stated Precisely

The application synthesises speech from arbitrary documents and clones voices. The requirement was a first-launch dialog with six acknowledgements that:

  1. must be all ticked to proceed;
  2. enables its I Agree and Disagree (Close Program) buttons only once every box is ticked;
  3. must not let the user through by refusing, by Escape, or by forcibly closing the dialog;
  4. must never appear again after agreement — until the next update or a fresh install.

Requirement 4 is the subtle one: “once per version, forever” is a completely different store from “once per installation”.

81.2 Versioned Acceptance in Settings

APP_VERSION = "2026.3.1"

# Version of the first-launch terms/acceptance dialog. Bump this on every
# release so the dialog shows again after an update.
TERMS_VERSION = "2026.3.1"


def terms_current(settings) -> bool:
    return settings.get("terms_version", "") == TERMS_VERSION


def record_acceptance(settings) -> None:
    settings.set("terms_version", TERMS_VERSION)
    settings.save()

Explain Line by Line Code Description (Block 1)

  1. Lines 1–5: two version constants, on purpose
    The application version and the terms version can move independently: a bug-fix release may ship without changing the legal text, a podgy release may change only the terms. Keeping them separate means changing the wording is one line, and no one has to reason about which releases “count”.
  2. Lines 8–10: terms_current
    A pure comparison against a settings value, with an empty-default for the first run. It returns False for anything that is not an exact match — including a settings file from an older version and a corrupt value. That default is what makes an update prompt again without any migration code.
  3. Lines 13–15: record_acceptance
    Writes and saves immediately. Deferring the save to a later “save settings on exit” would lose the acceptance in exactly the case that matters — the user accepts and then the application crashes for an unrelated reason.
Uninstalling does not delete user data. Settings live in %APPDATA%\AIVoiceStudio, which the uninstaller deliberately leaves alone (it contains the user’s projects). So a reinstall that ships the same terms version will not re-prompt. That is why the version must be bumped — it is the only mechanism that re-prompts an existing user.

81.3 The Dialog, Control by Control

class AcceptanceDialog(wx.Dialog):
    def __init__(self, parent=None):
        super().__init__(
            parent,
            title="Welcome to AI Voice Studio - Terms of Use",
            style=wx.DEFAULT_DIALOG_STYLE & ~wx.CLOSE_BOX,
        )
        self._accepted = False

        panel = wx.Panel(self)
        sizer = wx.BoxSizer(wx.VERTICAL)

        intro = wx.StaticText(panel, label=(
            "Welcome to AI Voice Studio.\n\n"
            "Please read each point below carefully. You must accept "
            "all of them to use this application."))
        intro.Wrap(560)
        sizer.Add(intro, 0, wx.ALL, 10)

Explain Line by Line Code Description (Block 2)

  1. Lines 3–8: the style expression
    wx.DEFAULT_DIALOG_STYLE & ~wx.CLOSE_BOX clears the close-box bit from a set of style flags. This removes the title-bar × button on platforms where the close box is part of that style — removing the obvious way to dismiss the dialog without deciding. It is a hint, not a guarantee, which is why the close event is also handled (81.5).
  2. Line 9: self._accepted = False
    State is initialised to the safe value. If any code path forgets to set it, the result is “not accepted”, and the application does not start — the failure mode leans in the safe direction.
  3. Lines 11–12: panel and vertical sizer
    A wx.Panel gives the contents a proper background and correct tab order; the vertical sizer stacks the terms and lets Fit size the dialog around them.
  4. Lines 14–19: the introduction
    Short, and it says what is required (“You must accept all of them”). A user who reads one line before ticking boxes should learn from it what the buttons will do.
  5. Line 20: intro.Wrap(560)
    A fixed wrap width keeps the dialog’s shape stable regardless of the platform’s font and DPI. Without it, the dialog is as wide as the longest sentence — which on a 100 % or 150 % DPI machine is off-screen.
        self._checkboxes = []
        for index, text in enumerate(_TERMS, start=1):
            wrapped = "\n".join(textwrap.wrap(text, width=90))
            box = wx.CheckBox(panel, label=f"{index}.  {wrapped}")
            box.Bind(wx.EVT_CHECKBOX, self._on_toggle)
            self._checkboxes.append(box)
            sizer.Add(box, 0, wx.LEFT | wx.RIGHT | wx.BOTTOM, 10)

        self._agree_all = wx.CheckBox(panel, label=_AGREE_ALL_LABEL)
        self._agree_all.SetFont(self._agree_all.GetFont().Bold())
        self._agree_all.Bind(wx.EVT_CHECKBOX, self._on_agree_all)
        self._checkboxes.append(self._agree_all)
        sizer.Add(self._agree_all, 0, wx.LEFT | wx.RIGHT | wx.TOP, 10)

Explain Line by Line Code Description (Block 3)

  1. Line 1: one list holds every checkbox
    The term checkboxes and the agree-all one live in self._checkboxes. That single collection is what makes “is everything ticked?” a one-line expression — and it is also the reason the property below has to exist.
  2. Line 3: textwrap.wrap(text, width=90)
    The terms are long sentences. wxPython’s wx.CheckBox has no Wrap() method (unlike StaticText), so a long label is simply cut off or produces an absurdly wide dialog. Wrapping the string before creating the control — and joining the lines with \n — is the portable way to get a multi-line checkbox. The newline also preserves the full text for a screen reader.
  3. Line 4: the numbered label
    “1.” through “6.” lets a screen-reader user say “I disagree with point 3” instead of reading the sentence aloud. The two spaces after the number keep the text visually aligned.
  4. Line 5: binding the handler
    Every box gets _on_toggle, including the master one bound separately below, so any change updates the button state immediately. Re-using one handler is what keeps the gating logic in a single place.
  5. Lines 9–12: the master checkbox
    Bold, because it means “all of the above”, and appended into the same list so that “all ticked” includes it. The requirement was explicit that the agree-all box itself is required — it is a shortcut for the other six, not a replacement for them.
        btn_row = wx.BoxSizer(wx.HORIZONTAL)
        self._agree_btn = wx.Button(panel, wx.ID_OK, _AGREE_LABEL)
        self._disagree_btn = wx.Button(panel, wx.ID_CANCEL, _DISAGREE_LABEL)
        self._agree_btn.Bind(wx.EVT_BUTTON, self._on_agree)
        self._disagree_btn.Bind(wx.EVT_BUTTON, self._on_disagree)
        btn_row.Add(self._disagree_btn, 0, wx.RIGHT, 8)
        btn_row.Add(self._agree_btn, 0, wx.LEFT, 8)
        sizer.Add(btn_row, 0, wx.ALIGN_CENTRE | wx.ALL, 12)

        panel.SetSizer(sizer)
        sizer.Fit(self)
        self.CentreOnScreen()

        self.Bind(wx.EVT_CHAR_HOOK, self._on_char_hook)
        self.Bind(wx.EVT_CLOSE, self._on_close)
        self._on_toggle(None)

Explain Line by Line Code Description (Block 4)

  1. Lines 2–3: explicit ids, explicit labels
    wx.ID_OK and wx.ID_CANCEL are used for the standard “modal result” plumbing, while the visible text says exactly what each button does. Disagree (Close Program) tells the user the consequence before they press it — the honest alternative to “Cancel”.
  2. Line 8: wx.ALIGN_CENTRE
    (Native wx spelling.) Centring the two buttons gives the dialog a stable, symmetric shape that does not shift when one of them is disabled.
  3. Line 11: sizer.Fit(self)
    Sizes the dialog around its contents once, rather than hard-coding a pixel size. Text metrics differ between platforms and DPI settings; fitting is the only thing that behaves the same everywhere.
  4. Line 12: self.CentreOnScreen()
    On a multi-monitor setup a centred-on-parent dialog may open on a screen the user is not looking at. “On screen” (with no parent, since this dialog has none) is the right choice for a dialog that appears before the main window exists.
  5. Lines 14–15: the two escape hatches
    EVT_CHAR_HOOK sees keystrokes before any child control, which is what makes an Escape handler reliable even when focus is inside a checkbox; EVT_CLOSE catches the window-close path. Both are handled in 81.5.
  6. Line 16: the initial gating
    Calling the handler once at the end applies the rule to the freshly built state. Without it the buttons would be enabled until something is clicked — an inconsistency the user can see.

81.4 Gating, and a Master Checkbox

    @property
    def _term_checkboxes(self):
        """Every checkbox except the final "agree with all" one."""
        return self._checkboxes[:-1]

    def _on_agree_all(self, event) -> None:
        value = self._agree_all.GetValue()
        for box in self._term_checkboxes:
            box.SetValue(value)
        self._on_toggle(None)

    def _all_checked(self) -> bool:
        return all(box.GetValue() for box in self._checkboxes)

    def _on_toggle(self, event) -> None:
        ready = self._all_checked()
        self._agree_btn.Enable(ready)
        self._disagree_btn.Enable(ready)

Explain Line by Line Code Description (Block 5)

  1. Lines 2–4: the slicing property
    A name for “everything except the last one”, instead of [:-1] scattered through the class. If a future release adds a seventh term, only this property changes — the master checkbox still drives exactly the term list.
  2. Lines 6–9: the master handler
    Reads the master box’s own value and copies it to every term box. Copying (rather than toggling) makes the operation idempotent: clicking the master twice leaves all boxes consistent, which is what a user expects and what makes the behaviour easy to test.
  3. Line 10: re-evaluating afterwards
    _on_toggle(None) is called directly. Programmatic changes (SetValue) do not fire EVT_CHECKBOX, so without this call the buttons would stay disabled after the user ticked the master box — a real bug caught while testing this class.
  4. Lines 12–13: the single source of truth
    all(...) over the whole list, including the master box. One expression answers the only question that matters, so “all of them, plus the agree-all one” cannot drift between code paths.
  5. Lines 15–18: the gating itself
    Both buttons are enabled together. That is deliberate: the user should be able to make a decision either way once they have read the terms, and disabling only one of them would make “Disagree” unreachable and look like a trap.
  6. The parameter is event, and it is unused
    The handler is called both by events and directly with None, so the signature must accept the event object. A comment or a default value would do; passing None is the simplest convention and is used consistently here.

81.5 Every Exit Path Leads to “Not Accepted”

    def _on_agree(self, event) -> None:
        if not self._all_checked():
            return
        self._accepted = True
        self._finish(wx.ID_OK)

    def _on_disagree(self, event) -> None:
        self._accepted = False
        self._finish(wx.ID_NO)

    def _finish(self, code: int) -> None:
        if self.IsModal():
            self.EndModal(code)
        else:
            self.Close()

    def _on_char_hook(self, event) -> None:
        if event.GetKeyCode() == wx.WXK_ESCAPE:
            return
        event.Skip()

    def _on_close(self, event) -> None:
        if not self._accepted:
            self._accepted = False
            if self.IsModal():
                self.EndModal(wx.ID_NO)
            else:
                event.Skip()
            return
        event.Skip()

Explain Line by Line Code Description (Block 6)

  1. Lines 2–3: the re-check
    The button is disabled when the conditions are not met, but the handler checks anyway. UI state and logic state are different things — a disabled button can still be activated by an accelerator, a test, or a stray programmatic ProcessEvent. The check costs one line and removes that class of accident.
  2. Lines 7–9: disagreement
    wx.ID_NO (not ID_CANCEL) is returned, so the caller can distinguish “the user said no” from “something else closed this”. Callers that only care whether it is OK are unaffected.
  3. Lines 11–15: _finish, the modal/non-modal split
    The important detail: EndModal on a dialog that was shown with Show() raises an assertion, and tests show dialogs non-modally. Asking IsModal() makes one code path serve the application (modal) and the tests (non-modal) without a test-only hook.
  4. Lines 17–20: the Escape hook
    Escape is swallowed — the handler returns without calling event.Skip(), so no further handler ever sees the key. Swallowing is the correct response here: refusing the terms is a decision, and it should require pressing the button that says what it does. Every other key is forwarded with event.Skip() so normal navigation, Tab and Space keep working.
  5. Lines 22–29: the close handler
    Reaching this method without acceptance means the user closed the window (title-bar ×, Alt+F4, a window manager command). The dialog then ends with ID_NO — closing is treated as disagreement, which is exactly the requirement that force-closing must not launch the application.
  6. Line 30: the accepted path
    If the user already accepted, the close event is passed along normally (event.Skip()) so the window closes without a second result being reported.

81.6 Wiring It Into Start-Up

def _require_terms_acceptance(settings: Settings) -> bool:
    if terms_current(settings):
        return True
    log = logging.getLogger("main")
    log.info("Showing first-launch terms acceptance dialog")
    app = wx.App(False)
    dialog = AcceptanceDialog(None)
    try:
        accepted = dialog.ShowModal() == wx.ID_OK and dialog.accepted
    finally:
        dialog.Destroy()
    if accepted:
        record_acceptance(settings)
        log.info("Terms accepted (version %s)", settings.get("terms_version"))
    else:
        log.info("Terms not accepted - application will not start")
    return accepted


def main() -> int:
    settings = Settings()
    developer_mode = settings.get("developer_mode", False)
    _setup_logging(developer_mode)

    log = logging.getLogger("main")
    log.info("AI Voice Studio starting (Python %s)", sys.version.split()[0])

    if not _require_terms_acceptance(settings):
        return 0

    _init_python_runtime()
    _init_addons()
    _warm_package_cache()

    app = wx.App(False)
    store = ModelStore()
    frame = MainFrame(None, settings, store)
    apply_theme(frame, settings.theme)
    frame.Show()
    return app.MainLoop() or 0

Explain Line by Line Code Description (Block 7)

  1. Lines 2–3: the fast path
    An accepted user pays one settings read. Nothing is imported and no window is created, which is what keeps the dialog from slowing down every launch for the rest of the version’s life.
  2. Lines 5–7: a wx.App for the dialog
    wxPython needs an application object with a message loop before any window can be created. Creating it here — and letting the local reference go when the function returns — means the main window’s own wx.App in main() can be created afterwards without conflict (verified: a second wx.App(False) succeeds once the first is released).
  3. Line 8: reading both the result and the flag
    ShowModal() == wx.ID_OK and dialog.accepted. Two independent conditions, which is the belt-and-braces version of a security-relevant check: a future refactor that returns ID_OK from the wrong place still cannot let the application start.
  4. Lines 9–10: try/finally with Destroy()
    Standard wx hygiene: the native window is released on every path, including an exception raised while showing the dialog.
  5. Lines 11–15: recording the outcome either way
    Both branches log. The acceptance line includes the version that was accepted, which is the single most useful line when a user later asks “why did the dialog come back?”. The decline line makes a support question (“it closes immediately”) answerable from the log.
  6. Lines 22–23: before any subsystem
    This position is deliberate. The check runs after logging is configured (so the dialog can be logged) and before the runtime, addons and package probes (so nothing expensive or network-touching happens for a user who has not accepted).
  7. Line 25: the early return
    Returning 0 from main() means a clean exit code for “the user chose not to continue” — not an error. An installer or launcher that checks the exit code then does not report a failure.
A real bug this wiring produced once: an early version logged from a helper that assumed the module-level log object, which did not exist at that point in start-up — the frozen build died instantly with NameError. The fix was to obtain the logger locally (logging.getLogger("main")) in the function, and the lesson is general: code that runs before initialisation completes may only rely on what it obtained itself. A frozen smoke test that launches the packaged executable with an isolated data folder is what catches this class of bug.

Note how the tests call the handlers directly rather than simulating clicks. Because the handlers take an event they never use, handler(None) works — a small design decision that makes a whole class of dialog testable without a robot.

81.8 Mini Project: A Settings-Backed One-Time Prompt

The same pattern, minus wx, for anything you build yourself:

import json, os

PROMPT_VERSION = "3"
PATH = os.path.join(os.path.expanduser("~"), ".my_tool_state.json")


def load_state():
    try:
        with open(PATH, encoding="utf-8") as handle:
            return json.load(handle)
    except (OSError, ValueError):
        return {}


def save_state(state):
    with open(PATH, "w", encoding="utf-8") as handle:
        json.dump(state, handle, indent=2)


def needs_prompt():
    return load_state().get("accepted_version") != PROMPT_VERSION


def mark_accepted():
    state = load_state()
    state["accepted_version"] = PROMPT_VERSION
    save_state(state)

Bump PROMPT_VERSION when the text changes; a new installation (no state file) prompts automatically because the missing key never equals the version.

81.9 Key Takeaways

  • Gate on a versioned acceptance value, not on a boolean, if future updates must re-prompt
  • Set the safe default first and check twice at the boundary: style tricks and disabled buttons are hints, not guarantees
  • Handle Escape with EVT_CHAR_HOOK and the close box with EVT_CLOSE; both must lead to “not accepted”
  • Programmatic SetValue fires no events — call the state handler yourself
  • Branch on IsModal() so one implementation serves the application and the tests
  • Run the prompt before any subsystem initialisation, and log both outcomes with the version
  • Uninstallers leave user data behind: the version bump is the only reliable re-prompt
