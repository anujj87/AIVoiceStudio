Chapter 35

Theming & Styling

Learning Objectives

  • Implement Light/Dark/System theme support
  • Apply colors to wxPython widgets
  • See the AIVS theme manager
  • Extend a palette into many predefined themes with one code path
  • Let users build and save their own themes, and paint a wallpaper into the window's empty area only

35.1 Theme Manager in AIVS

# From gui/theme.py
_LIGHT = {"bg": "#ffffff", "fg": "#1a1a1a",
          "control_bg": "#ffffff", "control_fg": "#1a1a1a"}
_DARK = {"bg": "#1e1e1e", "fg": "#e8e8e8",
         "control_bg": "#2d2d2d", "control_fg": "#e8e8e8"}

_state = {"theme": THEME_SYSTEM, "colors": _LIGHT}
_lock = threading.Lock()

def apply_theme(top: wx.Window, theme: str) -> None:
    """Apply theme to window and all descendants."""
    resolved = _resolve(theme)
    colors = _DARK if resolved == THEME_DARK else _LIGHT
    with _lock:
        _state["theme"] = theme
        _state["colors"] = colors
    _paint(top, colors)
    for child in _descendants(top):
        _paint(child, colors)
    top.Refresh()

def _resolve(theme: str) -> str:
    """Resolve 'system' to light or dark based on OS."""
    if theme == THEME_SYSTEM:
        try:
            appearance = wx.SystemSettings.GetAppearance()
            return THEME_DARK if appearance.IsDark() else THEME_LIGHT
        except Exception:
            return THEME_LIGHT
    return theme

35.2 Applying Colors to Widgets

def _paint(window: wx.Window, colors: dict) -> None:
    try:
        # Containers get background color
        if isinstance(window, (wx.Panel, wx.Dialog, wx.Frame, wx.ScrolledWindow)):
            window.SetBackgroundColour(colors["bg"])

        # Text labels get foreground color
        elif isinstance(window, (wx.StaticText, wx.CheckBox, wx.RadioButton)):
            window.SetForegroundColour(colors["fg"])

        # Input controls get both
        elif isinstance(window, (wx.TextCtrl, wx.ComboBox, wx.ListBox)):
            window.SetBackgroundColour(colors["control_bg"])
            window.SetForegroundColour(colors["control_fg"])
    except Exception:
        pass  # Some widgets don't support color changes

35.3 Current implementation: many themes from one palette

The block in 35.1 shows the original three-theme manager. The current gui/theme.py keeps that behaviour and treats light, dark and system as three palettes among many, so the same apply_theme() walk paints every theme without a second code path.

# gui/theme.py - the original two palettes stay frozen ...
_LIGHT = {"bg": "#ffffff", "fg": "#1a1a1a", ...}
_DARK = {"bg": "#1e1e1e", "fg": "#e8e8e8", ...}

# ... and ten predefined dark themes are built the same way.
THEME_PRESETS = (
    _preset("graphite_midnight", "Midnight Graphite",
            "#16181c", "#e6e9ef", "#22262d", "#e6e9ef",
            "#8ab4f8", "#ffffff", "gradient_v", "..."),
    # Obsidian Gold, Deep Navy, Forest Pine, Plum Royale, Crimson
    # Slate, Ocean Teal, Amber Dusk, Carbon Lime, Blue Steel
)

def resolve_palette(theme, settings=None) -> Dict[str, str]:
    """The palette a theme id resolves to (built-in, preset or custom)."""
    if theme == THEME_SYSTEM:
        theme = _resolve(theme)
    if theme == THEME_DARK:
        return dict(_DARK)
    if theme == THEME_LIGHT:
        return dict(_LIGHT)
    preset = _PRESET_BY_ID.get(theme)
    if preset is not None:
        return dict(preset.colors)
    record = get_custom_theme(settings, theme)
    if record is not None:
        return palette_from_record(record)
    return dict(_DARK)  # unknown ids stay legible

def apply_theme(top: wx.Window, theme: str, settings=None) -> None:
    colors = resolve_palette(theme, settings)
    # ... the same tree walk as 35.1, with `colors` ...

Three ideas carry the whole feature:

  • A palette is a dict, so a preset is just data. Adding a theme means adding a _preset(...) row, not new rendering code.
  • The four original keys are enough to paint the widgets (bg, fg, control_bg, control_fg); presets add accent and heading for the wallpaper and the welcome title.
  • Custom themes are records in the settings (custom_themes), so a user can create any number of them and they travel with the rest of the configuration.

35.4 Painting a wallpaper into the empty area

A wallpaper must not sit under the things the user clicks. The first cut painted the whole welcome screen and let the buttons draw on top of it, which put the pattern under the action bar and the recent projects list. The screen is therefore built as three sibling regions: a full-width action bar carrying the four main buttons, a left projects sidebar holding the recent-projects list behind a one-pixel _DividerPanel rule, and a _WallpaperPanel that takes everything left over. A panel holds no controls — only the descriptive paragraph, which the wallpaper hides — so nothing can ever be painted on top of it.

# _WallpaperPanel: the empty region of the welcome screen
class _WallpaperPanel(wx.Panel):
    def __init__(self, parent, settings):
        super().__init__(parent)
        self.settings = settings
        self.SetBackgroundStyle(wx.BG_STYLE_PAINT)  # no flicker
        self.Bind(wx.EVT_PAINT, self._on_paint)

    def _on_paint(self, _evt):
        dc = wx.AutoBufferedPaintDC(self)
        theme = current_theme()
        colors = resolve_palette(theme, self.settings)
        record = get_wallpaper(self.settings, theme)
        if record["enabled"]:
            paint_background(dc, self.GetClientSize(), colors,
                             theme_pattern(theme, self.settings),
                             record["image"])
        else:
            paint_background(dc, self.GetClientSize(),
                             colors, "solid", "")

The sizer that assembles the screen is what guarantees the separation: the action bar is added with wx.EXPAND at proportion 0 (full width, buttons' height plus _ACTION_BAR_PAD above and below), the sidebar and divider at proportion 0, and the wallpaper panel at proportion 1 so it absorbs the rest. _apply_welcome_mode() then hides the description and the sidebar hint whenever a wallpaper is on, leaving the button labels and the project list untouched.

paint_background() offers ten styles — solid, vertical and horizontal gradients, diagonal, vignette, grid, dots, stripes, a corner glow and waves — and falls back to the solid colour if an image cannot be loaded. The theme studio dialog uses the same call for its live preview, painted on a small panel instead. Both the action bar and the sidebar keep the theme's plain background: they are ordinary panels, so the existing _paint() tree walk colours them, and the divider blends the background with the theme's heading colour so the rule stays visible on every theme.

35.5 Key Takeaways

  • Many themes: System, Light, Dark, ten predefined dark themes, and any number of custom ones
  • wx.SystemSettings.GetAppearance() detects dark mode on Windows 10/11
  • Colors are applied by walking the widget tree and setting background/foreground
  • Buttons keep native look — only panels, text, and inputs are themed
  • Theme state is stored in a thread-safe dict with locking
  • A theme is data, not code; a wallpaper gets a panel of its own, so it can never paint behind a control
