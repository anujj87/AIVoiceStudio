Chapter 74

DAISY 3 Builder (Z39.86-2005)

Learning Objectives

  • Understand the DAISY 3 fileset: DTBook text, NCX navigation, SMIL synchronization
  • Generate a conforming DTBook 2005-3 document with frontmatter and images
  • Synchronize audio to text at phrase level using proportional time slicing
  • Embed source-document images as imggroup elements and OPF manifest entries

74.1 What DAISY 3 Adds Over DAISY 2.02

DAISY 2.02 stores its text in small HTML files; DAISY 3 (the Z39.86-2005 standard) replaces that with one DTBook XML document for the whole book, an NCX navigation file, and SMIL 2.0 documents that bind every paragraph to its place in the audio. The builder in documents/daisy3_builder.py (added after this book's first edition) produces a complete fileset in <project>/DAISY3/:

book.xml       -- DTBook 2005-3 text content (frontmatter, body, rearmatter)
ncx.xml        -- NCX navigation (navMap built from the heading hierarchy)
package.opf    -- OPF package manifest tying everything together
0001.smil ...  -- one SMIL 2.0 document per recorded segment
aud0001.wav .. -- recorded audio renamed to digit-only names

Explain Line by Line Code Description (Block 1)

  1. Line 1: book.xml -- DTBook 2005-3 text content
    The whole book's text in a single DTBook document: mandatory frontmatter (title, author), the bodymatter with all chapters, and a rearmatter. DAISY 3 players open this file's companion package and render the text while highlighting the spoken paragraph.
  2. Line 2: ncx.xml -- NCX navigation
    The navigation control file. Its navMap mirrors the document's heading hierarchy, so a reader can jump chapter by chapter (or heading by heading) exactly as in the printed book's table of contents.
  3. Line 3: package.opf -- OPF package manifest
    The entry point a DAISY 3 player opens first. It lists every file in the book with its MIME type and links the DTBook, NCX, SMILs and audio together.
  4. Line 4: 0001.smil ... -- one SMIL per segment
    Each recorded segment gets one SMIL 2.0 document containing a <par> per paragraph: the text reference and the <audio> element with exact clip begin/end times.
  5. Line 5: aud0001.wav -- digit-only names
    Recorded audio is copied under zero-padded digit-only names. Segment titles can contain any characters; players only ever see aud0001.wav, aud0002.mp3, which keeps every URI in the book trivially safe.

74.2 The Entry Point: build_daisy3_book()

def build_daisy3_book(
    output_dir: str,
    project_name: str,
    segments: List[Dict[str, Any]],
    audio_format: str = "wav",
    language: str = "en",
    publisher: str = "",
    source_file: str = "",
    author: str = "",
    meta: Optional[Dict[str, str]] = None,
) -> str:
    ready = [s for s in segments if s.get("status") == "done" and s.get("saved")]
    if not ready:
        return ""

    daisy_dir = os.path.join(output_dir, DAISY3_OUTPUT_DIR_NAME)
    os.makedirs(daisy_dir, exist_ok=True)

    book_uid = "urn:uuid:" + str(uuid.uuid4())
    now_iso = datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")

Explain Line by Line Code Description (Block 2)

  1. Lines 1–10: the signature
    The parameters deliberately mirror build_daisy_book() from the DAISY 2.02 builder, so the recording dialog can call either one with the same argument list. output_dir is the project folder, segments the fresh segment list from project.json, and meta the book information entered in the wizard (title, creator, date, subject, narrator, producer). The return value is the path of the generated package.opf — the file players open — or an empty string when there was nothing to build.
  2. Line 11: ready = [s for s in segments if s.get("status") == "done" and s.get("saved")]
    The same filter the playlist builder uses: only segments that were fully recorded (status done with a saved file) become part of the book. A partially recorded project produces a book covering exactly the audio that exists.
  3. Line 12: if not ready: return ""
    No recorded audio means no book: the function returns an empty string and the caller skips its "book generated" message.
  4. Lines 14–15: daisy_dir = os.path.join(output_dir, DAISY3_OUTPUT_DIR_NAME) / os.makedirs(daisy_dir, exist_ok=True)
    Creates the DAISY3 folder inside the project folder. exist_ok=True makes the call idempotent — rebuilding the book after re-recording a segment simply reuses the existing folder.
  5. Line 17: book_uid = "urn:uuid:" + str(uuid.uuid4())
    Generates a fresh unique identifier for the book. DAISY metadata requires a dc:Identifier in URN form; a random UUID guarantees two exports of different books never collide in a player's library.
  6. Line 18: now_iso = datetime.now(timezone.utc).strftime(...)
    Timestamps the build in UTC with the ISO-8601 format (%Y-%m-%dT%H:%M:%SZ) that DAISY metadata fields demand. UTC avoids ambiguous local-time offsets in the book metadata.
MP3 normalization on staging: while copying each recorded segment into the book as aud0001.wav and friends, the builder calls the same _stage_audio helper as the DAISY 2.02 builder. An MP3 saved by a TTS engine is often MPEG-2 LSF at 22–24 kHz, which several DAISY players truncate ("audio cuts out"). If ffmpeg.needs_mp3_normalization() detects a rate below 44.1 kHz, the file is re-encoded to MPEG-1 Layer III, 44.1 kHz mono before entering the book. See Chapter 59.

74.3 Building the DTBook

The DTBook writer emits the official public identifier and required structure:

_DTBOOK_DOCTYPE = (
    ''
)

Explain Line by Line Code Description (Block 3)

  1. Lines 1–3: _DTBOOK_DOCTYPE = ('<!DOCTYPE dtbook PUBLIC ...')
    The official Document Type Declaration for DTBook 2005-3. Strict DAISY 3 players (FSReader, EasyReader, AMIS) validate the document against this DTD; writing the exact formal public identifier and system URL means the book conforms rather than merely parses. The string is split across two literals that Python concatenates, keeping the source line short.

Every segment's text becomes a chapter with one phrase per paragraph:

def _entry_blocks(entry: Dict[str, Any], id_counter: List[int]) -> List[Dict[str, Any]]:
    blocks: List[Dict[str, Any]] = []

    def add(dtbook_id: str, text: str) -> None:
        id_counter[0] += 1
        blocks.append({"id": dtbook_id, "text": text})

    for para in entry["paragraphs"]:
        add(f"dtb{para['index']}", para["text"])
    return blocks

Explain Line by Line Code Description (Block 4)

  1. Line 1: def _entry_blocks(entry, id_counter):
    Converts one recorded segment into the DTBook paragraph records. entry holds the segment's text broken into paragraphs, and id_counter is a one-element list used as a mutable counter (a closure cannot rebind a plain int of the enclosing scope, but it can mutate a list).
  2. Lines 3–5: def add(dtbook_id, text): ... blocks.append(...)
    A local helper closing over blocks and id_counter. Each call bumps the shared counter and appends one record with a DTBook element id (dtb1, dtb2, …). These ids are what the SMIL files reference later, so they must be unique across the whole book.
  3. Lines 7–8: for para in entry["paragraphs"]: add(f"dtb{para['index']}", para["text"])
    One paragraph of the segment becomes one DTBook block, and one block later becomes one SMIL <par> — this 1:1 mapping is what gives the book phrase-level synchronization: while a paragraph is spoken, the player highlights exactly that paragraph's text.

74.4 Embedding Images

DAISY 3 is the first project type in AIVS that carries images. The builder extracts images from the source document and appends them as imggroup elements:

_IMAGE_EXT_MIME = {
    ".png": "image/png",
    ".jpg": "image/jpeg",
    ".jpeg": "image/jpeg",
    ".gif": "image/gif",
    ".svg": "image/svg+xml",
    ".webp": "image/webp",
    ".bmp": "image/bmp",
    ".tif": "image/tiff",
    ".tiff": "image/tiff",
}

_IMG_TAG_RE = re.compile(
    r"]*?\bsrc\s*=\s*[\"']([^\"']+)[\"']", re.IGNORECASE
)

Explain Line by Line Code Description (Block 5)

  1. Lines 1–11: _IMAGE_EXT_MIME = {...}
    Maps the image file extensions the builder understands to their official MIME types. The OPF manifest requires the correct MIME type for every resource, and the imggroup writer uses the same table when choosing the file extension for extracted media.
  2. Lines 13–14: _IMG_TAG_RE = re.compile(r"<img\b[^>]*?\bsrc\s*=\s*[\"']([^\"']+)[\"']", re.IGNORECASE)
    The regular expression that pulls image references out of HTML/EPUB content. Reading it piece by piece: <img\b matches the tag opening (\b prevents matching <imginput-style words); [^>]*? lazily skips any attributes before src; \bsrc\s*=\s* matches the src attribute with optional spaces around the equals sign; [\"']([^\"']+)[\"'] captures the value in either single or double quotes; and re.IGNORECASE accepts <IMG SRC=...> as produced by some exporters. Everything the parser finds here is downloaded/extracted into the book and referenced from the DTBook.

74.5 NCX Navigation and SMIL Synchronization

The NCX nests navPoints by heading level, and each SMIL binds text to audio with dtb: attributes that players require:

_SMIL_DOCTYPE = (
    ''
)

_SMIL_DTB_NS = "http://www.daisy.org/z3986/2005/dtbook/"

Explain Line by Line Code Description (Block 6)

  1. Lines 1–3: _SMIL_DOCTYPE = ('<!DOCTYPE smil PUBLIC ...')
    The official SMIL 2.0 DTD declaration for DAISY 3 content documents. Like the DTBook doctype it makes the fileset conformant, not just well-formed.
  2. Line 5: _SMIL_DTB_NS = "http://www.daisy.org/z3986/2005/dtbook/"
    The namespace URI bound to the dtb: prefix. DAISY 3 SMIL files carry required custom attributes in this namespace — dtb:requiredNamespace on the root, dtb:totalElapsed/dtb:timeInThisSmil for timings, and customTest on each <par> — without which strict players refuse to play the book.
Conformance detail learned the hard way: the <audio> element must sit directly inside each <par> — wrapping it in a <seq> (which SMIL itself allows) makes several real DAISY 3 players skip the audio entirely. The builder therefore writes <par><text .../><audio .../></par> and nothing between them.

Audio timing is phrase-level and proportional. For a segment whose audio lasts 60 seconds and whose three paragraphs have 100, 200 and 300 characters, the SMIL assigns 10 s, 20 s and 30 s clip windows respectively. The helper converting stored values:

def _total_ms(total_ms_value: Any) -> int:
    try:
        return max(0, int(float(total_ms_value)))
    except (TypeError, ValueError):
        return 0

Explain Line by Line Code Description (Block 7)

  1. Line 1: def _total_ms(total_ms_value):
    Coerces a duration value of unknown type (JSON may hand back an int, float, str or None) into a non-negative millisecond integer for the SMIL clock calculations.
  2. Line 2: try:
    Begins the guarded conversion — float("abc") or float(None) would raise, and a bad stored value must never abort a whole book build.
  3. Line 3: return max(0, int(float(total_ms_value)))
    Two-step conversion: float(...) accepts strings like "1234.5", then int(...) truncates to whole milliseconds; max(0, ...) clamps negative junk to zero so a clock value can never go backwards.
  4. Lines 4–5: except (TypeError, ValueError): return 0
    Both realistic failure modes are caught and mapped to 0 ms: TypeError for None/objects, ValueError for non-numeric strings. Zero keeps the SMIL timeline valid even when one paragraph's duration is missing.

74.6 The OPF Package and ZIP Export

_write_opf() emits the manifest that ties the book together, and export_daisy3_zip() packages the whole DAISY3 folder into a single ZIP for distribution (same UI as the DAISY 2.02 export button in the Recording window).

def export_daisy3_zip(project_dir: str, zip_path: str,
                      callback: Optional[Callable[[str], None]] = None) -> None:
    src = os.path.join(project_dir, DAISY3_OUTPUT_DIR_NAME)
    with zipfile.ZipFile(zip_path, "w", zipfile.ZIP_DEFLATED) as zf:
        for root, _dirs, files in os.walk(src):
            for name in files:
                full = os.path.join(root, name)
                rel = os.path.relpath(full, src)
                zf.write(full, rel)
                if callback:
                    callback(rel)

Explain Line by Line Code Description (Block 8)

  1. Lines 1–2: def export_daisy3_zip(project_dir, zip_path, callback=None):
    Packages the finished DAISY3 folder into one ZIP file. The optional callback receives each archived file name, which lets the GUI show progress while a large book is being zipped.
  2. Line 3: src = os.path.join(project_dir, DAISY3_OUTPUT_DIR_NAME)
    Locates the book folder inside the project — the same constant (DAISY3) the builder used when creating it.
  3. Line 4: with zipfile.ZipFile(zip_path, "w", zipfile.ZIP_DEFLATED) as zf:
    Opens the target ZIP for writing with DEFLATE compression. The with block guarantees the archive's central directory is finalized (properly closed) even if an error occurs mid-zip.
  4. Lines 5–9: the os.walk loop
    Visits every file under the book folder. os.path.relpath(full, src) converts each absolute path into a path relative to the book root, so the ZIP unpacks as a clean DAISY 3 fileset with no drive letters or parent folders — exactly what a player expects to find. The callback fires after each file so a progress dialog can tick.

74.7 Choosing DAISY 3 in the Wizard

The New Project wizard offers DAISY audio and text with images book (3) as a project type. Choosing it adds a DAISY page where the book information (title, author, narrator, publisher…) and the chapter-splitting mode (heading style 1 only / break on every heading) are collected; the Recording window then builds the DAISY 3 fileset automatically when recording completes, and the Export DAISY as ZIP button appears.

74.8 Key Takeaways

  • DAISY 3 = DTBook (one XML text document) + NCX (navigation) + SMIL 2.0 (sync) + audio
  • Official DTDs and dtb: attributes are mandatory for strict players
  • <audio> goes directly inside <par> — no wrapping <seq>
  • Phrase-level sync: paragraphs get proportional clip windows of the segment audio
  • Images from DOCX/EPUB/HTML are embedded as imggroup and listed in the OPF manifest
  • MP3s below 44.1 kHz are normalized on staging so DAISY players decode the full audio
