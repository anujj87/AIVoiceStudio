Chapter 55

Recording Dialog

Current implementation (2026.3.1). The window still opens on a project, but it now accepts a start position and a scope from the caller (start_index, and single_segment which becomes an exclusive end_index for the worker), which is how Start Selected Recording... records one chosen file, or every file from a chosen break to the end. A status line above the Start button reports what was chosen (“Ready: segment 12 of 40 — chapter 12…”) before the first click. The compute selector is the same per-category combo described in Chapter 78, and Engine tuning... edits this project's Voice Lab overrides (see Chapter 80).

Learning Objectives

  • Understand the Recording Dialog's complete UI
  • See how voice selection cascades with compute mode
  • Understand the recording lifecycle (start → pause → stop → close)

55.3 Recording Lifecycle

# Start → creates SynthesisWorker thread
def _on_start(self, _):
    voice = self._selected_voice()
    params = self._current_params()
    start_index = project.first_pending_index(self.project_dir)

    self._worker = SynthesisWorker(
        segments=self._segments[start_index:],
        voice_entry=voice, params=params,
        output_dir=self.project_dir,
        start_index=start_index,
        on_segment_done=lambda i, t, p: self._segment_done(i, t, p),
        on_all_done=lambda: wx.PostEvent(self, SynthFinishedEvent()),
        on_error=lambda msg: wx.PostEvent(self, SynthErrorEvent(msg)),
        cancel_event=self._cancel_event,
        pause_event=self._pause_event,
        on_status=lambda msg: wx.PostEvent(self, SynthStatusEvent(msg)),
    )
    self._worker.start()

# Pause → sets pause event
def _on_pause(self, _):
    self._worker.pause()
    self._pause_event.set()

# Stop → sets cancel event
def _on_stop(self, _):
    self._worker.cancel()
    self._cancel_event.set()

# Close → saves TTS settings, ends modal
def _on_close(self, _):
    self._save_tts_to_project()
    self.EndModal(wx.ID_CLOSE)

55.4 What Changed Since the First Edition

The Recording window grew four features after the book's first edition. All of them are post-recording or pre-recording conveniences; the synthesis pipeline itself (Chapter 56) is unchanged.

1. Non-modal task progress dialog

Recording now shows a TaskProgressDialog (Chapter 75) instead of relying on the status line alone. The dialog pulses while segments synthesize, carries a real Stop recording button wired to the worker's cancel event, and closes itself when the worker finishes. Because it is non-modal, the Recording window stays usable.

2. OmniVoice options per project

When an OmniVoice engine is selected, an OmniVoice voice options… button appears. It stores clone/design options in the project's tts.omni dictionary; a summary line beside the button announces the current setting. Voice-library voices (created in Settings) carry their own identity, so for them the button hides and the summary describes the library voice instead.

3. Playlist generation on completion

For Audio files with playlist projects, the moment recording completes the dialog reloads project.json from disk (the worker thread has been updating segment status while the dialog sat idle) and calls build_playlists() — see Chapter 73 for the module itself and its line-by-line walkthrough. The completion message then names the three written files:

def _playlist_summary(self) -> str:
    ptype = self.data.get("project_type", "audio_playlist")
    if ptype != "audio_playlist" or not self._playlist_files:
        return ""
    names = ", ".join(os.path.basename(p) for p in self._playlist_files)
    return ("\n\nPlaylists were generated in the project folder "
            f"({names}) - open them in VLC, Windows Media Player, "
            "PotPlayer or any modern player to play the whole "
            "recording in order.")

Explain Line by Line Code Description (Block 5)

  1. Line 1: def _playlist_summary(self) -> str:
    Builds the extra paragraph appended to the "Recording complete" message when playlists were written. Returning an empty string for other project types keeps the message clean for DAISY projects.
  2. Line 2: ptype = self.data.get("project_type", "audio_playlist")
    Reads the project type with a default. The guard on the next line returns "" unless this really is an audio-playlist project and playlist files exist — not self._playlist_files covers the "nothing was recorded" case where build_playlists returned an empty list.
  3. Line 4: names = ", ".join(os.path.basename(p) for p in self._playlist_files)
    Compresses each written path to its bare file name with os.path.basename and joins them with commas, producing e.g. My Book.m3u8, My Book.pls, My Book.wpl — the user does not need the absolute paths, just the names to look for.
  4. Lines 5–9: return (...)
    Returns a two-sentence note: which files were generated and that they open in VLC, Windows Media Player, PotPlayer "or any modern player". The leading \n\n separates it from the DAISY summary that may precede it.

4. MP3/FLAC warning in DAISY projects

Choosing MP3 or FLAC while a DAISY project is open shows a warning every time (no "don't ask again"): DAISY players are much more reliable with WAV, and although the builders now re-encode low-rate MP3s (Chapter 59), WAV remains the recommended output. The Recording window's output-format combo stays enabled — the warning is informational, not a block.

55.5 Key Takeaways

  • The Recording Dialog is the most complex GUI component in AIVS
  • Compute mode filters which TTS engines are available
  • Segments resume from first_pending_index — previously recorded segments are skipped
  • Pause/Resume/Stop control the background synthesis thread
  • TTS settings are saved to project.json on every start and close
  • Post-recording steps read fresh project state from disk: DAISY books and playlists are built from what the worker actually saved
