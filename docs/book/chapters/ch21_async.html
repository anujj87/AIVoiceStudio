21.1 What Is Async I/O?

asyncio is Python's built-in framework for writing concurrent code using coroutines. Unlike threads, async code runs in a single thread and cooperatively yields control at await points.

FeatureThreadsAsync
ParallelismPreemptive (GIL)Cooperative (single thread)
OverheadPer-thread stack (~8MB)Per-coroutine (~KB)
Best forMixed I/O + some CPUHigh-concurrency I/O
GUI compatible?Yes (PostEvent)Needs event loop integration

21.2 Async Basics

import asyncio

# Define a coroutine
async def fetch_model(url: str) -> bytes:
    import aiohttp
    async with aiohttp.ClientSession() as session:
        async with session.get(url) as response:
            return await response.read()

# Run a coroutine
data = asyncio.run(fetch_model("https://example.com/model.onnx"))

# Multiple concurrent coroutines
async def download_all(urls: list[str]):
    tasks = [fetch_model(url) for url in urls]
    results = await asyncio.gather(*tasks)
    return results

21.3 When Async Isn't the Right Choice

AI Voice Studio uses threads, not async, because:

  • wxPython is not async-compatible — its event loop conflicts with asyncio
  • Blocking libraries — sherpa-onnx and NumPy are synchronous
  • Subprocess isolation — heavy work runs in separate processes anyway
  • Thread simplicity — for 5-10 concurrent tasks, threads are simpler
When to use async: Web servers handling thousands of connections, web scrapers, WebSocket clients. For a desktop app with a handful of background tasks, threads are the better choice.

21.4 Key Takeaways

  • async/await is for I/O-bound concurrency in a single thread
  • asyncio.gather() runs multiple coroutines concurrently
  • AIVS uses threads + subprocesses instead, because wxPython and ML libraries are synchronous
  • Async shines for high-concurrency network I/O (hundreds of connections)
