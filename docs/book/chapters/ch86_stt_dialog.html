Chapter 86

The Transcribe Dialog: A Job, Its Outputs and an Honest Progress Window

Learning Objectives

  • Turn a model choice into a request the engine can run, and keep the GUI out of it
  • Write every finished document to disk immediately, so a crash costs one file
  • Render one segment list into seven output formats without seven code paths in the dialog
  • Split a long recording by time without ever cutting a sentence in half
  • Name the documents so two sources with the same base name cannot overwrite each other
  • Use a project base so one dialog serves recording and transcription without saying "audio" to a user transcribing text

86.1 The Dialog's Five Choices

The transcribe dialog is the last step of a transcription project's wizard and what Open reopens on a recent one. It asks five things and nothing more:

  1. Compute — the device, from catalog.device_options() (Chapter 84), rebuilt when the variant changes.
  2. Speech to text model and Variant — every model in the catalog, with the ones that are not installed yet saying so.
  3. Language — the spoken language, or Detect automatically.
  4. Accuracy — fast, balanced or most accurate.
  5. Translation — enabled only for a model that can translate, and it says why when it is disabled.

Every control follows the project's accessibility rule: a real StaticText label with an accessible name, a status line that is a real control rather than a painted string, and a gauge for progress. The transcribe dialog is software a screen-reader user has to be able to hear working, which is why the status line narrates each step ("Transcribing lecture 1 of 3…", "Saved lecture part 2.txt").

Accuracy is a policy, not a magic number. The three levels map to beam sizes (“fast” = greedy, “balanced” = beam 5, “most accurate” = beam 8) and every model offers the same three labels. That keeps the dialog predictable: a user who learned what balanced means for Whisper finds it means the same thing for Qwen3-ASR, and the per-model reality is shown separately as the accuracy hint (“~10.3 % WER (large-v3)”) from the catalog.

86.2 The Job Runs Off the GUI Thread

Transcription takes minutes, so the dialog starts a thread and gets out of the way. The job is deliberately small:

class TranscriptionJob(threading.Thread):
    """Transcribe a list of source files into output documents."""

    def __init__(self, project_dir, source_paths, options, *,
                 on_progress=None, on_done=None, on_error=None):
        super().__init__(daemon=True)
        ...
        self._cancel = threading.Event()
        self.outputs: List[Dict[str, Any]] = []

    def cancel(self) -> None:
        self._cancel.set()

Three rules make it safe:

  • Plain callbacks, no widgets. The job knows nothing about wx; it calls on_progress(message, fraction), on_done(outputs) or on_error(exc). The dialog marshals those onto the GUI thread. That is what lets the job be tested without a display.
  • Every callback is wrapped in try/except. A misbehaving callback must never kill the job halfway through a long book:
def _report(self, message: str, fraction: float) -> None:
    if self._on_progress is not None:
        try:
            self._on_progress(message, max(0.0, min(1.0, fraction)))
        except Exception:  # noqa: BLE001
            log.debug("progress callback failed", exc_info=True)
  • A document is written the moment it is finished. The ordering in _run() is not an accident:
for index, source in enumerate(sources, start=1):
    if self._cancel.is_set():
        return
    base = (index - 1) / len(sources)
    span = 1.0 / len(sources)
    self._report(f"Transcribing {name} ({index} of {len(sources)})...", base)
    segments = transcribe_audio(source, model_id=..., compute=...)
    if self._cancel.is_set():
        return
    ...
    path = self._write_document(doc_stem, part, doc_stem)
    self.outputs.append({ "source": source, "file": os.path.basename(path), ... })

The fraction is computed from the file index and not from the model's own idea of progress, because a model that reports nothing would otherwise leave the bar at zero for twenty minutes. The progress is per file: coarse, truthful, and always moving.

Crash-safety is inherited, not re-invented. The recording side already saves each segment as it is produced (Chapter 55). Transcription follows the same rule so a Close, a crash or a power cut costs at most the one file in flight — and a three-hour lecture is not a single point of failure.

86.3 One Segment List, Seven Documents

A segment is a plain dictionary:

{"start": 12.4, "end": 15.9, "text": "The mitochondria is the powerhouse..."}

Turning segments into a document is independent of which model produced them, so it lives in stt/output.py and nothing about it is in the dialog:

def format_document(segments, output_format, include_timestamp=False, title=""):
    """Render ``segments`` in the chosen output format.

    The subtitle formats (SRT/VTT) always carry their timing - it is what makes
    them subtitles - so ``include_timestamp`` only affects the text formats.
    """
    if output_format == STT_FORMAT_SRT:
        return _as_srt(segments)
    if output_format == STT_FORMAT_VTT:
        return _as_vtt(segments)
    writer = _WRITERS.get(output_format, _as_txt)
    return writer(segments, include_timestamp, title)

Two small decisions make the timed formats correct. Timestamps are formatted by one shared helper, because SRT wants a comma before the milliseconds and VTT wants a dot — getting that wrong produces files that look right and fail in players:

def format_timestamp(seconds, *, millisecond_sep=",") -> str:
    """hh:mm:ss<sep>mmm, with an empty string for a missing time."""

And a model without timings produces a single untimed segment, so the writers never fabricate a time. An SRT made from untimed segments has no meaningful cues — which is exactly why the catalog declares timestamps per model (Chapter 84) and the dialog can tell the user before the run that this model will not produce subtitles.

86.4 Splitting a Long Recording by Time

“Time by time separation” turns one two-hour lecture into several short documents. The naive implementation — cut at n minutes exactly — leaves half-sentences at every boundary. The rule here is the opposite: a chunk is closed when the next segment would push it past the limit, so a sentence is never cut in half.

def split_by_time(segments, minutes: int) -> List[List[Segment]]:
    """Group segments into chunks of at most ``minutes`` minutes each.

    A segment is never cut in half: a chunk is closed when the *next* segment
    would push it past the limit, and a single segment longer than the limit
    becomes its own chunk.  Segments with no timing are all collected into one
    chunk (there is nothing to measure against).
    """
    limit = max(1.0, float(minutes) * 60.0)
    chunks: List[List[Segment]] = []
    current: List[Segment] = []
    for seg in segments:
        if not current:
            current.append(seg)
            continue
        start = current[0].get("start")
        end = seg.get("end")
        if start is None or end is None:
            current.append(seg)
            continue
        if float(end) - float(start) > limit:
            chunks.append(current)
            current = [seg]
        else:
            current.append(seg)
    if current:
        chunks.append(current)
    return chunks

Note the two edge cases handled explicitly, because both happen in real files: a missing timestamp (an audio language model) collects everything into one chunk rather than guessing, and a single segment longer than the limit becomes its own chunk rather than being dropped or split.

86.5 Naming the Documents

The document name comes from the source file, and two sources can easily share a base name — audio\lecture 1.mp4 and lecture 1.m4a in the same folder. plan_documents() resolves that before anything is written:

name = stem if len(parts) == 1 and split_mode != "by_time" else (
    f"{stem} part {index}" if len(parts) > 1 else stem
)
# Disambiguate two source files with the same base name.
key = name.lower()
if key in used:
    used[key] += 1
    name = f"{name} ({used[key]})"
else:
    used[key] = 1

So a split recording writes lecture 1 part 1.txt, lecture 1 part 2.txt…, and a collision writes lecture 1 (2).txt instead of silently overwriting the first transcript — a bug that would otherwise only be discovered by reading the wrong file.

86.6 One Project Base, Two Vocabularies

A project has a base: recording or transcription. The Edit menu reads the base and changes its own words accordingly — a transcription project has files, a recording project has recordings:

  • Start Selected Recording becomes Start Selected Files, offering Select a transcribe file or Select by file break, then Only transcribe the selected file or Transcribe all files from here.
  • Restart All Recording becomes Restart All Files, and both restart confirmations spell out that recordings or transcribe files and the audio or transcribe options are reset.
  • When the job finishes, the progress window offers Open project folder — the same courtesy the recording flow has always shown, because the documents land next to the project and not somewhere the user has to hunt for.
Wording is part of the interface. A blind user navigating by menu labels cannot see which kind of project is open; if the Edit menu said “recordings” on a transcription project, the wrong command would be reached by muscle memory. Reading the project base and renaming the commands is cheaper than teaching users to remember two similar menus.

86.7 Exercises

  1. Add a "one document per heading" output mode. Where does the heading come from, and how does plan_documents() name the files?
  2. Change the progress model to per-segment with a total-duration estimate. What happens when a model reports no timings?
  3. Make split_by_time() prefer a silence gap within the last 30 seconds of a chunk instead of the first segment that crosses the limit.

Key Takeaways

  • Keep the job free of widgets: plain callbacks, wrapped so a bad callback cannot kill the run.
  • Write each finished document immediately; crash-safety is a property of the ordering, not of a cleanup handler.
  • One formatter per output type, chosen by a table, and one shared timestamp helper — SRT and VTT differ by one character.
  • Never cut a segment in half when splitting by time, and handle untimed segments explicitly.
  • Disambiguate output names up front; overwriting a transcript is a silent data loss.
