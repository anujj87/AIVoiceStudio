Chapter 77

One Python Environment per Engine

Learning Objectives

  • Create and manage a virtualenv per engine, from inside a frozen application
  • Map an engine id to an environment folder deterministically
  • Answer “is this package installed?” three ways — cached, asynchronous and straight from disk
  • Plan a CUDA-aware pip install, and understand why the wheel index matters
  • Verify an installation by importing the engine, and explain the failures that check catches

77.1 The Problem: One Shared Environment Cannot Hold Two Engines

TTS engines are ordinary Python packages that depend on machine-learning frameworks. Their requirements conflict constantly:

  • two engines need two different torch releases;
  • one engine pins transformers<4.40 while another needs 4.46+;
  • one engine ships a torchao-style sub-dependency whose module was renamed in a later release, so a newer version breaks the engine at import time even though pip considers the install valid.

This is exactly the failure mode that made the project move from one shared environment to one environment per engine. The layout is:

%APPDATA%\AIVoiceStudio\
├── addon_env\                 shared environment (addons, Developer tab)
└── tts_envs\
    ├── pocket_tts\            Pocket TTS only
    ├── bark\                  Bark + transformers + torch
    ├── f5tts\                 F5-TTS + torch + torchaudio
    └── omnivoice\             OmniVoice + OmniVoice Server (shared on purpose)
Engines that genuinely want the same packages may share an environment. In this project the two OmniVoice front-ends (the direct runner and the HTTP server) both need the same omnivoice base package and the same CUDA PyTorch, so a second environment would only duplicate gigabytes of wheels. That exception is written down as data (SHARED_ENVIRONMENTS) rather than hidden in a condition somewhere in the GUI.

77.2 Mapping an Engine to Its Environment

def _safe_env_name(engine_id: str | None) -> str:
    name = "".join(
        char if char.isalnum() or char in "_-" else "_"
        for char in (engine_id or "").strip().lower()
    )
    return name or "default"


def environment_id(engine_id: str | None) -> str:
    name = _safe_env_name(engine_id)
    return SHARED_ENVIRONMENTS.get(name, name)


def engine_env_dir(engine_id: str) -> str:
    return os.path.join(
        paths.user_data_dir(), _TTS_ENVS_DIR, environment_id(engine_id)
    )

Explain Line by Line Code Description (Block 1)

  1. Lines 1–6: _safe_env_name
    Sanitises an id into a safe folder name: every character that is not alphanumeric, _ or - becomes _, and the result is lower-cased. This matters because the folder name is built from data that arrives from the registry, a settings file or a test — and a stray character would otherwise create a path that Windows refuses. The or "default" tail guarantees a non-empty name even for None.
  2. Lines 9–11: environment_id
    The single place where “which environment does engine X use?” is answered. Two OmniVoice ids collapse onto one folder here, which means every caller — installer, uninstaller, probe cache, worker starter — agrees automatically. Putting this mapping anywhere else would eventually produce an install in one folder and a probe in another.
  3. Lines 14–18: engine_env_dir
    paths.user_data_dir() resolves per-user, per-OS state (%APPDATA% on Windows, ~/.local/share on Linux, ~/Library/Application Support on macOS), so the application never writes inside its own installation folder — which matters because the installation folder is read-only for a normal user.

The runtime object itself is a thin wrapper over one environment directory:

class PythonRuntime:
    def __init__(self, env_dir: str | None = None):
        self._env_dir = env_dir or os.path.join(
            paths.user_data_dir(), _ADDON_ENV_DIR
        )
        self._system_python: str | None = None
        self._lock = threading.RLock()

    @property
    def python_exe(self) -> str:
        return _python_exe_for_env(self._env_dir)

    @property
    def is_created(self) -> bool:
        return os.path.isfile(self.python_exe)

    @property
    def site_packages_dirs(self) -> List[str]:
        found: List[str] = []
        for pattern in ("Lib/site-packages", "lib/python*/site-packages"):
            found.extend(sorted(glob.glob(os.path.join(self._env_dir, pattern))))
        return [path for path in found if os.path.isdir(path)]

    def ensure_env(self) -> str:
        if self.is_created:
            return self._env_dir
        os.makedirs(self._env_dir, exist_ok=True)
        subprocess.run(
            [self.system_python, "-m", "venv", self._env_dir, "--clear"],
            capture_output=True, text=True, check=True,
            cwd=tempfile.gettempdir(), creationflags=creationflags,
        )
        return self._env_dir

Explain Line by Line Code Description (Block 2)

  1. Lines 2–5: the constructor
    An explicit env_dir makes the class testable with a temporary folder; the default is the shared addon environment, so existing addon code is unchanged. _system_python is filled lazily (finding a base interpreter is a search) and a lock guards it, because several threads may build a runtime at once.
  2. Lines 8–9: python_exe
    A tiny platform-aware function chooses Scripts/python.exe on Windows versus bin/python elsewhere. Centralising it means no other module ever hard-codes a path separator.
  3. Lines 12–13: is_created
    The environment exists when its interpreter exists. That is the cheapest reliable test: a half-built folder without an interpreter is correctly treated as “not created”, and the next install repairs it.
  4. Lines 16–21: site_packages_dirs
    Returns the folder(s) that hold installed packages, looking for both the Windows layout and the POSIX layout with a wildcarded Python version. Two layouts, one list — and the empty list is a valid answer meaning “nothing installed yet”. This property is the foundation of the synchronous disk probes in 77.4.
  5. Lines 23–31: ensure_env
    Idempotent by design (if self.is_created: return), then creates the virtualenv with the system interpreter — a frozen PyInstaller application cannot use sys.executable for this, because that is the application itself. check=True turns a failed venv creation into an exception the caller can report, and cwd=tempfile.gettempdir() avoids inheriting a working directory that may no longer exist, which is a classic way for subprocess creation to fail on a background thread.
def get_runtime(engine_id: str | None = None) -> PythonRuntime:
    global _default_runtime
    if not engine_id:
        if _default_runtime is None:
            with _runtime_lock:
                if _default_runtime is None:
                    _default_runtime = PythonRuntime()
        return _default_runtime
    key = environment_id(engine_id)
    with _runtime_lock:
        runtime = _engine_runtimes.get(key)
        if runtime is None:
            runtime = PythonRuntime(engine_env_dir(engine_id))
            _engine_runtimes[key] = runtime
        return runtime

Explain Line by Line Code Description (Block 3)

  1. Line 1: the optional engine_id
    Calling it with no argument returns the shared environment; calling it with an id returns that engine’s own environment. One function serves both, so callers never pick a class.
  2. Lines 3–8: the double-checked singleton
    The lock is taken only on a miss, and inside it the check is repeated. Two threads racing to build the shared runtime end up with one object — important because two runtime objects would each cache their own “is it created?” answer and could disagree.
  3. Lines 9–14: the per-engine dictionary
    Keyed by environment_id, not by engine id, so the two OmniVoice engines deliberately share one runtime object.

77.3 Installing: Two pip Steps, Not One

On a machine with an NVIDIA GPU, the plain PyPI torch wheel for Windows is CPU-only. A GPU engine therefore needs wheels from PyTorch’s own index. Those wheels are not mirrored on PyPI, and the index does not carry the engine’s other packages — so the install is planned as an ordered list of steps:

PYTORCH_CUDA_INDEX = "https://download.pytorch.org/whl/cu128"

_CUDA_PACKAGES = {
    "pocket_tts": ("torch",),
    "bark": ("torch",),
    "f5tts": ("torch", "torchaudio"),
}


def install_plan(engine_id):
    packages = list(packages_for(engine_id))
    steps = []
    cuda = list(engines.cuda_packages(engine_id))
    index = engines.cuda_index_url(engine_id)
    if cuda and index and has_cuda() and not venv_packages.installed(
        "torch", engine=engine_id
    ):
        steps.append((cuda, index))
        packages = [p for p in packages if p not in cuda]
    if packages:
        steps.append((packages, None))
    return steps

Explain Line by Line Code Description (Block 4)

  1. Line 1: PYTORCH_CUDA_INDEX
    The wheel index for CUDA builds. The cu128 tag is chosen to match the Python the application runs on: an older index (cu121) stops at Python 3.12 and has no wheels at all for 3.13, which produces the infuriating “No matching distribution found for torch” while installing an engine. Version tags like this belong in exactly one constant — and the OmniVoice installers read the same constant, so every CUDA wheel in the product comes from one index.
  2. Lines 3–7: _CUDA_PACKAGES
    Which packages must come from that index per engine. F5-TTS needs torchaudio as well, and taking the two from the same index is what stops a build mix (a CUDA torch with a CPU torchaudio is a runtime crash, not a warning).
  3. Line 10: packages = list(packages_for(engine_id))
    Start from the full list the registry declares, then remove whatever the CUDA step already installed. The registry stays the single source of truth about what is needed; the plan only decides from where.
  4. Line 13: the condition
    Three independent facts must hold: the engine has CUDA packages, the index is known, an NVIDIA GPU with a working driver is present, and PyTorch is not already installed in this environment. The last clause is what makes a re-run cheap and avoids re-downloading gigabytes when only a small package is missing.
  5. Lines 14–15: step one
    The CUDA packages plus the index URL. Returning (packages, index) pairs — rather than a single command line — lets the GUI show each step’s progress and keeps the pip invocation in one place.
  6. Lines 16–17: step two
    Everything else from the default index (None means “no --index-url”). Ordering matters: installing the CUDA build first prevents pip from resolving a CPU torch as a dependency of the engine and then having nothing to do in step one.
Never put version specifiers in the registry’s packages tuple. The same tuple feeds “Remove engine…”, and pip uninstall "torchao<0.18" fails — leaving the user with an engine that cannot be removed. Compatibility pins are applied as an install-time step, not as the package name.

77.4 Three Answers to “Is It Installed?”

The Settings dialog builds all of its pages up front. The original code asked the question by starting python -c "import importlib.metadata…" inside the environment — a second or more per package, a dozen of them, all while the window was being drawn. The current module answers the same question three ways:

APICostUsed by
version(pkg, engine=…)memory; on a cold cache it starts one background probe and reads disklabels that must fill in while the window stays responsive
request(pkg, on_ready=…, engine=…)one worker threadpanels that want to refresh themselves when the answer arrives
package_present(pkg, engine=…)a directory listing, synchronousdeciding which interpreter the worker must run with
 
def _disk_distributions(engine: Optional[str] = None) -> Dict[str, str]:
    try:
        from .python_runtime import get_runtime
        folders = get_runtime(engine).site_packages_dirs
    except Exception:
        return {}
    found: Dict[str, str] = {}
    for folder in folders:
        try:
            stamp = os.path.getmtime(folder)
        except OSError:
            continue
        with _lock:
            entry = _disk_cache.get(folder)
        if entry is not None and entry[0] == stamp:
            found.update(entry[1])
            continue
        listed: Dict[str, str] = {}
        try:
            for name in os.listdir(folder):
                if not name.endswith(".dist-info"):
                    continue
                distribution, _, version_text = name[:-len(".dist-info")].partition("-")
                listed[_normalize(distribution)] = version_text
        except OSError:
            continue
        with _lock:
            _disk_cache[folder] = (stamp, listed)
        found.update(listed)
    return found

Explain Line by Line Code Description (Block 5)

  1. Lines 2–5: getting the folders
    Delegates to the runtime object so this module never builds a path itself. Wrapped in try/except returning an empty dict: “I cannot tell” must not crash a GUI that is merely drawing a label.
  2. Lines 7–12: the stamp check
    The folder’s modification time is the cache key. Any pip operation changes it, so the cache is invalidated by the act of installing — without a single explicit “please clear the cache” call from the installer.
  3. Lines 13–20: the listing
    Every installed distribution leaves a <name>-<version>.dist-info folder. Splitting on the first dash (partition) and stripping the suffix yields name and version, and _normalize() applies PEP 503 normalisation so f5_tts, f5-tts and F5.TTS are one key. Reading files instead of importing them is why this is safe on the GUI thread.
  4. Lines 21–26: caching and merging
    The listing is stored under the stamp and merged into one dictionary across folders. A partially written directory (pip is mid-install) is handled by the outer OSError guard: the next call sees a new stamp and re-reads.
def package_present(package: str, engine: Optional[str] = None) -> bool:
    name = _normalize(package)
    if not name:
        return False
    if name in _disk_distributions(engine):
        return True
    try:
        folders = get_runtime(engine).site_packages_dirs
    except Exception:
        return False
    stem = name.replace("-", "_")
    for folder in folders:
        if os.path.isdir(os.path.join(folder, stem)):
            return True
        if os.path.isfile(os.path.join(folder, stem + ".py")):
            return True
    return False

Explain Line by Line Code Description (Block 6)

  1. Lines 2–5: the normalised short-circuit
    An empty name can never match, and the fast path asks the same disk listing used everywhere else.
  2. Lines 9–13: the fallbacks
    Some hand-patched or vendor-installed environments have the importable module or package folder but no dist-info metadata (this is common with wheels unpacked by other tools). Accepting a folder stem/ or a module stem.py means such an environment is still detected as usable rather than looking empty.
  3. The point of the function
    It is synchronous and cache-free. It exists for exactly one decision, described next, where a slightly stale answer would send a worker into the wrong environment.

77.5 Choosing the Interpreter for the Worker

This is where the three probes earn their keep. A worker started in the wrong environment does not report the engine’s real error; it reports ModuleNotFoundError: No module named 'torch' — a message that says nothing about which environment was used and sends the reader hunting in the wrong place.

def _runtime(self):
    required = tuple(engines.import_modules(self.engine_id)) or (
        engines.probe_package(self.engine_id),
    )
    required = tuple(name for name in required if name)
    engine_runtime = get_runtime(self.engine_id)
    if engine_runtime.is_created and (
        not required
        or all(venv_packages.package_present(name, engine=self.engine_id)
               for name in required)
    ):
        return engine_runtime
    runtime = get_runtime()
    if not runtime.is_created:
        runtime.ensure_env()
    if not required or all(venv_packages.package_present(name) for name in required):
        return runtime
    raise VoicelabError(
        f"{engines.engine_name(self.engine_id)} is not installed in its own "
        "Python environment any more. Install it again from Settings > Voice Clone."
    )

Explain Line by Line Code Description (Block 7)

  1. Lines 2–5: what the engine needs
    The worker’s own module list (the same tuple the worker checks at start-up) with the single probe package as a fallback. The list is shared data: the worker and the application must not disagree about what “installed” means, and there is a test asserting the two copies have not drifted apart.
  2. Lines 6–12: prefer the engine’s own environment
    Both conditions are required: the environment must exist and every required module must be present in it, checked with the synchronous package_present. Using the cached probe here would be the bug the docstring warns about — a probe that has not answered yet returns None, which reads as “not installed”, which silently downgrades to the shared environment.
  3. Lines 13–16: the fallback
    Engines installed before per-engine environments existed still live in the shared environment, so an installation is honoured there. The environment is created if missing, because the caller is about to start a process in it.
  4. Lines 17–21: the honest failure
    If neither environment can satisfy the engine, the error says so and tells the user exactly what to do. This is the difference between a support ticket that reads “it says No module named torch” and one that reads “it told me to reinstall the engine”.

77.6 Verify the Install, Do Not Assume It

pip succeeding means the dependency graph resolved — not that the engine can import. A resolved combination can still fail at import time when a sub-dependency renamed a module. So after installing, the application imports the engine once, in its own environment, and reports what happens:

def verify_engine_import(engine_id: str, timeout: float = 300.0) -> Optional[str]:
    modules = engines.import_modules(engine_id)
    if not modules:
        return None
    try:
        runtime = get_runtime(engine_id)
        if not runtime.is_created:
            return None
        python_exe = runtime.python_exe
    except Exception as exc:
        return f"Could not start the engine's Python environment: {exc}"
    if not os.path.isfile(python_exe):
        return None
    script = "import " + ", ".join(modules)
    try:
        result = subprocess.run(
            [python_exe, "-c", script],
            capture_output=True, text=True, timeout=timeout,
            creationflags=flags,
        )
    except subprocess.TimeoutExpired:
        return (f"Loading {engines.engine_name(engine_id)} took too long "
                f"({int(timeout)}s) and was stopped.")
    except OSError as exc:
        return f"Could not run the engine's Python environment: {exc}"
    if result.returncode == 0:
        return None
    detail = (result.stderr or result.stdout or "").strip().splitlines()
    last = detail[-1] if detail else f"exit code {result.returncode}"
    return f"{engines.engine_name(engine_id)} is installed but failed to load: {last}"

Explain Line by Line Code Description (Block 8)

  1. Lines 2–4: the module list
    Exactly the modules the worker will need. An empty list means the registry has nothing to verify and the check is skipped rather than guessed.
  2. Lines 5–11: the interpreter
    Each failure to even locate the environment is converted into a message, not an exception: this function’s return value is the user-facing report, so it tells rather than raises.
  3. Line 13: script = "import " + ", ".join(modules)
    One interpreter run imports everything at once, so the empty case cannot happen and the cost is a single process start-up.
  4. Lines 15–21: the subprocess call
    A 300-second timeout is deliberately generous: the first import of a large model package may load native libraries from disk and take minutes on a cold cache, and killing it would report a false failure. text=True decodes the output so it can be shown verbatim.
  5. Lines 22–24: the timeout branch
    Telling the user “it took too long and was stopped” is honest and actionable; letting the GUI hang behind an import would look like a freeze.
  6. Lines 27–30: the failure branch
    Only the last line of stderr is surfaced. Python tracebacks end with the genuinely informative line, and the full traceback is far too long for a dialog — it belongs in the log, which the install dialog also writes.
  7. A note on the return convention
    “Problem, or None” keeps the caller trivial: problem = verify_engine_import(id); if problem: show(problem). Compare that to a function that raises, where the caller must also remember to catch.
This check is the single highest-value addition to the installer flow. A missing module discovered during installation costs a minute; discovered three chapters into recording, it costs the trust of the whole feature.

77.8 Key Takeaways

  • One virtualenv per engine is the only reliable answer to conflicting ML dependencies
  • Map ids to environments in one function so every subsystem agrees
  • CUDA wheels come from PyTorch’s index, in a separate pip step, keyed to the Python version in use
  • Answer “is it installed?” from disk when correctness matters, and asynchronously when responsiveness matters
  • Never let a non-blocking cache decide which interpreter starts a worker
  • Verify by importing — a successful pip run is not a working engine
  • Never put version specifiers in the list used for uninstalling
