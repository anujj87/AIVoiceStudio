Chapter 80

Start Selected Recording: Out-of-Order Recording for Long Books

Learning Objectives

  • Turn a “resume where you stopped” feature into a general “record these segments” range
  • Model a worker’s position with a start index and an exclusive end index
  • Build a dialog whose combo box changes content based on a sidebar radio group
  • Keep the keyboard-and-screen-reader path usable when controls are rebuilt
  • Remove the guard rails that fight the user’s actual workflow

80.1 The Workflow It Has to Support

A 100-chapter book. The narrator records chapter 75 first because that is the chapter they have time for today, then jumps back to chapter 12, then finally records the introduction. The old behaviour — “start where you left off and continue to the end” — cannot express any of that.

The feature is called Start Selected Recording… and it answers two questions separately:

  1. Where does the list of choices come from? Either the audio files already recorded, or every file break in the project (recorded or not).
  2. How far should recording go? Only the chosen file, or the chosen file and everything after it.

Those are two radio groups, and the first one also decides what the combo box contains. That single coupling is what makes the dialog feel obvious: one sidebar choice changes the list and its label.

Sidebar choiceCombo labelCombo contentsTypical intent
Select an audio fileChoose which recorded file to record again:only files already recorded“that take was wrong, redo it”
Select by file breakChoose which file to record by file break:all 12 (or 100) breaks, recorded or not“start on chapter 75 today”

80.2 The Range Contract in the Worker

Everything starts with the synthesis worker, because a dialog that cannot express “just this one” would have to lie. The worker already took a start_index; the feature adds an exclusive end_index:

def __init__(self, ..., start_index: int = 0, end_index: Optional[int] = None):
    ...
    self.start_index = max(0, start_index)
    # end_index = start_index + 1 records a single segment; None means
    # "to the end of the project" (the plain Start recording behaviour).
    self.end_index = end_index


def _segment_positions(self, total: int):
    if self.end_index is not None:
        stop = max(self.start_index, min(self.end_index, total))
    else:
        stop = total
    for idx in range(self.start_index, stop):
        yield idx

Explain Line by Line Code Description (Block 1)

  1. Lines 1–3: the two parameters
    Both are optional, so every existing call site keeps working unchanged: no argument means “start at the first pending segment and go to the end”, which is exactly the old behaviour. Backwards compatibility by default value is the cheapest kind of refactor.
  2. Line 5: self.start_index = max(0, start_index)
    A negative index would silently mean “from the end” in Python slicing rules, which is not what “start at segment −1” should ever do. Clamping to 0 makes the invalid input harmless.
  3. Line 8: the comment that defines the vocabulary
    One sentence that makes end_index self-documenting: it is exclusive, and start_index + 1 is the idiom for a single segment. Without that line, the next reader would have to guess whether the end is inclusive — and would guess wrong half the time.
  4. Line 14: stop = max(self.start_index, min(self.end_index, total))
    Two clamps in one expression: never go past the end of the project (min), and never produce an empty range when the caller passes an end before the start (max). A manual if for each would be four lines doing exactly this.
  5. Lines 17–18: a generator
    The worker iterates positions through range(...), which keeps the loop body free of index arithmetic and index-boundary bugs. “What percent am I done?” is derived from the range, not from counters that can drift.
Exclusive ends are a convention worth adopting deliberately: range(a, b), list[a:b] and this worker all agree, so no reader has to remember a special case.

80.3 One Entry per Segment, Built Purely

The dialog needs, for each segment, three things: its 0-based position, its display name, and the audio file it already has (if any). Building that mapping is pure data work — no wx, no disk scanning beyond the files the caller passes in — so it lives in its own module-level function where it can be tested directly.

def _picker_entries(data: dict, saved: list[str]) -> list[dict]:
    from ..util import sanitize_filename

    segments = data.get("segments", []) or []
    entries = []
    by_stem: dict[str, int] = {}
    by_name: dict[str, int] = {}
    for position, seg in enumerate(segments):
        title = str(seg.get("title") or f"segment {position + 1}")
        entries.append({"position": position, "title": title, "file": None})
        by_stem.setdefault(sanitize_filename(title, 80), position)
        stored = os.path.basename(str(seg.get("saved") or ""))
        if stored:
            by_name.setdefault(stored, position)
    for name in saved:
        position = by_name.get(name)
        if position is None:
            position = by_stem.get(os.path.splitext(name)[0])
        if position is None:
            continue  # A stray file that no file break refers to.
        if entries[position]["file"] is None:
            entries[position]["file"] = name
    return entries

Explain Line by Line Code Description (Block 2)

  1. Lines 4–6: the starting structures
    One entry per segment, in document order, with file unknown for now; plus two lookup dictionaries that will be filled in the same pass. Doing it in one pass means the two mapping strategies cannot disagree about positions.
  2. Line 7: reading the project data
    data.get("segments", []) or [] tolerates both a missing key and an explicit None. Project files are user-editable JSON, so “absent” and “null” must both be survivable.
  3. Lines 8–9: the title fallback
    A segment without a title gets “segment 7”. A visible, correct placeholder beats an empty combo row that the screen reader announces as blank.
  4. Line 10: sanitize_filename(title, 80)
    The same function the recorder used to name audio files, with the same length limit. Reusing it is what makes by_stem a valid fallback: the audio file’s name minus its extension equals the sanitised title only if both sides agree on sanitation — and they do, because it is one function.
  5. Lines 11–13: the authoritative mapping
    A segment’s saved field records the file it produced, so that path is the primary link. os.path.basename normalises a full path to a name, and setdefault keeps the first mapping if a project contains duplicates.
  6. Lines 14–16: matching the files on disk
    Primary key is the recorded name; the secondary key is the sanitised title. Two strategies, because a metadata field can be out of date while the file names remain correct — the fallback rescues exactly that case.
  7. Lines 17–18: the deliberate continue
    An audio file that no break refers to is skipped rather than listed. The mode’s promise is “files that belong to this project”, and a stray file has no position to record from — offering it would create a choice the worker cannot execute.
  8. Line 19: first-wins assignment
    if entries[position]["file"] is None keeps the earliest name when two files match one segment (for example an old take and a new one). Predictable, order-dependent, and easy to test.

80.4 The Dialog: Two Radio Groups, One Combo

class _StartRecordingDialog(wx.Dialog):
    def __init__(self, parent, entries):
        super().__init__(parent, title="Start selected recording", size=(600, 320))
        self._entries = [dict(entry) for entry in entries]

        outer = wx.BoxSizer(wx.HORIZONTAL)
        side_panel = wx.Panel(self)
        sidebar = wx.BoxSizer(wx.VERTICAL)
        self.file_radio = wx.RadioButton(
            side_panel, label="Select an audio file", style=wx.RB_GROUP)
        self.break_radio = wx.RadioButton(side_panel, label="Select by file break")
        for radio in (self.file_radio, self.break_radio):
            radio.SetName(radio.GetLabel())
            sidebar.Add(radio, 0, wx.ALL, 6)
        side_panel.SetSizerAndFit(sidebar)
        side_panel.SetMinSize((240, -1))
        side_panel.SetName("Recording selection mode")
        if not any(entry.get("file") for entry in self._entries):
            self.break_radio.SetValue(True)
        outer.Add(side_panel, 0, wx.EXPAND | wx.ALL, 8)

Explain Line by Line Code Description (Block 3)

  1. Line 3: the constructor
    The dialog receives already computed entries. It knows nothing about project files, the disk or the worker — which is why every UI state in this chapter can be tested without a project fixture.
  2. Line 4: copying the entries
    dict(entry) per item means the dialog cannot modify the caller’s list. Defensive copying at a boundary like this costs microseconds and prevents a class of bug that is painful to trace.
  3. Lines 6–9: the sidebar
    A horizontal sizer with a narrow left panel: the layout the requirements described. The first radio carries wx.RB_GROUP, which is what makes wxPython treat the two as one mutually exclusive group rather than two independent toggles.
  4. Lines 10–12: accessible names
    SetName(radio.GetLabel()) is the difference between NVDA announcing “Select an audio file, radio button, checked” and “radio button, checked”. Naming every control from its own label keeps the label and the accessible name from drifting apart.
  5. Line 13: SetSizerAndFit
    The panel sizes itself to its content, then the minimum width is raised to 240 px. Fixing a sidebar width avoids the layout reflowing when the combobox content below changes.
  6. Lines 15–17: the sensible default
    If nothing has been recorded yet, the file mode has an empty list and would show the user a dead combo, so “Select by file break” is pre-selected. This is the dialog doing the reasoning the user would otherwise have to do — and it is also why the workflow works on a brand-new project.
  7. Line 18: outer.Add(side_panel, 0, wx.EXPAND | wx.ALL, 8)
    Proportion 0: the sidebar keeps its width while the combo column takes the remaining space. Getting proportions right here is what keeps the dialog from looking stretched when a project has 700 segments.
    def _fill_combo(self):
        self.combo.Clear()
        if self.file_radio.GetValue():
            self.choice_label.SetLabel("Choose which recorded file to record again:")
            update_accessible_name(self.combo, "Recorded audio files")
            self.combo.SetToolTip(
                "Audio files that are already recorded in this project")
            items = [(entry["file"], entry["position"])
                     for entry in self._entries if entry.get("file")]
        else:
            self.choice_label.SetLabel("Choose which file to record by file break:")
            update_accessible_name(self.combo, "Project file breaks")
            self.combo.SetToolTip(
                "Every file break of the project, recorded or not")
            items = [(entry["title"], entry["position"])
                     for entry in self._entries]
        for label, position in items:
            self.combo.Append(str(label), position)
        if self.combo.GetCount():
            self.combo.SetSelection(0)
        self.combo.Enable(self.combo.GetCount() > 0)
        ok_btn = self.FindWindowById(wx.ID_OK)
        if ok_btn is not None:
            ok_btn.Enable(self.combo.GetCount() > 0)
        self.Layout()

Explain Line by Line Code Description (Block 4)

  1. Line 2: self.combo.Clear()
    Refilling always starts by emptying. Forgetting this is the classic radio-button bug: the two lists concatenate and the combo shows recorded files followed by every break.
  2. Lines 3–9: the recorded-files branch
    Label, accessible name and tooltip are set together with the items, so the three can never describe different things. The list comprehension filters on entry.get("file") — the same truth the dialog used to pick its default mode.
  3. Lines 10–16: the file-break branch
    Every break, unconditionally. This is the branch that makes chapter 75 of a 100-chapter book recordable today: the list is the project’s plan, not its progress.
  4. Lines 17–18: labels and client data
    The displayed string is what the user asked to see; the appended position is what the worker needs. Keeping both in the combo means the dialog never has to look anything up again after the user chooses.
  5. Lines 19–22: selection and enablement
    Selecting the first item, then disabling the combo and the OK button when the list is empty. Disabling OK is the important half: a dialog that can be confirmed with no choice is a dialog that fails later with a confusing message.
  6. Line 23: self.Layout()
    A label that grows from “Choose which recorded file…” to “Choose which file to record by file break…” changes the required width. Laying out after the change is what stops the text being clipped — a small detail that is very visible to a user with a screen reader reading a truncated label.

80.5 Wiring It Together, and Deleting the Guard

def _restart_selected(self):
    recent = self._require_selected()
    if not recent:
        return
    try:
        data = project.load_project(recent["path"])
    except (OSError, ValueError, KeyError) as exc:
        wx.MessageBox(f"Could not open the project: {exc}",
                      "Start selected recording", style=wx.OK | wx.ICON_ERROR)
        return
    saved = project.recorded_files(recent["path"])
    # Deliberately no "has anything been recorded?" guard: a long book may be
    # recorded out of order (chapter 75 of 100 today, the rest later), so the
    # picker always opens.
    if not data.get("segments"):
        wx.MessageBox(
            "This project has no file breaks yet, so there is nothing to record.",
            "Start selected recording", style=wx.OK | wx.ICON_INFORMATION)
        return
    dlg = _StartRecordingDialog(self, _picker_entries(data, saved))
    try:
        if dlg.ShowModal() != wx.ID_OK:
            return
        start_index = dlg.start_index()
        only_selected = dlg.only_selected()
        chosen = dlg.chosen_file()
    finally:
        dlg.Destroy()
    if start_index is None:
        return
    if chosen:
        project.remove_recording(recent["path"], chosen)
    self._open_recording(recent["path"], start_index=start_index,
                         single_segment=only_selected)

Explain Line by Line Code Description (Block 5)

  1. Lines 2–3: the selection check
    This remains, because the command operates on a project: with nothing selected there is no context to ask about. It reports why instead of failing silently.
  2. Lines 4–9: loading the project
    A narrow tuple of exception types (OSError, ValueError, KeyError) rather than a bare except: a corrupt project is reported, while a genuine programming error (AttributeError, TypeError) still surfaces as a crash worth fixing.
  3. Line 10: the files on disk
    project.recorded_files() reads what is actually in the project folder, not just the metadata. This is why “Select an audio file” shows everything recorded, including files whose metadata was lost.
  4. Lines 11–16: the guard that was removed, and the one that stayed
    The comment records the product decision: the old “this project has no recorded files yet” message made out-of-order recording impossible and was deleted. What remains is a real precondition — a project whose document was never split has no segments to choose from, so there is genuinely nothing to do. Distinguishing “the user has not finished everything” from “the user cannot start” is the whole point.
  5. Lines 17–25: the modal call
    Three values are read out of the dialog before Destroy(), in a try/finally so a failed read still destroys the window. Reading widget state after destroying the window is a use-after-free waiting to happen, and wxPython reports it in unhelpful ways.
  6. Lines 26–31: delete, then record
    The chosen recording is removed first so the segment behaves exactly as if it had never been recorded: the worker sees a pending segment. The call then passes the two things the picker produced, and nothing else — the recording window remains the single place where engine and voice are chosen.
Why delete instead of overwrite? Because the project, the processed_text.json log and the DAISY builders all key off “is this segment recorded?”. Removing the file marks the segment pending in one step, so every downstream consumer agrees without any of them needing to know about this dialog.

Explain Line by Line Code Description (Block 6)

  1. Lines 1–4: the index
    None means the user did not choose: keep the historical behaviour and resume at the first pending segment. Otherwise use the choice, clamped to the segment count so a project edited between opening the dialog and pressing Start cannot produce an out-of-range index.
  2. Line 6: one line that encodes the scope
    start_index + 1 if self._single_segment else None — “just this one” becomes an exclusive end one past the start; “from here” becomes None, meaning to the end. The dialog’s radio buttons therefore need no further glue: they map onto the worker’s contract directly.
  3. Lines 8–12: construction
    Both values travel as constructor arguments. Because the worker validates and clamps them (80.2), the dialog can hand over what the user chose without a defensive re-check — validation lives with the code that owns the range.
Single-segment recording has one consequence worth knowing: when the run stops after its one segment, nothing is queued behind it, so “Stop” simply means “this take is done”. Users who expect the old continue-to-the-end behaviour must pick Record all files from here.

80.7 Mini Project: Drive the Range Without a GUI

The worker range is pure logic, so it can be exercised in five lines:

from ai_voice_studio.jobs.synthesizer import SynthesisWorker

def positions(start, end, total):
    worker = SynthesisWorker.__new__(SynthesisWorker)   # no thread, no wx
    worker.start_index = start
    worker.end_index = end
    return list(worker._segment_positions(total))

print(positions(0, None, 5))    # everything
print(positions(3, 4, 5))       # only segment 4
print(positions(3, None, 5))    # segment 4 to the end
print(positions(4, 3, 5))       # empty: end before start
print(positions(2, 99, 5))      # clamped to the project's end

  2. Add a third sidebar mode, “Select by page range”, to a scratch copy. What must change in _picker_entries, the dialog and the worker?
  3. Write a test that builds a 4-segment project with no recordings and asserts the dialog opens in file-break mode and that wx.MessageBox is never called. (This is the regression test for the guard that was removed.)
  4. Explain why the dialog reads its three values before Destroy(), and what symptom you would expect if it did not.

80.8 Key Takeaways

  • Give the worker an explicit range (start + exclusive end) instead of a “resume” flag; the dialog then becomes a thin front end
  • Keep list-building in a pure function so every UI state is testable without a project fixture
  • One radio group can legitimately change another control’s contents — set the label, accessible name and items together
  • Choose the default that keeps a brand-new project usable, and disable OK when a list is genuinely empty
  • Delete guards that encode a workflow assumption the user did not ask for; keep the ones that reflect a real precondition
  • Mark a segment pending by removing its file, so every downstream consumer agrees in one step
