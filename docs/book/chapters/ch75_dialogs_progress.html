Chapter 75

Reusable Dialogs & Progress

Learning Objectives

  • Build labelled-button dialogs that screen readers announce properly (vs. wx.MessageBox)
  • Route engine errors through pattern matching to offer a server restart
  • Write one progress dialog that serves both background threads and synchronous work
  • Understand pulse animation with wx.Timer and forced repaints with wx.Window.Update

75.1 Why Not wx.MessageBox?

The stock message box only offers standard buttons ("OK", "Yes", "No"). Two places in AIVS need two meaningful buttons instead:

  • recording finished → Open project folder / OK
  • an OmniVoice Server failure → Restart OmniVoice server now / I will restart later

The module gui/dialogs.py provides one small dialog class plus helpers, so both flows stay consistent — and every button is a real wx.Button with a real accessible name, which NVDA and JAWS announce reliably (unlike owner-drawn or generic message-box buttons).

75.2 The Action Dialog

def run_action_dialog(
    parent: wx.Window,
    title: str,
    message: str,
    actions: list[tuple[str, str]],
    default_key: str | None = None,
) -> str | None:
    dlg = _ActionDialog(parent, title, message, actions, default_key)
    try:
        if dlg.ShowModal() == wx.ID_OK:
            return dlg.selected_key
        return None
    finally:
        dlg.Destroy()

Explain Line by Line Code Description (Block 1)

  1. Lines 1–6: the signature
    The public helper wraps the private dialog class. actions is a list of (key, label) pairs — key is what the caller receives, label is what the user sees and the screen reader announces. default_key names the button that receives initial focus (Enter activates it), so the safe choice is always the Enter choice. The return value is the chosen key, or None when the dialog was dismissed with Escape or the close box.
  2. Line 7: dlg = _ActionDialog(parent, title, message, actions, default_key)
    Creates (but does not yet show) the modal dialog. Construction builds all controls and sizers; showing happens in ShowModal().
  3. Lines 8–11: try: ... finally: dlg.Destroy()
    Shows the dialog modally and translates the result: wx.ID_OK means a button was pressed and the chosen key is returned; anything else (Escape, close box) maps to None. The finally block is essential wx hygiene — Destroy() releases the native window resources on every path, including exceptions, preventing window-handle leaks.
class _ActionDialog(wx.Dialog):
    def __init__(self, parent, title, message, actions, default_key=None):
        super().__init__(parent, title=title)
        self.selected_key: str | None = None
        self._keys: dict[int, str] = {}

        sizer = wx.BoxSizer(wx.VERTICAL)
        text = wx.StaticText(self, label=message)
        text.SetName(title)
        text.Wrap(520)
        sizer.Add(text, 0, wx.EXPAND | wx.ALL, 12)

        btn_row = wx.BoxSizer(wx.HORIZONTAL)
        btn_row.AddStretchSpacer(1)
        default_btn = None
        for key, label in actions:
            btn = wx.Button(self, label=label)
            btn.SetName(label)
            btn.SetToolTip(label)
            self._keys[btn.GetId()] = key
            if default_key is not None and key == default_key:
                default_btn = btn
            btn_row.Add(btn, 0, wx.ALL, 6)
            btn.Bind(wx.EVT_BUTTON, self._on_action)
        sizer.Add(btn_row, 0, wx.EXPAND | wx.LEFT | wx.RIGHT | wx.BOTTOM, 6)

        self.SetSizer(sizer)
        self.Fit()
        self.SetMinSize(self.GetSize())
        if parent is not None and parent.IsShown():
            self.CentreOnParent()
        else:
            self.Centre()
        target = default_btn or (btn_row.GetChildren()[0].GetWindow()
                                 if btn_row.GetChildren() else None)
        if target is not None:
            wx.CallAfter(target.SetFocus)

Explain Line by Line Code Description (Block 2)

  1. Lines 1–4: class header and initial state
    The dialog keeps two pieces of state: selected_key (which button the user chose; None until one is pressed) and _keys, a dictionary mapping wx control ids to the caller's action keys. When a button event arrives, the id is looked up in this dictionary — this is how one event handler serves any number of buttons.
  2. Lines 6–10: the message text
    A vertical sizer holds a StaticText with the message. text.SetName(title) gives the label a real MSAA accessible name, and text.Wrap(520) breaks long messages at word boundaries around 520 pixels so the dialog never grows wider than the screen. sizer.Add(text, 0, wx.EXPAND | wx.ALL, 12) adds it with a 12-pixel border on all sides.
  3. Lines 12–21: the button row
    A horizontal sizer holds the action buttons, right-aligned after a stretch spacer. For every (key, label) pair a real wx.Button is created; SetName(label) makes its accessible name equal to its visible label (screen readers announce exactly the label), and self._keys[btn.GetId()] = key registers the mapping the event handler needs. When the pair matches default_key, that button is remembered as the default focus target.
  4. Lines 23–28: layout and centering
    Fit() sizes the dialog to its contents and SetMinSize(self.GetSize()) stops the user shrinking it below that. Centering prefers the parent window (CentreOnParent) so the dialog appears near where the user is looking, falling back to screen center when the parent is hidden.
  5. Lines 29–31: target = default_btn or ... / wx.CallAfter(target.SetFocus)
    Chooses the button to focus: the default action if one was named, otherwise the first button. wx.CallAfter defers the focus call until after the dialog finishes its modal show cycle — setting focus during __init__ would be overwritten by wx's own focus handling, so the call is queued for the next event-loop pass. Focus on the safe default means Enter triggers the conservative action ("I will restart later", "OK").

75.3 The "Open project folder" and Server-Restart Helpers

def show_recording_complete(parent, message, project_folder):
    key = run_action_dialog(
        parent, "Recording complete", message,
        [("open", "Open project folder"), ("ok", "OK")],
        default_key="ok",
    )
    if key == "open":
        open_folder(project_folder)


_SERVER_HINTS = (
    "omnivoice server",
    "server is not responding",
    "server exited prematurely",
    ...
)


def looks_like_server_error(message: str) -> bool:
    low = (message or "").lower()
    if any(hint in low for hint in _REQUEST_LEVEL_HINTS):
        return False
    return any(hint in low for hint in _SERVER_HINTS)

Explain Line by Line Code Description (Block 3)

  1. Lines 1–9: show_recording_complete(...)
    The recording-finished dialog. Two buttons are offered with "ok" as the default; when the user picks "open", open_folder(project_folder) launches the OS file manager (via os.startfile on Windows, a file:// URL as fallback). Any other outcome (OK, Escape) simply closes.
  2. Lines 11–17: _SERVER_HINTS = (...)
    A tuple of lowercase substrings that indicate the OmniVoice HTTP server itself failed (connection refused, exited prematurely, "try restarting it from settings", …). Pattern matching on error text is deliberately simple: the engine layer raises many exception types, but the user-facing decision only needs "is this a server problem or not".
  3. Lines 19–23: def looks_like_server_error(message): ...
    The classifier. First the message is lowercased so matching is case-insensitive. Then the subtle part: _REQUEST_LEVEL_HINTS (messages like "server returned HTTP 500: …") are checked first and veto the classification — if the server answered with its own HTTP error, it is demonstrably alive and offering a restart would only confuse. Only when no veto matched do the _SERVER_HINTS decide. This two-tier check is why the restart dialog appears for dead-server errors but not for synthesis failures the server already reported.

75.4 One Progress Dialog, Two Usage Patterns

gui/progress.py serves two callers with opposite needs:

  • Background threads (recording, server restart): the worker pushes updates through wx.CallAfter; the normal event loop repaints.
  • Synchronous work (document parsing in the wizard): the UI thread is busy inside a long call, so the dialog must repaint itself with wx.Window.Update().
class TaskProgressDialog(wx.Dialog):
    def __init__(self, parent, title="Working", message="Working...",
                 cancel_label=None, on_cancel=None, style=None):
        if style is None:
            style = wx.CAPTION | wx.RESIZE_BORDER
        super().__init__(parent, title=title, style=style)
        self._on_cancel = on_cancel

        sizer = wx.BoxSizer(wx.VERTICAL)
        self._message = wx.StaticText(self, label=message)
        self._message.SetName("Progress message")
        self._message.Wrap(430)
        sizer.Add(self._message, 0, wx.ALL, 10)

        self.gauge = wx.Gauge(self, range=100, size=(420, 22))
        self.gauge.SetName("Progress")
        self.gauge.SetToolTip("Shows how much of the work has finished")
        sizer.Add(self.gauge, 0, wx.EXPAND | wx.LEFT | wx.RIGHT | wx.BOTTOM, 10)

Explain Line by Line Code Description (Block 4)

  1. Lines 1–5: the signature and style fallback
    The constructor accepts the dialog texts, an optional cancel button (label + callback) and an optional style. When no style is given it uses wx.CAPTION | wx.RESIZE_BORDER — deliberately without wx.CLOSE_BOX: the dialog's lifetime is controlled by the calling code (via finish()), not by the user clicking a close box mid-operation.
  2. Lines 6–10: the message label
    A StaticText with a fixed accessible name ("Progress message") that later gains the current text (see set_message below), and Wrap(430) so long status lines break cleanly. Screen readers announce the label whenever it changes because the name changes with it.
  3. Lines 12–15: the gauge
    A wx.Gauge with range 100 — values are always expressed as percentages. It gets its own accessible name and a tooltip. range=100 also matches the pulse animation below, which walks the gauge between 0 and 95.
    def start_pulse(self, interval_ms: int = 150) -> None:
        self._pulse_value = 0
        self._pulse_timer = wx.Timer(self)
        self.Bind(wx.EVT_TIMER, self._on_pulse_tick, self._pulse_timer)
        self._pulse_timer.Start(interval_ms)

    def _on_pulse_tick(self, _):
        self._pulse_value = (self._pulse_value + 4) % 96
        self.show_progress(self._pulse_value)

    def show_progress(self, value: int) -> None:
        self.gauge.SetValue(max(0, min(100, int(value))))
        self.gauge.Update()

    def finish(self) -> None:
        self.stop_pulse()
        try:
            self.Destroy()
        except Exception:
            pass

Explain Line by Line Code Description (Block 5)

  1. Lines 1–5: start_pulse(interval_ms=150)
    Starts indeterminate ("busy") animation for work whose length is unknown — a server restart, a recording that depends on document size. A wx.Timer owned by the dialog fires every 150 ms on the UI thread (timers are the only safe way for GUI state to change periodically without a second thread touching widgets).
  2. Lines 7–8: _on_pulse_tick
    Each tick advances the stored pulse value by 4 and wraps with modulo 96, so the gauge sweeps 0→95→0 forever without ever reaching 100 (which would falsely signal completion). It then routes through show_progress, gaining the forced repaint for free.
  3. Lines 10–12: show_progress(value)
    Sets the gauge, clamped into 0–100 by max(0, min(100, ...)) so a misbehaving worker cannot crash the dialog. The crucial detail is self.gauge.Update() — unlike Refresh, Update() repaints immediately, synchronously. This is what makes the bar move even while the UI thread is blocked inside a long parsing call and no event-loop paint pass will ever run.
  4. Lines 14–18: finish()
    The single, safe way to close the dialog: stop the pulse timer (a timer firing after destroy would raise), then Destroy() wrapped in a guard because two callers (worker thread via CallAfter and the UI handler) may both call finish — the second call must be a harmless no-op.

75.6 Key Takeaways

  • Real wx.Buttons with SetName(label) are what screen readers announce — prefer them over wx.MessageBox when buttons carry meaning
  • Map control ids → action keys in a dict so one handler serves any number of buttons
  • Classify errors in two tiers: request-level messages veto, then server hints decide
  • wx.Window.Update() repaints synchronously — the only way a progress bar can move while the UI thread is busy
  • Guard Destroy(); timers must stop before the window dies; wx.CallAfter sequences focus and cross-thread updates
