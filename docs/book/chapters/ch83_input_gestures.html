Chapter 83

Configurable Input Gestures: Learning from NVDA's Input Gestures Dialog

Learning Objectives

  • Separate a command (what the user means) from a gesture (the key they press)
  • Normalize a key combination into a stable identifier so bindings can be compared
  • Layer defaults, locale and user overrides the way NVDA's GlobalGestureMap does
  • Report a key two commands both want instead of resolving it silently
  • Capture a key press into a gesture and refuse combinations that would shadow typing
  • Keep the model GUI-free so it can be unit tested without a window

83.1 The Problem with Hard-Coded Keys

Every keyboard shortcut written as a literal in an event handler is a promise the application cannot keep. A screen reader user may already use Ctrl+Shift+R for something else in their own workflow; a laptop keyboard may have no Insert key; a blind user's muscle memory from another program points at a different key entirely. NVDA solved this years ago with its Input Gestures dialog, and this chapter builds the same facility for AI Voice Studio.

The central idea is a separation of concerns:

  • A command is what the user means — “Create a new project”. It has an id, a category and a human-readable label.
  • A gesture is how they ask for it — a normalized key combination such as kb:control+shift+n.

A command ships with default gestures; the user may replace those defaults, and the replacement is what actually runs. Nothing in the event handlers mentions a key at all.

83.2 Normalizing a Gesture

A gesture identifier is a string: a source prefix (kb for keyboard, exactly NVDA's spelling), then a +-separated list of modifiers and one key. Normalization makes two spellings of the same key press compare equal:

def normalize(identifier: str) -> str:
    """Normalize a gesture to its canonical ``kb:<mods+key>`` form."""
    text = str(identifier or "").strip()
    if ":" in text:
        source, _, body = text.partition(":")
        source = source.strip().lower()
    else:
        source, body = SOURCE, text
    parts = [chunk.strip().lower() for chunk in body.split("+") if chunk.strip()]
    if not parts:
        return ""
    parts = [_ALIASES.get(part, part) for part in parts]
    modifiers = [p for p in MODIFIER_ORDER if p in parts]
    keys = [p for p in parts if p not in MODIFIER_ORDER]
    if len(keys) != 1:
        return ""            # a gesture ends in exactly one non-modifier key
    return f"{SOURCE}:{'+'.join(modifiers + keys)}"

Three details matter. Modifiers are emitted in a fixed order (control, alt, shift, windows), so shift+control+n and control+shift+n are one gesture. Everything is lower-cased. And a small alias table accepts the spellings people actually type — ctrl, win, esc, pgdn — so a hand-edited settings file is not silently ignored.

83.3 The Command Catalog

Commands are declared once, as data:

@dataclass(frozen=True)
class Command:
    id: str
    category: str
    label: str
    defaults: Tuple[str, ...] = field(default_factory=tuple)

COMMANDS: Tuple[Command, ...] = (
    Command("project.new", "Projects", "Create a new project",
            ("kb:control+shift+n",)),
    Command("project.open", "Projects", "Open a project...",
            ("kb:control+o",)),
    Command("project.resume", "Projects", "Resume the selected project"),
    # ... Recording, Help and Application commands
)

The categories (Projects, Recording, Help, Application) are what the dialog shows as the branches of its tree. categories_present() returns only the categories that actually hold a command, so a renamed category cannot leave an empty branch behind.

83.4 Layering Defaults and User Overrides

GestureMap keeps the user's map — {command id: [gesture, ...]} — and answers for every command:

def bindings_for(self, command_id: str) -> List[str]:
    """The gestures that trigger ``command_id`` (user map first)."""
    if command_id in self._user:
        return list(self._user[command_id])
    return self.defaults_for(command_id)

An entry in the user map replaces the defaults entirely, which is what makes an empty list mean “unbound” rather than “fall back”. That is deliberate: a user who removes the last key from a command means it, and the command must stop answering.

Why not merge the lists? NVDA's global map appends to the defaults, which is right when a locale adds a binding but wrong for a user who wants a key gone. A replacement model makes “unbind” expressible without a special case.

83.5 Conflicts Are Data, Not Errors

Two commands can end up asking for the same key: the user assigns Ctrl+Shift+N to Open a project without noticing the New project command already has it. The model does not guess. It reports:

def conflicts(self) -> Dict[str, List[str]]:
    """``{gesture: [command ids]}`` for every key claimed more than once."""
    owners: Dict[str, List[str]] = {}
    for entry in COMMANDS:
        for gesture in self.bindings_for(entry.id):
            owners.setdefault(gesture, [])
            if entry.id not in owners[gesture]:
                owners[gesture].append(entry.id)
    return {gesture: ids for gesture, ids in owners.items() if len(ids) > 1}

The dialog shows the conflict in its status line, and the dispatcher resolves it deterministically (the first declared command wins) so a key press never does two things at once. A test pins the shipped defaults to no conflicts, so a new command cannot quietly introduce one.

83.6 Capturing a Key Press

The capture dialog listens on its own char hook and turns the event into a gesture. Two rules keep the result sane:

def gesture_from_event(evt: wx.KeyEvent) -> str:
    code = evt.GetKeyCode()
    if code in _GESTURE_MODIFIER_CODES:
        return ""                       # a modifier alone is not a gesture
    key = gesture_key_name(code)
    if not key:
        return ""
    modifiers = []
    if evt.ControlDown():
        modifiers.append("control")
    if evt.AltDown():
        modifiers.append("alt")
    if evt.ShiftDown():
        modifiers.append("shift")
    if getattr(evt, "MetaDown", lambda: False)():
        modifiers.append("windows")
    return gestures_model.normalize("+".join(modifiers + [key]))

Then gesture_problem() refuses a combination that would shadow ordinary typing: a gesture needs Ctrl, Alt or Windows, unless it is a named key such as a function key. A bare J is rejected with a sentence saying why, instead of silently stealing a letter.

83.7 Dispatching in the Main Window

The frame offers every key press to the configured gestures before its built-in shortcuts:

def _dispatch_gesture(self, evt: wx.KeyEvent) -> bool:
    """Run the command a configured gesture names; True when one matched."""
    gesture = gesture_from_event(evt)
    if not gesture:
        return False
    command_id = self._gestures.owner(gesture)
    if not command_id:
        return False
    name = self._gesture_actions.get(command_id)
    handler = getattr(self, name, None) if name else None
    if handler is None:
        return False
    log.info("Input gesture %s -> %s", gesture, command_id)
    handler()
    return True

The handler table maps a command id to the name of a method rather than a bound method, so a later override of that method is what actually runs — which is what makes the dispatcher testable and keeps one code path for a mouse click and a gesture.

When the Settings window closes, the frame reloads the bindings, so a rebinding takes effect immediately without a restart.

83.8 The Settings Panel

Settings → Keyboard gestures follows NVDA's dialog layout: a tree of categories and commands, the selected command's gestures in a list below it, and three buttons — Add gesture…, Remove gesture and Restore defaults. A filter box narrows the tree, which matters when the command list grows.

Adding a gesture that another command already owns asks first:

owner = self.gesture_map.owner(gesture)
if owner and owner != command_id:
    other = gestures_model.command(owner)
    answer = wx.MessageBox(
        f"{gestures_model.display_name(gesture)} is already assigned "
        f"to \"{other.label}\".\n\n"
        "Take it away from that command and give it to this one?",
        "Input gesture already in use",
        style=wx.YES_NO | wx.ICON_QUESTION,
    )
    if answer != wx.YES:
        return
    self.gesture_map.add(command_id, gesture, replace_owner=True)

The bindings are saved with the rest of the settings in apply_to_settings() under gestures.bindings, so they travel with the user's configuration and are reset with it.

83.9 Keeping the Model Testable

ai_voice_studio/gestures.py imports nothing from wx. The whole model — normalization, the user map, conflicts, add/remove/reset — is exercised by tests/test_gestures_model.py without a window, and the GUI layer (capture, panel, dispatcher) by the smoke tests. That split is what lets the interesting rules be tested in milliseconds.
