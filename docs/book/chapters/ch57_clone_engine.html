Chapter 57

Voice Cloning: from XTTS v2 to the Voice Lab

Superseded (2026.3.1). XTTS v2 is no longer part of the application. Voice cloning is now provided by the Voice Lab: three pip-installed engines — Pocket TTS (Kyutai), Bark (Suno) and F5-TTS — each in its own Python environment, driven by a subprocess worker. This chapter still teaches the ideas that survived the change (a dedicated client, a JSON-lines protocol, one loaded model reused across segments), so read it for the architecture and then continue with:
  • Chapter 76 — the Voice Lab engine subsystem
  • Chapter 77 — one environment per engine
  • Chapter 78 — CPU and GPU compute
A fourth engine (NeuTTS) was removed because it required a Hugging Face login; no part of this application depends on an account.

Learning Objectives

  • Understand the voice cloning pipeline
  • See the CloneClient subprocess architecture
  • Understand the JSON-lines IPC protocol

57.2 CloneClient IPC Protocol

# JSON lines protocol over stdin/stdout
# App → Worker:
{"cmd": "ping"}                           # Check engine availability
{"cmd": "synthesize", "text": "Hello",
 "sample_wav": "/path/to/sample.wav",
 "language": "en", "speed": 1.0}     # Synthesize with cloned voice
{"cmd": "quit"}                          # Shutdown

# Worker → App:
{"ok": true, "engine": true}              # Ping response
{"ok": true, "wav": "<base64>"}          # Audio response
{"ok": false, "error": "..."}            # Error response

57.4 Key Takeaways

  • XTTS v2 is a zero-shot voice cloning model (4-5 second sample)
  • Runs in a separate subprocess to isolate PyTorch from sherpa-onnx
  • JSON lines protocol over stdin/stdout for IPC
  • Supports 17 languages with multi-lingual cloning
  • The cloning engine is optional — downloaded on-demand from Settings
