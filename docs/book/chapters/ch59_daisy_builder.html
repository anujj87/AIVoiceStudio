DAISY Book Builder

Current implementation (2026.3.1). The DAISY 2.02 builder described here is joined by documents/daisy3_builder.py (Z39.86-2005 audio + text with images and paragraph-level synchronisation, Chapter 74) and by documents/playlist_builder.py (m3u8/pls/wpl for ordinary recorded projects, Chapter 73). Book metadata defaults come from the DAISY settings category, and the Recording window offers Export DAISY as ZIP once a DAISY project is complete.

Learning Objectives

  • Understand the DAISY 2.02 standard
  • See how AIVS generates NCC, OPF, and SMIL files
  • Understand the DAISY ZIP export

59.1 What Is DAISY?

DAISY (Digital Accessible Information System) is a standard for accessible digital books. DAISY 2.02 books include synchronized audio and text, making them usable by blind and visually impaired readers with DAISY-capable players.

DAISY 2.02 File Structure

project/
├── ncc.html           # Navigation Center Combined (master TOC)
├── package.opf        # OPF content manifest
├── audio/
│   ├── Chapter_1.wav  # Audio files
│   └── Chapter_2.wav
├── smil/
│   ├── Chapter_1.smil # Audio-text sync files
│   └── Chapter_2.smil
└── Chapter_1.txt      # Text files (for audio+text mode)

59.3 Export as ZIP

def export_daisy_zip(project_dir, zip_path):
    """Package the DAISY book into a distributable ZIP."""
    with zipfile.ZipFile(zip_path, "w", zipfile.ZIP_DEFLATED) as zf:
        # Add NCC and OPF
        zf.write(os.path.join(project_dir, "ncc.html"), "ncc.html")
        zf.write(os.path.join(project_dir, "package.opf"), "package.opf")
        # Add audio and SMIL directories recursively
        for dirname in ["audio", "smil"]:
            dirpath = os.path.join(project_dir, dirname)
            for root, _, files in os.walk(dirpath):
                for file in files:
                    zf.write(os.path.join(root, file),
                             os.path.relpath(os.path.join(root, file), project_dir))

59.4 What Changed Since the First Edition

The DAISY 2.02 builder received three significant upgrades. The most important one fixes the classic "audio cuts out" complaint.

1. MP3 normalization on staging

Two new functions in audio/ffmpeg.py give the builder control over problem MP3s. DAISY players reliably decode MPEG-1 Layer III; the TTS engines, however, emit MPEG-2 LSF MP3s at their native sample rate (22–24 kHz), which several players truncate or refuse while VLC plays the same file fine.

def needs_mp3_normalization(path: str) -> bool:
    exe = find_ffmpeg()
    if not exe:
        return False
    try:
        result = subprocess.run(
            [exe, "-i", path],
            capture_output=True,
            text=True,
            timeout=30,
            creationflags=getattr(subprocess, "CREATE_NO_WINDOW", 0),
        )
        import re
        stream = re.search(
            r"Stream #\d+:\d+.*?: Audio: mp3.*?, (\d+) Hz", result.stderr or "")
        if not stream:
            return False
        return int(stream.group(1)) < 44100
    except Exception:
        return False

Explain Line by Line Code Description (Block 6)

  1. Line 1: def needs_mp3_normalization(path):
    Answers one question: is this MP3 file one that DAISY players will mishandle? The probe costs one FFmpeg invocation, so it is cheap enough to run per segment.
  2. Lines 2–3: exe = find_ffmpeg() / if not exe: return False
    Locates FFmpeg (bundled folder or PATH). When it is not installed the probe returns False — meaning "assume the file is fine" — because without FFmpeg there is also no way to re-encode, and skipping is the only graceful choice.
  3. Lines 4–11: the subprocess.run probe
    Runs ffmpeg -i path without an output file, which makes FFmpeg print stream information to stderr and exit. capture_output=True, text=True collects that text; timeout=30 bounds a hung probe; creationflags=CREATE_NO_WINDOW (guarded with getattr so non-Windows platforms stay compatible) stops a console window from flashing on screen.
  4. Lines 12–14: the regex
    Searches FFmpeg's stream report for a line like Stream #0:0: Audio: mp3, 24000 Hz, .... The pattern anchors on Audio: mp3 and captures the sample-rate digits before Hz. When nothing matches (corrupt file, unexpected layout) the probe again answers False.
  5. Line 15: return int(stream.group(1)) < 44100
    The decision rule: anything below 44.1 kHz is MPEG-2 LSF territory and gets normalized. 44.1 kHz and above pass untouched.
  6. Lines 16–17: the blanket except
    Any failure (missing exe mid-run, timeout, decode error) degrades to False. A broken probe must never abort a book build — worst case the user gets an unnormalized MP3, which is exactly the pre-fix behaviour.

The companion normalize_mp3_for_daisy(src, dst) re-encodes such a file to MPEG-1 Layer III, 44.1 kHz, mono via libmp3lame -q:a 2, writing to a temp file and os.replace-ing it into place so a failed transcode never destroys the original. The DAISY 2.02 and DAISY 3 builders both call this pair while staging recorded audio into the book.

2. Book information from the wizard

The New Project wizard's DAISY page now collects title, creator, narrator, publisher, subject and date. These flow through the recording dialog into build_daisy_book(..., meta=...); empty fields fall back to the global defaults in Settings or to sensible built-ins, and the running time is always measured from the actual audio — never trusted from metadata.

3. Cleaned metadata

Generator strings and build metadata were cleaned up so players show the book's own title rather than tooling artefacts, and the master SMIL/NCC cross-references were made strictly sibling-relative (same portability rule as the playlist builder in Chapter 73).

59.5 Key Takeaways

  • DAISY 2.02 is an accessible book format with audio-text synchronization
  • Three key files: ncc.html (TOC), package.opf (manifest), SMIL (sync)
  • AIVS supports both audio-only and audio+text DAISY modes (the legacy type stays loadable; new projects pick DAISY 3 for text+images — Chapter 74)
  • The builder is called automatically after recording completes
  • ZIP export packages everything into a single distributable file
  • Low-rate MP3s are re-encoded to 44.1 kHz MPEG-1 during staging so every DAISY player decodes the full audio
