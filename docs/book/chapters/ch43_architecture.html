43.2 Data Flow

User opens document (PDF/DOCX/TXT)
    │
    ▼
Document Parser (parsers.py)
    │ Extract text blocks with headings
    ▼
Document Splitter (splitter.py)
    │ Split into segments by page/heading
    ▼
Project Creator (project.py)
    │ Save segments to project.json
    ▼
Recording Dialog (recording_dialog.py)
    │ User selects voice, rate, pitch
    ▼
Synthesis Worker (synthesizer.py) — Background Thread
    │ For each segment:
    │   1. Get TTS engine (engine.py)
    │   2. Synthesize text → numpy array
    │   3. Apply pitch/volume adjustments
    │   4. Save to WAV (or convert to MP3/FLAC)
    │   5. Mark segment done in project.json
    ▼
DAISY Builder (daisy_builder.py) — If DAISY project
    │ Generate ncc.html, package.opf, SMIL files
    ▼
Audio files in project directory

43.4 Key Takeaways

  • AIVS has 53 Python source files across 13 subpackages
  • The architecture follows layered design: GUI → Business Logic → TTS Engine → Infrastructure
  • Heavy TTS engines run in separate subprocesses (Clone, OmniVoice)
  • The data flow is: Document → Parser → Splitter → Project → Recording → Audio
  • JSON is the universal data format (settings, projects, catalog, worker protocol)
