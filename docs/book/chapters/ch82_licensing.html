Chapter 82

Licensing & Compliance for a Multi-Engine Audio Application

Learning Objectives

  • Separate the licence of an application, of its libraries, of model code and of model weights
  • Record licence names as data, next to the thing they apply to
  • Ship the licence texts where users and auditors will actually find them
  • Build a commercial-use matrix a non-lawyer can act on
  • Audit your own dependency set before a release, not after a complaint

82.1 Four Layers of Licensing in One Application

A TTS studio is not “licensed” in the singular. Four layers stack, and each can carry different terms:

LayerExample in this projectTypical licence
ApplicationAI Voice Studio itselfGPL-3.0
Python librarieswxPython, NumPy, sherpa-onnx, ONNX Runtime, requests, pypdf, python-docxMIT / BSD-3 / Apache-2.0 / wxWindows
Model codef5-tts, pocket-tts, transformers, Bark’s repoMIT / Apache-2.0
Model weights & voicesF5-TTS checkpoints, MMS, AISHELL3 data, Pocket TTS voicesCC-BY-NC-4.0, per-voice terms, dataset licences

The fourth layer is where the surprises live. F5-TTS is the canonical example in this project: the code is MIT, but the released weights are CC-BY-NC-4.0, which forbids commercial use. Anyone who reads only the repository’s main licence file and ships a product will be wrong.

Nothing in this chapter is legal advice, and none of it replaces reading a licence before shipping. The engineering point is narrower and fully actionable: record which licence applies to which component, and put that information in front of the user. Guessing is how projects end up unable to answer the simplest question a distributor asks.

82.2 Licences as Data, Next to the Component

The engine registry carries a license field per engine, and the JSON model catalog carries one per TTS family. This is the single most useful decision in the whole chapter: the licence lives with the component it describes, so it cannot silently become stale in a separate document.

{
    "id": "f5tts",
    "name": "F5-TTS (transformer)",
    "package": "f5-tts",
    "packages": ("f5-tts", "torch", "torchaudio", "soundfile"),
    "license": "MIT (code); CC-BY-NC-4.0 (weights)",
    "homepage": "https://github.com/SWivid/F5-TTS",
}

Explain Line by Line Code Description (Block 1)

  1. Line 5: the two-part licence string
    “MIT (code); CC-BY-NC-4.0 (weights)” names both layers and marks which is which. A single word here would be either misleading or useless: MIT alone hides the non-commercial weights, and CC-BY-NC-4.0 alone would deny the permissive code.
  2. Line 6: homepage
    The URL makes every claim checkable in one click, for a user and for an auditor. A licence statement without a source is a rumour.
  3. Why in the registry, not in a document?
    Because the registry is what the install dialog reads. When the user presses “Install engine…”, the sentence they see comes from this field — the disclosure happens at the moment of choice rather than in a file nobody opened.

The same pattern in the model catalog, for the sherpa-onnx families:

{"id": "piper",       "license": "MIT"}
{"id": "kokoro",      "license": "Apache-2.0"}
{"id": "kitten",      "license": "Apache-2.0"}
{"id": "vits_zh",     "license": "Apache-2.0"}
{"id": "matcha",      "license": "CC-BY-4.0 (icefall conversion); LJSpeech/other datasets may have their own terms"}
{"id": "omnivoice",       "license": "Apache-2.0"}
{"id": "omnivoice_server", "license": "Apache-2.0 / MIT"}
{"id": "sapi5",       "license": "Windows (built in)"}
{"id": "windows_core", "license": "Windows (built in)"}

Explain Line by Line Code Description (Block 2)

  1. Lines 1–4: the permissive families
    Short, unambiguous strings. Uniform values are still recorded per entry, because the moment one of them changes (a new checkpoint under a different licence) the data is already the right shape.
  2. Line 5: Matcha-TTS
    The longest string, and the most honest: the conversion is CC-BY-4.0 while the training data behind the checkpoints may impose its own conditions. Saying “may have their own terms” is not vagueness — it is the accurate statement, and it warns an integrator to check.
  3. Lines 6–7: the OmniVoice pair
    Two front-ends over one project, with slightly different terms — which is exactly why the licence is per entry and not per “voice engine”.
  4. Lines 8–9: Windows voices
    “Windows (built in)” is the truthful answer for SAPI5 and Windows Core voices: they are licensed by the operating system or the voice vendor, not by this application. This is the case the first-launch terms call out explicitly — the user must own the right to use those voices.

82.3 Where the Licences Have to Appear

Recording the data is half the job; the other half is putting it where people are. The project ships it in four places, each with a different audience:

ArtifactContentsAudience
LICENSEthe application’s GPL-3.0 text plus a third-party summaryanyone reading the repository
docs/THIRD-PARTY-LICENSES.htmlsummary table of every bundled component, full texts for Apache-2.0 / MIT / BSD-3, links and accurate summaries for the restusers and auditors, opened from the Help menu
Installer licence pageLICENSE, shown before installation proceedseveryone who installs the application
Install dialog per enginethe registry’s license string for the engine being installedthe user at the moment they choose an engine
 
[Setup]
LicenseFile=..\LICENSE

[Files]
Source: "..\docs\THIRD-PARTY-LICENSES.html"; DestDir: "{app}\docs"; Flags: ignoreversion

Explain Line by Line Code Description (Block 3)

  1. Lines 1–2: LicenseFile
    Inno Setup renders the given file on a page the user must accept to continue. Pointing it at the repository’s LICENSE means there is one file to maintain, and the installer cannot drift from it.
  2. Lines 4–5: the HTML page
    Copied into the application folder so the Help menu can open it offline, long after installation. A licence page that only exists on the internet is unavailable in the one place it is most needed — a machine with no network.
  3. Why HTML rather than a text file?
    The page contains tables, links and several full-licence sections. HTML keeps it navigable by keyboard and readable by a screen reader, matching the rest of this application’s documentation.

82.4 Building an Auditable Inventory

Because the metadata is data, an inventory is a loop — not a manual table that goes stale the day someone adds an engine:

import json

from ai_voice_studio.voicelab import engines

print("== Voice Lab clone engines ==")
for info in engines.ENGINES:
    print(f"{info['name']:<34} {info['license']}")
    print(f"{'':34} {info['homepage']}")

print()
print("== Catalog TTS families ==")
with open("ai_voice_studio/tts/models_catalog.json", encoding="utf-8") as handle:
    catalog = json.load(handle)
for entry in catalog["tts"]:
    print(f"{entry['name']:<34} {entry.get('license', '(not recorded)')}")

82.5 The Commercial-Use Matrix

The question users actually ask is not “what licence is Kokoro?” but “may I sell the audiobook I made?”. Converting a licence name into an answer requires knowing whether it touches the output or only the software:

Two entries deserve to be highlighted in any user-facing documentation: F5-TTS weights are non-commercial, and MMS / AISHELL3-family data is non-commercial. Both are fine for personal and educational use, which is why they remain in the catalog — with the terms stated where the engine or voice is chosen, the user can make an informed decision instead of discovering the limitation after publishing.

82.6 Obligations That Come With the Permissive Licences

“Permissive” does not mean “no obligations”. Three attach to almost everything in this dependency set:

  1. Attribution. MIT, BSD and Apache-2.0 all require the copyright notice and licence text to be preserved in distributions. That is the entire reason THIRD-PARTY-LICENSES.html exists and is installed alongside the app.
  2. NOTICE file (Apache-2.0). If a component ships a NOTICE file, its contents must be reproduced. Check the wheels you bundle.
  3. State changes (Apache-2.0). If you modify Apache-2.0 code, say so. This is why a build that patches a library needs a note.
  4. Copyleft. wxPython’s wxWindows Library Licence is LGPL-compatible; dynamic linking is the usual reason such a GUI toolkit can be bundled in a non-LGPL application. Its licence text belongs in the same document as the rest.
  5. Optional binaries. FFmpeg is downloaded on demand and is distributed under LGPL/GPL depending on the build; the page states that this is the user’s download, which keeps the question of redistribution with the user.

82.7 Mini Project: A Release Licence Check

Turn the inventory into a check that fails loudly when something is missing. A test is a better place than a checklist, because it runs every time:

import json
from pathlib import Path

from ai_voice_studio.voicelab import engines

ROOT = Path(__file__).resolve().parents[1]
PAGE = ROOT / "docs" / "THIRD-PARTY-LICENSES.html"


def test_every_engine_states_its_licence():
    for info in engines.ENGINES:
        assert info.get("license"), f"{info['id']} has no licence recorded"
        assert info.get("homepage"), f"{info['id']} has no source link"


def test_catalog_families_state_their_licence():
    catalog = json.loads(
        (ROOT / "ai_voice_studio" / "tts" / "models_catalog.json").read_text("utf-8")
    )
    for entry in catalog["tts"]:
        assert entry.get("license"), f"{entry['id']} has no licence recorded"


def test_licence_page_exists_for_the_help_menu():
    assert PAGE.is_file()
    text = PAGE.read_text("utf-8").lower()
    for needle in ("apache", "mit", "bsd", "cc-by-nc"):
        assert needle in text, f"{needle} is not covered in the licence page"

Explain Line by Line Code Description (Block 4)

  1. Lines 6–7: resolving the repository root
    Tests must not depend on the working directory: deriving paths from __file__ means the same check runs from an IDE, from pytest and from CI.
  2. Lines 10–13: the engine check
    Two assertions per engine: a licence and a source link. Recording one without the other is the half-finished state this test exists to prevent — an unexplained licence string is as hard to verify as a missing one.
  3. Lines 16–22: the catalog check
    Reads the JSON data file rather than importing the catalog module, so the test keeps working even when the import path changes — it asserts the data, which is what ships.
  4. Lines 25–29: the page check
    Asserts the file exists and mentions the four licence families that always apply. That single test would have caught the release where the page was missing entirely, or where the Apache text was dropped during an edit.

82.8 Key Takeaways

  • Track four layers — application, libraries, model code, model weights — because they can differ
  • Store the licence next to the component as data, so UI and documentation read one source
  • Disclose at the moment of choice (the install dialog) and permanently (the installed licence page)
  • Give users a commercial-use matrix, not a list of licence names
  • Permissive licences still require attribution and, for Apache-2.0, NOTICE preservation
  • Make the inventory executable: a test that fails on a missing licence beats a checklist
  • Flag non-commercial components (F5-TTS weights, AISHELL3/MMS data) in bold, where the user chooses them
