8.2 try / except / else / finally

try:
    # Code that might fail
    result = 10 / 0
except ZeroDivisionError:
    # Handle the specific error
    print("Cannot divide by zero")
else:
    # Runs only if NO exception occurred
    print(f"Result: {result}")
finally:
    # ALWAYS runs, whether or not an exception occurred
    print("Cleanup")

# Catching multiple exception types
try:
    load_voice_model(path)
except FileNotFoundError:
    print("Model not found — download it first")
except PermissionError:
    print("Permission denied")
except OSError as exc:
    print(f"OS error: {exc}")

# Catching multiple types in one handler
try:
    download_model(url)
except (ConnectionError, TimeoutError) as exc:
    print(f"Network error: {exc}")

# Catching everything (use sparingly!)
try:
    risky_operation()
except Exception:
    print("Something went wrong")
    # ⚠️ Don't catch BaseException — it kills Ctrl+C!

8.5 Exception Handling Patterns in AIVS

# Pattern 1: Graceful degradation with logging
try:
    result = load_model(path)
except FileNotFoundError:
    log.warning("Model not found at {path}")
    result = None
except Exception as exc:
    log.error("Failed to load model: {exc}", exc_info=True)
    result = None

# Pattern 2: Retry with fallback
def download_with_fallback(urls):
    """Try multiple URLs until one works."""
    for url in urls:
        try:
            return download(url)
        except DownloadError as exc:
            log.warning("Failed {url}: {exc}")
    raise DownloadError("All download sources failed")

# Pattern 3: Suppressing expected exceptions
import contextlib
with contextlib.suppress(FileNotFoundError):
    os.unlink(temp_file)  # Ignore if already deleted

# Pattern 4: Safe operations in GUI callbacks
def _on_download(self, _):
    try:
        self._start_download()
    except Exception as exc:
        # Never let exceptions crash the GUI!
        wx.MessageBox(
            f"Download failed: {exc}",
            "Error",
            style=wx.OK | wx.ICON_ERROR,
        )

# Pattern 5: noqa comments for intentional bare exceptions
try:
    some_risky_call()
except Exception:  # noqa: BLE001
    pass  # Intentionally ignore all errors

8.7 Exception Best Practices

Rules for Exception Handling:
  1. Be specific — catch FileNotFoundError, not Exception
  2. Don't swallow errors silently — at least log them
  3. Never use bare except: — always specify except Exception:
  4. Use custom exceptions to distinguish application errors from library errors
  5. In GUI code, always catch exceptions to prevent crashes
  6. In worker threads, catch and report exceptions via events

8.8 Key Takeaways

  • try/except/else/finally is the full error handling pattern
  • Catch specific exceptions — never use bare except:
  • Custom exceptions make application errors distinguishable from system errors
  • Always log exceptions with exc_info=True for debugging
  • In AIVS, exceptions are caught at GUI boundaries and worker threads
